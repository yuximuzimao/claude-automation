# 2026-10-28 确定性收获、仓库映射与库存资料阶段记录

## 阶段范围

本阶段从“AI 每一步看截图再决定”的半人工流程，推进到窗口 ROI、固定网格和阶段状态识别。重点完成收获状态机压缩、四格可摘识别、QQ 快速入口、仓库与 picker 顺序关系验证、实时库存重扫和新种子建档。稳定规则已迁入 `docs/gameplay-rules.md` / `docs/seed-catalog.md`；本文只保留阶段事实、错误与纠正。曾试行的每日三轮预排计划已退出现行方案，不再保留历史计划文件。

## 已完成

- 4×6 土地曾用等距网格公式标定，QQ / 微信均可生成 24 格坐标；现行坐标以 `data/ui-layout.json` 的用户确认点为准。
- 当时的 `ui_probe.py` 增加窗口尺寸保护，拒绝把整屏截图误当农场窗口。
- 四格“可摘”识别从全场宽泛模板改成更紧凑的星标模板；混合成熟画面回放：QQ 准确识别 3 个、微信 2 个，未成熟画面均为 0。
- 收获正常路径压缩为：`四格可摘（如有）先连续点完 → 手形一键按钮一次 → 等约3秒 → 空地终验`。没有四格可摘时只需要手形按钮一次。
- QQ 主窗口快速入口曾实测：当前 1239×928 主窗口，左侧农场图标中心相对窗口左上约 `(31,307)`；切回 QQ 主窗口后左键一次即可打开农场。
- 仓库实测确认：`仓库 → 种子` 的 row-major 顺序就是当时土地 picker 顺序，每行 5 个对应一页。
- 曾完整重扫两边实时仓库并保存快照；该快照已过期，现已删除。当前账号库存以 `docs/seed-catalog.md` / `data/seed-catalog.json` 的最近已知数量为准。

## 关键错误与纠正

- 早期操作最大的耗时不是 CGEvent 点击，而是实时阶段反复截图、显示整图、重新思考。算法研究与库存规划应放在操作轮次之间；真正开始农田操作后只执行已经确定的步骤。
- QQ 四格种植曾把 2×2 预览误当成已经种下，随后点击其它土地，实际改变/取消了预览。现行硬约束是：`选种 → 预览 → 明确确认 → 验收落地` 完成前禁止点其它土地。
- 一键普通种植曾出现未填满土地。不能把计划点击当作种植完成，必须以最终田地画面验收。
- 曾尝试从历史 picker 页面重建隐藏固定顺序，但实时页与还原表有缺口；后续实测确认仓库顺序与 picker 顺序对应，旧隐藏排序模型已停止使用并在 2026-11-09 清理。
- 曾误把单株大铲子当成全局 one-key clear；实测确认残株清理仍由手形全局按钮处理。
- 曾把整屏截图直接传给 `ui_probe.py`，导致网格错误缩放；当时已加输入尺寸保护。
- 窗口焦点曾造成滚动/点击发给 Chrome/Finder。仓库滚动规则已明确：先确保农场前台，再在种子网格内部鼠标拖动；滚轮无效。
