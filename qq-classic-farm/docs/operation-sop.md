# QQ 农场按次操作决策

本页是用户说“操作农场／收菜／跑一轮”时的脚本选择入口。用户只需发起操作，无须逐项列脚本；Agent 根据当前日期、已完成动作和田内状态选择。用户本次指定范围优先。只处理 QQ，不启动后台调度或自动续跑。

## 1. 操作前读取

读 `CURRENT.md` 的当前实种批次、种植时刻和当日日常完成记录，以及 `../data/operation-plan.json` 的下一次计划。库存以 `seed-catalog` 最近现场读取加已记录增减为准；正常开窗不重扫仓库。用户报告买种、卖种、误种或库存异常时才核实受影响状态。

日期按 Asia/Shanghai 的自然日，以 00:00 为界。开窗次数不是每日任务完成次数；各项独立记账，未完成不能因“今天已来过”被跳过。跨日只重置当天资格，不补跑错过日期。用户人工完成的项目也记为已完成。记录不确定时先核实，不直接重做。

每次开窗：`farm_window.py open --platform qq --execute` → 等待 5 秒 → Agent 确认自己的土地首页、窗口标准且无遮挡 → 选择下列分支。确认完成后固定动作串行执行，不逐步插入例行截图。报错即停；仅在核清部分完成情况、修正原因后从未完成步骤恢复，不重跑整条链。

## 2. 土地状态决定收获方式

| 现场与当前批次记录 | 本次动作 |
| --- | --- |
| 作物已成熟 | `farm_harvest_once.py`，不先施肥；四格按当前实种记录传 `--planted-plan` |
| 尚未成熟，已进入最后非零阶段，普通肥本季尚可用 | `farm_fertilize_once.py` 普通肥一次 → 等 2.2 秒 → 收获 |
| 尚未到最后阶段 | 不提前施肥、不铲掉作物、不种萝卜；可处理符合条件且当日未完成的日常，按当前批次维护提醒后关闭 |
| 土地全空 | 跳过初始施肥/收获，直接进入当天剩余萝卜循环或正式种植 |
| 多季收获后仍在再生，或仅部分地可收 | 不假定全田空；保留作物，按实种季数与阶段处理，不执行全田萝卜或普通一键补种 |
| 遮罩、误种、时刻不明、界面与记录冲突 | 先核实，不按旧快照推断可执行步骤 |

一键务农由施肥脚本在需要时处理；若本次不施肥但用户要求单独务农，按玩法规则操作。仓鼠出现时沿用已有“气泡出现就购买”规则，通过 `farm_hamster_once.py` 处理；不在独立脚本验收前把分享加入日常；放虫和种草等未实现项目也不顺带执行。

## 3. 每日项目与补货

| 项目 | 什么时候做 | 什么时候跳过 |
| --- | --- | --- |
| 白萝卜经验循环 | 当天尚未完成 5 轮，并且全田已空；运行 `farm_radish_xp.py --rounds 剩余轮数 --execute`，成功轮次逐项记账 | 当天 5 轮已完成、田未空，或用户要求只收获；中断后只补剩余轮数 |
| 白萝卜补货 | 已知库存小于本次剩余轮数 ×24 时，先用 `farm_radish_restock.py` 月度补货，再按完成次数记账 | 库存足够时一律跳过，不因跨日或再次开窗重复购买 |
| 每日任务 | 当天未完成且已经完成一次采摘后，`farm_daily_task_once.py` 互动首位好友并领奖 | 已完成则跳过；当天尚未采摘时不把任务记为全部完成 |
| 好友全扫 | 当天尚未完成时，跟在每日任务后运行 `farm_friend_sweep.py`；用户明确再扫时可单独运行 | 当天正常日常已经扫过则默认跳过，不随收菜频次重复扫 |
| 免费化肥 | 当天未领则 `farm_daily_fertilizer_reward.py`；无需等待田空 | 已领取则跳过 |

`CURRENT.md` 记录各项日期、完成轮数/状态。当天若只来过但没有收获，不能把萝卜和每日任务算完成。萝卜使用双肥；实际经验受游戏每日上限影响，不以理论轮数收益代替到账数据。

## 4. 正式种植与耗尽补种

正式种植只用唯一 `operation-plan.json`。`slot` 是页内种子序号，`page_items` 是当时该页剩余种类数；居中换算见 `gameplay-rules.md`。库存扣到 0 后，该种子从选择器消失，后续种子的页槽与末页数量必须重新计算。萝卜脚本从当前有效库存顺序计算位置，不写死末页槽位。

具体种子、预期数量与耗尽前后位置由唯一计划文件维护，批次含义见CURRENT。普通一键种植依靠第一种剩余库存耗尽，再用第二种填剩余空地；`quantity` 是预期消耗，不是游戏输入数量。库存发生变化时先重算。

`farm_plant_once.py` 首次执行完成四格和第一种普通种子后，因计划含 `ordinary_after_exhaustion`，返回明确的待补种状态和退出码3；这不是整轮完成，也不是需要重跑。Agent 只在这个新混种分支检查剩余空地，选已确认坐标且不在禁点/四格覆盖中的入口，再运行：

```sh
python3.13 scripts/farm_plant_once.py --platform qq --followup-entry <现场确认的空地编号> --execute
```

该命令只种计划中的后续普通种子，不重跑第一段。补种入口不能猜24号仍空；由Agent观察处理，无须用户再次指定种子。验收状态见Todo。

## 5. 脚本组合与收尾

独立脚本是正式执行单位。`farm_qq_round.py` 仅按Agent已确定的参数串行，不负责自动判断页面或日期：

- `--field-state tail|mature|empty` 必填；未到尾段不使用整轮入口。
- `--radish-rounds 0..5` 默认0；只填当日剩余轮数。
- `--tasks --friends --reward` 按当天各项是否未完成显式选择，默认不做。
- 种植返回待补种状态时整轮立即停住；完成第二段种植后，Agent继续尚未执行的日常，不重跑整轮。

实际收获的四格位置以CURRENT实种记录为准，不能用刚更新的下一批计划替代事实。

完成后按实际动作扣库存，更新当日日常记录和新批次种植时刻；仅正式种植创建最后阶段收菜提醒并读回核验，再关闭小程序并确认。没有新种植时不重复创建同批提醒。规则细节分别以SKILL种植收尾与工作区提醒协议为准。
