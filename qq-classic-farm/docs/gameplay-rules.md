# 玩法与操作规则

## 1. 种植区

农田只认中央 4×6 = 24 个土地格。土地外的池塘、花、喷泉、建筑、道路和其它场景物件全部排除。

土地颜色是等级，不是作物：
- 金土地：产量 +300%，成长提速 +20%，经验 +20%，变异无，共鸣无。
- 紫晶土地：产量 +300%，成长提速 +20%，经验 +25%，变异概率 1.2 倍，共鸣 +25%。

### 成长提速公式

2026-10-22 用同批月见草跨金土地/紫晶土地实测确认：

`实际成长时间 = 基础时间 × (1 - 成长提速百分比)`

因此 20% 提速时，12 小时基础成熟时间实际为 `12h × 0.8 = 9.6h = 9小时36分`，不是 `基础时间 ÷ 1.2`。两类土地当前成长提速相同，所以同基础成熟时间的种子仍保持同一成熟时刻。

## 2. 收获

### 1 格普通作物
- 成熟后可用游戏自带“一键收获”。
- 对多季作物，非最后一季只收获；最后一季收获后会进入清理完成状态。
- “一键收获”按钮常驻，不能凭按钮存在判断是否成熟。

### 4 格特殊植物
- 占连续 2×2 土地。
- “一键收获”不会处理。
- 成熟唯一可靠信号：植株头顶黄色星形 + “可摘”。
- **收获时必须精确点击头顶“可摘”星标**；点击植株本体只会打开状态面板，不等于收获。
- 收获成功后植株变成黑色残株；再点击残株，界面显示“已枯萎，待铲除！”，并出现铲子动作。
- 点击铲子后，目标 2×2 才真正恢复为裸土地。
- 完整链路：`点“可摘”星标 → 收获动画 → 黑色残株 → 点残株 → “已枯萎，待铲除！” → 点铲子 → 2×2 裸土地`。
- 多个 4 格植物必须逐个执行上述链路；“没有可摘”不是完成条件，最终必须检查每个 2×2 土地是否重新露出。

### 状态干扰
- 一键收获后会出现经验星、升级、图鉴等动画/弹窗，先处理或等稳定后再判断。
- 经验星动画不能当成“可摘”。

## 3. 普通 1 格种植

- 点任意空土地打开种子选择器。
- 操作前确认“一键种植”已勾选；用户当前配置默认勾选。
- 每页最多 5 个种子选项。
- 总页数随当前库存动态变化，不预设固定页数。
- 第一页无左箭头；最后一页无右箭头；页码形式如 `1/8`。
- 用箭头翻到目标页，再单击种子。
- 普通种植选种默认**从后往前找**：4 格特殊种子通常集中在列表前部，从末页/后部开始挑选普通 1 格种子可以显著降低误入 `2×2` 特殊种子放置分支的概率；若仍出现 `2×2` 绿色放置框则立即取消。
- 选种前先确定：当前空地数、候选种子最新库存、候选种子的基础成熟时间，以及**下一次计划打开游戏的时间窗口**。
- 选种目标不是单纯“库存够就种”，而是让 QQ / 微信尽量落在同一个成熟窗口。当前金土地与紫晶土地均为 20% 成长提速，因此：基础 8 小时种子实际约 **6小时24分**成熟；基础 12 小时种子实际约 **9小时36分**成熟。
- 默认经验：**白天优先 8 小时种子，深夜/过夜优先 12 小时种子**。但最终以“预计成熟时间是否接近下一次方便打开游戏的时间”为准；如果 8 小时会落在凌晨无人操作时段，应改选 12 小时。
- 两个平台同一轮应优先选择**相同基础成熟时间**。即使两边实际种植相差几分钟，也能保持成熟窗口接近，下一次可以一起收获。
- 若两边无法使用同一成熟时长，下一次合并操作时间取两边预计成熟时间的**较晚者 + 少量缓冲**，并在下一轮重新对齐。
- 优先使用单一种子填满整轮空地；如果库存不足必须混种，第二种优先选择与第一种**基础成熟时间一致**的种子，使同一轮尽量同时成熟，方便统一收获和时间计算。
- 因金土地和紫晶土地当前成长提速都为 20%，基础成熟时间一致的种子在这两类土地上仍会保持同一成熟时刻。
- 一键种植会尽量填充空地，但受库存限制；库存不足时只种现有数量，再按“成熟时间一致”规则选择下一种补齐。

### 4 格特殊种子种植
- 4 格特殊种子占连续 **2×2 = 4 格土地**，**只能单颗种植，不能使用一键种植批量铺满**。
- 非边界情况下，先确定准备占用的目标 2×2 区域；在这 4 格中，点击画面上**视觉位置最上方的那一格**作为种植锚点。
- 点击锚点后选择对应 4 格特殊种子，游戏会默认生成覆盖这 4 格的 **2×2 放置预览**。
- 选种后必须再点一次**二次确认**，确认后才真正种下并消耗 1 颗特殊种子。
- 若需要种多颗 4 格特殊种子，必须对每一个目标 2×2 区域重复 `点最上方锚点 → 选种 → 二次确认`，不能批量。
- 普通种植流程若误选特殊种子并出现 `2×2 绿色放置框 + 确认/取消`，说明已进入特殊种子分支；若本轮本意是普通 1 格种植，应立即取消，不得误确认。
- **靠农田边界时游戏会自动调整 2×2 覆盖方向**，不需要人工反推朝向；仍以放置预览为准，确认预览覆盖的是目标四格后再点二次确认。
- 4 格特殊种子的土地加成按其覆盖区域中的较低土地档结算：目前已知若同时覆盖紫晶土地和金土地，会按**金土地**计算。因此不要为了占到部分紫晶而让一个 2×2 跨越紫晶+金地。
- **微信当前布局**：紫晶土地数量/形状足以安排 **2 个完整 2×2 四格种子**，所以有合适的 4 格活动种子时，优先把这两个 2×2 完整放在紫晶土地上；其余土地再种普通 1 格种子。
- **QQ 当前布局**：紫晶土地暂时凑不出一个完整 2×2 正方形；4 格特殊种子优先选择完整的金土地 2×2 区域，避免跨紫晶+金地却仍按金地结算。

## 4. 化肥、务农与神秘商人

### 化肥催熟
- 化肥分为**普通化肥**和**高级化肥**。
- 施肥前先检查右下“一键施肥”是否勾选；该状态按平台/窗口独立保存，不能假设 QQ 勾选后微信也会同步。勾选后，一次施肥会作用于当前所有符合条件的作物，包括普通 1 格作物和 4 格特殊植物。
- **普通化肥：每个生长阶段每株最多使用 1 次。** 对可多次收获的作物，第一次成熟前可用 1 次；第一次收获后进入下一生长阶段时，又重新获得该阶段的 1 次普通化肥机会。
- **高级化肥：同一生长阶段可以连续使用多次。** 标准催熟逻辑为 `当前阶段普通化肥 1 次 → 高级化肥重复若干次 → 直到成熟 → 收获`；若收获后还有下一阶段，则重新从“普通 1 次”开始。
- 高级化肥不要预设固定次数；每次后根据剩余成熟时间/成熟画面决定是否继续。2026-10-24 QQ 当前批次从约 7小时20分剩余开始，普通 1 次后再用高级 3 次达到成熟，仅作为本次实测，不作为恒定次数。
- 若点击化肥后出现确认弹窗，先确认，再检查**库存或剩余成熟时间是否实际变化**；若仅完成模式确认、尚未真正施肥，则需要再点一次对应化肥。不要把“弹窗确认完成”直接视为施肥成功。
- 催熟达到成熟后，普通 1 格作物仍按“一键收获”处理；4 格特殊植物仍按本文件 §2 的“可摘 → 残株 → 铲除”链路逐个处理。

### 一键务农
- 只会在作物**未成熟**阶段出现；作物成熟后不会出现“一键务农”。
- 普通种植期间如果出现杂草或虫害，界面下方会出现“一键务农”。
- 看到“一键务农”时直接点击一次，当前杂草/虫害会一次性处理完成。
- 不需要逐格判断是杂草还是虫子，也不需要逐格处理。
- 状态判断上，“一键务农”存在可作为“当前至少有未成熟作物”的辅助信号，但不能替代对作物本身状态的视觉判断。

### 左下角仓鼠 / 神秘商人
- 土地左下角的仓鼠类角色会不定时在头顶出现物品气泡，气泡内显示物品与数量。
- 每次进入自己的农场、以及从商城/好友农场等页面返回自己的农场后，都把**仓鼠头顶是否有物品气泡**列入固定视觉巡检；这是纯视觉状态，不能依赖 OCR 文本判断。
- 用户长期规则：**只要气泡出现就购买**，不根据物品种类或价格筛选；该规则限定于这个仓鼠/神秘商人的种子或化肥购买事件。
- 操作链路：`点击头顶气泡 → 打开神秘商人 → 点击购买 → 等待“恭喜获得” → 点击空白关闭`。

## 5. 日常小活动

### 任务书
- 入口：左下角仓库按钮上方的书本图标。
- 打开后上半部分为成长/主线任务，下半部分为每日任务；底部显示每日任务刷新倒计时。
- 每次打开后都现场读取每日任务文字与按钮状态，不假设任务内容或排列顺序永久固定。
- 主线任务按账号进度独立；每日任务的“领取 / 已完成 / 前往”等状态也按平台分别读取，不跨平台推断。
- 当前已验证的三类每日任务中，“每日登录”在正常打开游戏后即可完成，“采摘 1 次果实”在正常收获后即可完成；两项完成后只需在任务书点击“领取”。
- “在 1 个好友农场进行互动”需要实际进入好友农场完成一次交互后才会变为可领取；完成一位好友的任一有效交互已经足够满足该每日任务。
- 好友交互入口：右下角“好友”。好友列表默认把当前可交互好友排在前面，每页最多显示 5 位。
- 好友行上的**手 + 眼镜**标志代表可以偷菜；**锄地/务农**标志代表可以帮忙清理虫害或杂草，务农会获得经验。
- 标准完整链路：
  1. 打开好友列表，确认第一位好友存在可交互标志后点该行“拜访”。
  2. 进入好友农场后，底部可能出现“一键偷取”“一键务农”中的一个或两个；**出现哪个就点哪个**。某项处理成功后对应按钮会消失。
  3. 一位好友处理完后，从底部横向好友列表点击下一位仍显示可交互气泡/标志的好友继续处理。
  4. 遇到“下一位已经没有可交互气泡”，或进入下一位后底部已没有任何“一键偷取 / 一键务农”按钮，即停止继续访问。
  5. 点击右下角“回家”返回自己的农场，再打开任务书领取每日任务奖励。
- 每日任务领奖完成后，三个对应按钮应从“领取”变为“已完成”；关闭任务书后必须确认已经回到自己的正常农田。

### 商城每日福利
- QQ、微信均有右上角“商城”入口，每天各可领取一次免费福利。
- 固定链路：`右上角商城 → 底部“礼包商城” → “每日福利”卡片 → 点“免费” → 出现“恭喜获得” → 点击空白关闭 → 左上角返回 → 回到正常农田`。
- 领取前“每日福利”显示 `每日限购 1/1`；领取成功后显示 `每日限购 0/1`，可作为当天是否已领的判断依据。
- 只处理“每日福利”的免费按钮，不点击旁边的其它付费礼包、广告礼包或充值入口。
- 左上角返回后不能把“发出返回点击”直接视为完成；必须重新确认已经看到自己的正常农田和底部农场导航，再继续其它步骤或结束本轮。

### 每日首次分享
- QQ、微信均有“分享”入口。
- 打开后明确显示：**每日首次分享可获得 化肥礼包 ×5**。
- 固定分享目标：微信搜索并选择 **“咩不是咩是喵”**；QQ 搜索并选择 **“灬🐈‍⬛、御汐。”**。必须使用分享弹窗/面板内的搜索框精确搜索，不依赖预填联系人列表。
- 微信链路：`农场分享页 → 分享 → 微信农场窗口内出现联系人选择器 → 搜索目标 → 选中 → 发送 → 自动回到农场分享页 → 按“领取” → 出现“恭喜获得” → 关闭获得弹窗 → 关闭分享栏 → 回到正常农田`。
- QQ 链路：`农场分享页 → 分享 → 焦点跳到 QQ 主程序窗口的分享弹窗 → 搜索目标 → 选中 → 点“确定”发送 → 仍停留在 QQ 主程序窗口 → 手动切回 QQ 小程序农场 → 按“领取” → 出现“恭喜获得” → 关闭获得弹窗 → 关闭分享栏 → 回到正常农田`。
- 所以两边都不是“点分享即到账”：实际发送后，还必须回到奖励页再点一次“领取”。
- QQ 分享后不会自动回农场；后续正式流程中必须显式执行“返回 QQ 农场”。优先通过程序坞中的 QQ 小程序图标返回；自动化实现禁止写死 Dock 绝对坐标，需先唤出 Dock 并确认“QQ小程序”图标位置。

## 6. 仓库读取

路径：仓库 → 种子。

- 当前种子列表每屏约 4×5。
- 点击某个种子，下方显示名称、成熟、可收、季产、经验、收入等。
- 上下查看列表必须鼠标按住拖动，禁止滚轮。
- 概率获得字段暂时忽略。
- QQ 与微信对同名种子的季产、经验、收入可能不同；视为账号/平台当前显示值，不推断成全服基础属性。

## 7. 窗口与状态恢复

项目级安全红线以 `../CLAUDE.md` 为唯一权威；本节只维护游戏 UI 的恢复规则。

- 每个关键动作后截图验证，不连续盲点。
- 农场大多数状态由图标、头像、气泡、按钮形态和画面变化表达，**默认优先直接用截图做视觉定位与识别**。OCR 只用于确实需要读取文字、数字、任务内容、库存数量等信息的场景；不能把 OCR 当成普通页面定位的默认手段。
- 对好友交互尤其如此：好友头像和头像框可能完全不同，但可交互气泡/标志的图形样式稳定，因此应识别“气泡/标志是否存在”，不要识别具体头像是谁。
- 窗口位置改变后重新读取窗口位置。
- **截图像素坐标不能直接当作 macOS 屏幕点击坐标**。Retina/缩放环境下截图常为 2× 像素；从局部截图反推点击点时，必须先按截图实际像素尺寸与逻辑窗口尺寸换算，再加窗口/画布原点。优先复用已经验证过的逻辑坐标，不从放大后的截图直接抄像素坐标。
- 若 Safari / ERP / 其它置顶窗口覆盖农场可操作区域，**不要在重叠坐标继续试点**。先把农场窗口移动到无覆盖的安全区域并重新读取窗口位置/画布边界，再继续操作；这样既避免误点其它业务系统，也减少反复截图确认。
- **所有平台打开农场前先检查程序坞**：如果对应农场小程序已经打开，直接从程序坞切回农场，不再进入微信/QQ 主程序重新打开。
- **微信农场未打开时的状态式恢复流程**：
  1. 切到一直存在的微信主窗口。
  2. 先判断当前是否已经位于“发现”页；若不是，再点击“发现”。若已经在“发现”页，不重复点击。
  3. 再判断右侧当前是否已经显示“游戏 / 找游戏”页面；若已经显示，就**不要再点击“游戏”**，因为再次点击会取消该选择并使右侧内容区域变空。
  4. 只有当前还不在游戏页时，才点击“游戏”。
  5. 在右侧“最近玩过”中找到“QQ经典农场”并点击，等待农场独立窗口出现。
- **QQ 农场未打开时的恢复流程**：QQ 主窗口长期保持存在。优先直接点击 QQ 左侧栏固定的**农场图标**（用户已提供图标样式），等待农场独立窗口出现；无需先进入“更多功能”。只有直达图标异常/不存在时，才退回 `更多功能 → QQ农场` 作为备用入口。QQ 不需要像微信一样区分“发现 / 游戏”二级页面，也不要去 App / 进程列表寻找另一个农场程序。
- 程序坞中的农场图标只承担“已经打开时快速切回”的职责，不应先通过枚举 App / 进程列表来寻找农场。
- QQ 分享后焦点落在 QQ 主程序窗口时，优先检查程序坞中的 QQ 农场图标并直接切回农场奖励页。

## 8. 日常快速执行策略

### 当天首次完整流程

以每个平台当天第一次实际操作为完整轮。判断依据优先使用 docs/CURRENT.md 中已验证日期；同一天已经明确完成的项目不再次打开页面复核。

推荐顺序：

1. **恢复农场窗口**：先查程序坞；已有农场直接切回，没有才走平台恢复入口。
2. **单张整页截图做首轮状态判断**：同时看普通作物是否成熟/空地、是否有“一键务农”、仓鼠物品气泡、明显弹窗。默认不跑 OCR。
3. **收获 → 普通种植**：成熟就一键收获；处理必要弹窗后种满空地。选种从后往前找普通 1 格种子。
4. **务农 / 神秘商人**：画面存在按钮或气泡才点；不存在立即跳过。
5. **每日首次分享**：当天尚未完成才执行；完成后当天后续轮次直接跳过。
6. **商城每日福利**：当天尚未完成才执行；完成后当天后续轮次直接跳过。
7. **好友交互**：每轮都执行，因为偷菜/务农机会与每日任务本身分开；按标准气泡和按钮链继续到停止条件。
8. **每日任务领奖**：只在当天首次完整轮执行。好友交互完成后再统一打开任务书，此时“登录 / 采摘 / 好友互动”通常三项可一次领取；确认三项均“已完成”后，当天不再打开任务书。
9. **最终整页截图**：确认回到自己的正常农田，并检查遗漏的“一键务农”与仓鼠气泡。
10. **计算下一次打开时间**：记录本轮 QQ / 微信各自实际种植完成时间与基础成熟时长，套用当前土地成长提速计算预计成熟时间。两边成熟窗口一致时，下一次按较晚成熟者 + 少量缓冲打开；不一致时也以较晚成熟者作为合并操作时间，并在下一轮优先重新对齐。

### 当天后续快速流程

若 docs/CURRENT.md 已明确记录该平台当天的分享、商城每日福利、三个每日任务奖励均已完成，后续再次打开时固定跳过这些日常页面，只做：

恢复窗口 → 1 张农田截图 → 收获（如成熟）→ 种植（如有空地）→ 一键务农（如有）→ 神秘商人（如有气泡）→ 好友交互偷菜/务农 → 回家 → 最终确认

若作物尚未成熟且没有空地，则直接跳过收获/种植，只处理务农、神秘商人与好友交互。

### 固定窗口下的加速原则

- QQ / 微信农场窗口尺寸和布局稳定时，**点击位置按当前游戏画布（game canvas）的左上角做相对坐标复用**，不要默认以整个应用窗口左上角为基准。
- **微信默认按“左侧游戏侧栏 + 右侧农场画布”处理**；左侧侧栏不是异常，而是常态布局。所有农场按钮坐标必须锚定右侧 game canvas，不能锚定整个微信窗口。当前固定窗口实测约为 `1039×1155`，右侧 game canvas 起点约在窗口左侧偏移 `418–420px`，画布宽约 `620px`；此数值只作为当前布局快速基线，若截图边界不符则重新标定。
- QQ 农场独立窗口通常就是完整 game canvas，坐标可直接相对 QQ 农场窗口；若出现额外侧栏/嵌入布局，则同样先识别 game canvas 边界。
- 入口、分享、商城、好友、任务书、返回/关闭等稳定按钮均属于“固定位置动作”；先用当前截图确认页面类型正确，再直接点相对坐标。
- 页面判断优先使用**小区域截图（ROI）**：例如只截底部操作区判断“一键收获/一键务农”，只截左下仓鼠区域判断气泡，只截好友底栏判断下一位是否有交互气泡。只有状态不符合预期时再升级到整页截图。
- 已跑通链路不要求“每一步一张整页截图”。正常路径只在状态转换关键点截图；异常、弹窗、点击后页面未变化时才追加截图。
- OCR 仅用于必须读取的动态文字/数字（任务内容、库存、页码等）；图标、气泡、按钮存在性、农田成熟/空地等全部走视觉判断。
- 好友头像与头像框不作为定位依据；只看稳定的交互气泡，以及好友农场底部“一键偷取 / 一键务农”按钮。
- 普通选种从后往前；优先复用知识库中已确认的普通 1 格种子图标和库存，但**先按下一次计划打开时间筛选 8h / 12h 成熟档**，再在对应档里找库存足够的种子。不能因为末页第一项库存最大就忽略成熟时间。
- 当前活动种子若成熟档与本轮目标一致，优先消耗活动种子；库存不足 24 时允许用同基础成熟时间的普通种子补齐，仍保持整轮同一成熟窗口。
- 选种执行时只校准“计划目标种子 + 必要备选”的当前数量；不为选种重新扫描整个仓库。活动奖励导致历史库存变动时，以选择器本次看到的候选数量覆盖旧估计。
- 正常链路优先短等待（约 0.4–1 秒）后检查局部状态；只有页面加载、分享跨程序切换、升级动画等已知慢步骤才增加等待。

### 下一轮加速验收

下一次用户要求再次操作时，先按本节快速路径执行，不做定时化。记录实际开始/结束时间以及发生的异常分支，用实测决定是否还需要进一步脚本化。目标不是追求零截图，而是在安全确认前提下把重复判断压缩到最少。
