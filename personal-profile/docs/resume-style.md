# 简历表达与排版原则

## 总体气质

用户偏好低调、克制、事实型表达，不喜欢“站出来给自己下定义”。

目标不是把用户包装成某个热门标签，而是让招聘方从真实经历自然看出：

- 业务经验深；
- 能独立承担较大业务量；
- 熟悉 ERP / 履约 / 售后 / 异常处理；
- 已经把 AI / 自动化实际用于自己熟悉的业务。

## 文案原则

### 1. 事实先于结论

优先写：

- 做过什么；
- 规模多大；
- 负责哪些环节；
- 用过什么工具；
- 如何处理异常。

少写：

- “我是什么样的人”；
- “我的核心价值是……”；
- 宣言式定位句；
- 替招聘方总结“我很强”。

### 2. 不主动辩护或降级

避免：

- “并不把自己定位成传统 RPA / Python 开发人员”；
- “RPA 只用于基础流程”；
- “复杂自动化主要依靠 AI”；
- “不是为了追求全自动”；
- “仅为可核验的已统计部分”。

这些内部边界可以在面试被问到时如实解释，但简历不主动写“我不会什么”。

RPA 在简历中的正确方式是写真实案例，例如：

> 与技术人员配合使用影刀 RPA，优化采购及入库进度监控、补货周期及相关数据计算流程。

工具栏直接写“影刀 RPA”，不加“基础”括号。

### 3. 业务是事实主线，AI 不抢戏

不要写“AI 赋能业务”“业务是主线，AI 是方法”等口号。

用具体内容体现关系：

> 根据实际业务梳理处理规则、异常情况和人工判断条件，并借助 Codex、Claude Code、WorkBuddy 等工具完成内部自动化工具的搭建和持续修改。

### 4. 禁用空泛词

尽量不用：

- 赋能
- 闭环
- 抓手
- 重构
- 沉淀方法论
- 全链路

除非真实业务语境确实必须。

### 5. 不虚构数字

不得编造：

- 效率提升百分比；
- 节省工时 / 成本；
- 自动化准确率；
- GMV；
- 未确认的业务规模。

当前活动规模使用“营业额 / 销售额”，不要擅自换成 GMV。

### 6. 不夸大职责

- 不写“负责仓库”，写“仓库对接 / 仓库协调 / 履约协调”。
- 采购项目不包装成长期采购职业路线。
- AI 自动化不包装成传统软件开发。
- 游戏、农场、魔兽等个人自动化默认不进入职业简历。

## 内容取舍

- 当前简历可以两页 A4，不为了压成一页删掉历史工作经历。
- 2018 以前经历只说明存在，不逐项展开。
- 现行工作经历至少保留：绰绰、超乎、仓力、备胎说车、赫美。
- 项目经历保留：电商业务流程自动化、即时零售采购项目。
- 80 亿+ Token 可以作为工具使用强度信号，但不能成为整份简历的主角。

## 设计偏好

已经否定的方向：

- 左右分栏塞满信息；
- 大量卡片 / Dashboard 风；
- 明显“AI 简历模板感”；
- 为了高级感极端压缩正文；
- 顶部大号宣言句。

当前较认可方向：

- 两页 A4；
- 有设计感但不抢内容；
- 暖铜色作为克制强调色；
- 关键业务规模与 AI 使用可以形成视觉锚点；
- 正文完整、层级清楚；
- 顶部使用普通职业概述，而不是自我宣言。

## 当前认可的概述

> 多年电商客服、售后及业务后台经验，熟悉 ERP、订单履约、仓库、物流和平台售后等实际流程。借助 AI 编码工具和 RPA，将售后、订单、ERP 等业务中的部分重复操作逐步工具化，并根据实际规则和异常情况持续调整。
