# 2026-10-28 简历与职业方向重定位

## 本阶段做了什么

- 从原有客服 / 售后履历重新梳理职业方向，不再把自己限制在“客服主管”。
- 结合真实工作经历，将主方向收敛到业务数字化、流程自动化、需求分析、系统实施和 AI 业务应用。
- 对照杭州真实招聘 JD 做过一轮市场校准，确认业务侧 RPA / 数字化岗位最贴近现有经历；需求分析、实施顾问可以选择性投递。
- BOSS 求职期望调整为：需求分析工程师、实施顾问、产品运营，杭州，10–15K。
- 更新 BOSS 在线工作经历与项目经历。
- 重新制作个人简历并经过多轮版式与措辞调整。

## 关键职业叙事

最终不采用“从客服转行 AI / RPA”的讲法。

更准确的事实关系是：

- 用户本来就在长期处理电商后台、ERP、履约、售后、异常和规则；
- 对业务为什么这样处理、哪里容易出问题有长期一线经验；
- 后来开始借助 AI 编码工具和 RPA，把自己原本在做的重复工作逐步工具化。

AI / 自动化是现有业务能力的延伸，不是凭空增加的职业标签。

## 简历设计演进

否定过：

1. 左右双栏、卡片堆叠的一页版：信息太挤，AI 模板感强。
2. 极简黑白单栏的一页版：虽然干净，但为了塞进一页压缩了历史经历，也没有突出业务 + AI。
3. 顶部大号宣言句：“我原本就在负责这些业务……”：内容本身准确，但用户不习惯如此直接突出自己，觉得 AI 味和“站出来证明自己”的感觉太重。

最终较认可：

- 两页 A4；
- 有设计感但不做 Dashboard / 卡片模板；
- 暖铜色作为单一强调色；
- 第一页通过真实业务规模与 AI 使用形成视觉重点；
- 完整保留旧工作经历；
- 顶部改成普通职业概述，不用宣言；
- 让招聘方从事实和数字自己得出结论。

## 关键措辞修正

本阶段形成了一条重要规则：**简历不要主动替自己解释能力边界。**

删除 / 避免过的表达包括：

- “RPA 只用于基础流程。”
- “复杂自动化主要依靠 AI 辅助完成。”
- “并不把自己定位成传统 RPA / Python 开发人员。”
- “优先保证判断可靠而不是追求全自动。”
- “仅为可核验的已统计部分。”
- “业务是主线，AI 是方法。”

这些话作为内部事实或设计原则可能成立，但放在简历里会变成主动辩护、自我降级或替招聘方下结论。

正确做法是只展示真实经验，例如：

> 参与采购流程自动化改进，与技术人员配合使用影刀 RPA，优化采购及入库进度监控、补货周期及相关数据计算流程。

以及：

> 梳理实际业务需求、处理规则、异常场景和核验条件，并借助 Codex、Claude Code 等 AI 编码工具完成内部工具的搭建、修改、测试和问题排查。
