# 2026-07-22 按轮次归属与 neat 收尾归档

## 问题

用户通常从 `/Users/chat` 启动 Codex/CodexPro，再按本次需求选择项目文件，不会为每个项目单独启动 Codex。旧 reader 给整段 session 只推断一个项目，导致临时工作树、子代理、跨任务长会话和示例路径大量进入“其他”或被错误归属。

真实数据中，`某项目` 来自 WorkBuddy 示例路径，不是项目；历史工作树则保留了可验证结构：

```text
~/.config/superpowers/worktrees/claude/<临时任务名>/<正式项目名>
```

## 稳定方案

- 以 `user_message` 为轮次边界，每轮单独归属项目。
- 正式项目 `cwd`、用户明确路径和真实工具 `workdir` 是主要证据。
- 同一轮先产生的 token 等轮次项目确认后统一回填。
- 从完整工作树路径建立唯一别名；不按 `aftersales-*` 等名称前缀猜测。
- 子代理无更强证据时继承父会话启动时刻的已确认项目。
- 无效最终候选、占位词和冲突映射继续归入“其他”。

## neat 的角色

neat 是会话收尾确认，不取代逐轮真实操作：

- 只有明确 `/neat`、`/sync`、`整理一下`、`收尾` 等指令触发。
- neat 确认单一项目且会话没有其他明确项目时，可回填未知或过期继承的弱归属。
- 已经确认的跨项目分段不被最后一次 neat 覆盖。
- 仅讨论 neat 是否有用，不视为收尾标记。

## 真实效果

2026-07-22 第一轮滚动 30 天 smoke 中，“其他”由修复前约 `32.6%` 降至约 `16.2%`；工作树别名加入后，大量售后历史用量回到“鲸灵售后自动化”。

同日第二轮继续补充新版嵌套 `exec` 路径、项目自声明 `项目历史路径：` 和 Claude 单项目确认区间回填。“语音取回”新项目声明旧路径 `/Users/chat/phone-voice-paste` 后，历史与迁移后的用量合并显示约 `33.9M`；“其他”进一步降至约 `11.7%`。第三方 CodexPro、Skills/WorkBuddy 工具维护、确认区间外的根讨论和真实跨项目会话继续保留在“其他”。

## 边界

- 归因变化只调整项目分布，不改变 token 总量、时间窗口或 quota。
- reader 不修改原始 JSONL，也不读取 `.codex/auth.json`。
- 不要求安装 Hook，不要求用户在第一句手动填写项目。
- Superpowers Skill 被删除不影响运行；历史路径只作为日志结构解析，未来直接项目 `workdir` 继续正常识别。
