# WorkBuddy 记忆与工作区治理归档

日期：2026-09-13  
状态：已完成并验证。本目录只记录历史决策，不是 WorkBuddy 现役规则入口。

## 本轮目标

把 WorkBuddy 从“依赖聊天/日期日志/混合 MEMORY 恢复上下文”收敛为可冷启动、模型无关、单一权威的结构；同时清理历史工作空间、旧日志和希凝工作区残留，避免长期规则继续膨胀。

## 最终架构

- 用户级长期记忆只放跨工作空间都成立的工作纪律，不保存项目业务速查或实时状态。
- 正式项目优先用根 `CODEBUDDY.md` 作为导航与硬边界入口；`.codebuddy/CODEBUDDY.md`、`AGENTS.md` 仅作为后续加载候选。
- 项目 `.workbuddy/memory/MEMORY.md` 是可选稳定事实层，不是规则入口，也不会因为缺失而自动创建。
- `.workbuddy/memory/YYYY-MM-DD.md` 只视为低权威历史线索；普通任务不主动生成，也不靠它恢复当前状态。
- 稳定业务规则 / SOP 进入对应现役 Skill；实时库存、待发货、归档、订单等始终回读 WPS / ERP 当前数据。
- WorkBuddy 生成式云记忆通过产品控制面开关、清空和重置；本地缓存不作为人工维护入口。
- 同一事实只保留一个权威来源；入口负责导航，Skill 负责流程，实时系统负责当前状态，archive 负责历史。

## 关键治理结果

- 关闭并清空了 WorkBuddy 的生成式对话记忆，避免旧云画像继续参与项目恢复。
- 重写了 WorkBuddy 全局长期记忆，使其只保留跨项目工作纪律。
- 重构 `neat-freak`：项目 MEMORY 降为可选；日期日志退出默认路径；不再因复杂任务自动建 Skill；`.workbuddy` 改为按对象分治；残留文件名只代表审计候选，不代表可删。
- 重构 `xining-yaohao-shipping-docs`：移除固定库存数字、旧本地 Excel 例外、日志/全局 MEMORY 启动依赖；保留稳定 WPS/ERP 业务 SOP。
- 后续一次真实业务任务验证通过：新会话可按 `CODEBUDDY → 希凝 Skill → WPS/ERP` 工作，普通任务结束后没有重新生成日期日志。
- 用户级长期规则新增“先抽象再沉淀”：只有下次模型缺失该规则会导致错误时才写入；长期层只保留触发条件、稳定规则、必要例外和验证方式，默认删除案例、人名、日期、单次订单/地址、临时路径、一次性报错、内部工具细节、精确性能数字和过程叙事。

## 清理结果

- `~/WorkBuddy/` 最终只保留 3 个正式工作空间；105 个孤儿空间经完整迁移核验后由用户删除。
- 希凝工作区 16 份日期日志完整审计后确认无唯一稳定知识，随后移出并由用户删除。
- 希凝工作区旧脚本、pkl 中间缓存、旧 Excel/xls 备份、ERP 审计副本、旧本地样品清单输出和临时 `vendor/` 参考区均确认无现役唯一价值后清理。
- 希凝正式工作区根目录最终只剩 `CODEBUDDY.md`、`.workbuddy/` 和 `.DS_Store`；新版 neat 盘点显示残留候选为 0。

## 验证结论

- `CODEBUDDY.md` 正常成为希凝项目冷启动入口。
- 项目 MEMORY 不存在，符合设计。
- 项目日期日志为空，普通任务未重新生成。
- `xining-yaohao-shipping-docs` 与 `neat-freak` 均从真实安装路径回读核验。

- 本轮治理临时目录 `.ai-bridge/workbuddy-governance/` 已移出活跃工作区。

## 以后不要从这里恢复什么

- 不把本轮迁移数量、临时路径、一次性案例重新写回全局 MEMORY、项目 MEMORY 或业务 Skill。
