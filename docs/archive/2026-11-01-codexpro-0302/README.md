## 兼容问题与处理

0.30.2 的原生 `readTextFile` 已支持指定行范围读取较大的源文件，但没有自动分页和续读位置：不指定范围时仍会把 `max_bytes` 用作源文件准入门槛，指定范围过大时也会报错。因此保留公开 `read` 工具的分页补丁。

[补丁脚本](../../../scripts/lib/ensure-codexpro-paged-read.mjs)只更新必要的兼容点：

1. 三处源码匹配跟随新版变更：导入列表新增 `listFiles`，`read` 说明新增 `apply_patch`，以及 `read` 后新增 `view_image` 工具。
2. 新版会先检查整个指定区间的编号文本大小。500,000 字节的短行密集文件，续页前的编号文本可能超过 2 MB，导致包装函数来不及裁页。内部编号预算改为有界的 `22_000_010` 字节，并显式提供默认 `startLine`，继续走原生范围读取的 2 MB 源文件上限；对外每页仍按原配置和 `max_bytes` 裁出完整行。
3. 原生窄行范围读取已经可用，因此调整旧拒绝断言；新增短行密集文件续页和显式首行回归，并覆盖不指定范围时的源文件安全上限。

本轮验证中途曾安装只修三处匹配的版本。发现编号区间边界后，确认实装只包含本轮补丁，将两份文件还原到本轮保存的原生源码，再经原启动链安装最终补丁；没有增加长期迁移兼容层。
