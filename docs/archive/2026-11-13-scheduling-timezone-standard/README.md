# 定时任务时间规范建立与现役排期核验

日期：2026-11-13。范围：工作区共享定时任务时间转换、工具适配和排期读回核验。本文只记录本阶段决策、实现与证据；现役唯一规则见 [docs/scheduling.md](../../scheduling.md)。

## 问题与根因

本次维护由两次北京时间晚 8 小时的事故触发：

1. **农场第一次事故**：把用户指定的本地时间直接写进按 UTC 解释的 Codex cron RRULE，导致触发晚 8 小时。农场后来已修复：使用 Python `datetime` / `zoneinfo` 转成 UTC，并读取 SQLite 中调度器实际 `next_run_at`，再转换回北京时间核对。
2. **群聊 heartbeat 事故**：一次性规则把 `BYHOUR=1` 当成北京时间 01:00。实际观测为 UTC 01:00:32，即北京时间 09:00:32。此前只读回规则，没有核验实际 `next_run_at`，所以没有在创建后发现偏移。该任务已删除；本次维护没有恢复或重新安排它。

共同缺口不是农场业务排期算法，而是缺少工作区唯一的通用时间 owner：各项目需要重复说明时区转换与验证；工具成功回执、规则读回和实际触发时间之间的区别没有被提升为跨项目硬约束。

## 方案与边界

- 新建工作区唯一 owner：`docs/scheduling.md`。目标时间必须保留完整日期时间和 IANA 时区；默认客户端目标时区为 `Asia/Shanghai`，但不把所有工具统一当作固定 UTC+8。
- Codex 本机 cron 按农场已经验证的经验：目标用 `datetime + zoneinfo` 转换，创建/更新走官方工具，随后只读读取调度器 `next_run_at` 并转回目标时区精确核对。
- 创建 cron 时，若官方工具 schema 支持 `durable: true`，必须显式设置；工具不支持时不猜参数、不改底层配置。
- ACTIVE 必须有实际 `next_run_at` 且精确匹配目标；PAUSED 没有 `next_run_at` 时只能核验候选规则，不宣称已进入执行队列。数据库不存在、schema 变化或读取失败均明确失败，不猜字段。
- 一次性任务使用工具支持的 `COUNT=1`，保留日期和截止窗口；错过窗口只报告跳过，不自动补跑或改期。
- Mac 提醒事项继续由既有 `docs/reminders.md` 负责。该文档已明确共享快捷指令时间按 Mac 本地时间解释，本次没有复制或改写提醒事项规则。
- 农场继续拥有成熟时间、业务避让、续排条件和实际开工保护；只把通用转换与读回核验改为引用共享 owner。没有重写农场业务逻辑。
- 未建设调度器、daemon、任务创建器或独立辅助脚本。共享能力只用 Python 标准库和现有只读证据。

## 现役任务只读核验

核验范围仅限已知农场任务 ID 与已删除的群聊任务 ID，没有扩大扫描个人其他定时任务。

| 任务 | 状态 | 调度器实际时间 | 北京时间 | 结果 |
|---|---|---|---|---|
| `qq-11-11-21-13` 收种 | ACTIVE | 2026-11-13 06:02 UTC | 2026-11-13 14:02 | 与 CURRENT 一致 |
| `qq-11-12-22-00` 日常 | ACTIVE | 2026-11-13 14:00 UTC | 2026-11-13 22:00 | 与 CURRENT 一致 |
| `11-13-01-00` 群聊 heartbeat | 未找到，已删除 | 无 | 无 | 不恢复、不重排 |

SQLite 使用只读 URI；实际返回的 `next_run_at` 分别为 `1794549720000` 和 `1794578400000` 毫秒。对应 RRULE 分别为 UTC `BYHOUR=6;BYMINUTE=2` 和 `BYHOUR=14;BYMINUTE=0`，均为 `COUNT=1`。没有写入数据库或修改任务。

群聊运行证据 `group-chat-analysis/runtime/nightly/night-20261113-20261020-22/scheduled-check-result.json` 记录 `observed_utc=2026-11-13T01:00:32Z`、`observed_shanghai=2026-11-13T09:00:32+08:00`、`capture_started=false`、`rescheduled=false`、`automation_deleted=true`。因此没有启动采集，也没有补排。

农场提醒的既有回执 `_sandbox/qq-farm-reminder-20261113-1402.ics` 记录 `DTSTART;TZID=Asia/Shanghai:20261113T140200`，`VALARM TRIGGER=20261113T060200Z`，与农场 14:02 本地目标一致。该证据用于确认现有提醒协议的本地时间语义，不代表本次新建提醒。

## 验证

使用临时 SQLite fixture 的离线 Python 检查通过，覆盖：

- 北京时间凌晨跨 UTC 日期；
- 月末、年末跨界；
- 过去时刻拒绝；
- 一次性 `COUNT=1`；
- 夏令时重复时刻和不存在时刻拒绝；
- ACTIVE 的 `next_run_at` 不匹配；
- PAUSED 无 `next_run_at` 仅能核验候选规则；
- SQLite 只读打开失败和 schema 变化失败。

未创建任何会触发真实业务的测试任务。另核对了新增文档的相对链接。
