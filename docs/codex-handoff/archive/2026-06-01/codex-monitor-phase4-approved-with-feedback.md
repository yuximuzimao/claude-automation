## 用户 UI 反馈（需在阶段 5 前处理）

用户预览了 UI 截图，提出以下 3 条修改意见：

### 反馈 1：余额限额模块

**用户要求：** 去掉"余额限额"标题，两个框放大，视觉上明显的左右两个独立框。

**技术分析：** 纯 UI 改动，`_quota_view` 数据结构不变。

**待确认问题：** `used_percent` 是已使用百分比还是剩余？当前 UI 没有明确标出，用户问"你显示的是已使用还是剩余"。需要在值旁边加说明文字（如"已用"/"剩余"）。

---

### 反馈 2：项目消耗模块

**用户要求：** 去掉"项目消耗"双模块（今日/本月/Claude月汇总），只保留 Top 5 项目列表。

**用户的疑问（重要）：** "这是模拟数据吗？按这样的分类我无法看懂是我自己哪个项目。"

**实际情况：** 数据是真实的，但项目名取 `cwd` 最后一级，导致：
- `chat` → 含义不明，是 Codex 在主目录下运行的 session
- `claude` → 整个工作区
- `product-detect`、`codex-monitor` → 清晰

**修改建议：**
1. 去掉 `_section`（项目消耗汇总卡片）
2. Top 5 项目保留，但在"chat"行的 tooltip 里补充说明（"Codex 在主目录下运行的会话，非具体项目"）
3. 可以考虑在 `_project_name()` 里对 `cwd == "/Users/chat"` 的情况返回 `"主目录 (Codex)"` 而不是 `"chat"`

---

### 反馈 3：事件类型模块（最大分歧）

**用户要求：** 把"事件类型（月）"改成"本月用途"，分类为：**编程 / 图片视觉 / 文档表格 / 研究浏览 / 其他**。

**现状：** `aggregate.event_types` 字段在 `UsageAggregate` 中**不存在**，当前 UI 代码引用的是一个占位字段，实际会报错或返回空。这个模块在阶段 4 是未完成状态。

**设计决策（需与用户对齐，不能 Codex 自行拍板）：**

用途分类无法从 token 数字推断，有两个方向：

- **方案 A（路径推断）：** 根据 `cwd` 路径名自动映射。例如：
  - `product-detect` → 图片视觉
  - `aftersales-automation` → 编程
  - `codex-monitor` → 编程
  - `sku-calculator`、`transfer` → 编程
  - `douyin-workout` → 编程
  - `lkwj` → 编程
  - `/Users/chat`（chat）→ 研究浏览/其他
  - 其余 → 其他
  
  需要在配置里维护一张 `cwd 路径名 → 用途` 映射表。

- **方案 B（用户手动配置）：** 提供一个 `data/project-purpose.json` 让用户配置映射，UI 直接读取，无自动推断。

**建议：** 方案 A 先硬编码一版（基于你对用户项目的了解），用户确认后迁入配置文件。
