# 果实导入与收集列表布局设计

## 目标

避免把 Excel「果实进度」Sheet 的每一行都误读成果实，同时统一所有收集标签页的默认列表、排序和筛选布局。

## 已确认事实

- 历史确认版有 143 条有效果实。
- 当前 168 条由历史 143 条加 S3 新增 25 条组成，没有丢失历史有效记录。
- 当前 Excel 有 177 行候选记录，其中 7 行获取说明明确写“无果实”，迪莫说明为“唯一的迪莫”，学院呱呱说明为“获得蛋”；这 9 行不是果实，剩余 168 行有效。
- Excel 行表示家族范围，果实挂在该行确认的目标精灵上，但页面编号应展示完整家族范围。

## 方案比较

1. **推荐：导入时统一判定并保存家族范围**
   - Excel 读取层集中判断有效/无果实、获取类型和编号范围；同步与审计共用结果。
   - `pets.json` 的 fruit 保存家族起止编号，前端直接展示。
   - 优点：规则只有一份，未来 Excel 更新不会再次出现同步正确、审计错误或反过来的情况。

2. **前端临时排除异常行**
   - 保留所有 JSON 数据，页面隐藏迪莫等条目。
   - 缺点：错误数据仍存在，随机果实和统计仍会出错，不采用。

3. **前端根据进化链推算家族范围**
   - 不保存 Excel 范围，运行时从进化链猜测。
   - 缺点：分支进化和 Excel 家族口径可能不一致，不采用。

## Excel 果实判定

读取「果实进度」时按以下顺序判断：

1. D 列以“无果实”开头：无果实。
2. C 列属于历史确认的非果实来源：`传说精灵`、`特殊奇遇`、`开局必送`、`呱呱上学记`：无果实。
3. D 列只描述获得精灵或精灵蛋，而不是获得果实：无果实；当前明确反例是迪莫和学院呱呱。
4. 其余来源必须命中已确认的六类映射：课题任务、智慧树苗、剧情任务、通行证契约礼券、赛季作业、限时活动。
5. 出现未知来源时，导入和审计必须报错，不能默认归入“限时活动”。

经验同时写入 `docs/REVIEW_CHECKLIST.md`，并由校验脚本锁定迪莫、学院呱呱、有效总数、六类来源和家族范围。

## 页面布局

- 精灵相关列表按精灵编号升序；同一精灵的多个形态按稳定形态顺序。
- 果实按家族起始编号升序，行首显示家族范围，例如 `No.5-No.7 火神果实`。
- 家具、称号、遗迹、服装和通用品类按各自稳定 ID / 既定业务顺序。
- 状态为“全部”时，无论是否使用搜索、元素、来源或其他筛选，都显示一个连续列表，不拆成“未收集/已收集”。
- 状态选“未收集”或“已收集”时，只显示对应结果，也不增加重复分组标题。
- 所有标签页取消分页；异色炫彩一次展示全部匹配项。
- 精灵和异色炫彩的筛选区与明细区增加统一桌面间距。
- 当前只优化电脑端，不增加手机端专用布局。

## 验证

- 果实历史 143 条全部保留，S3 25 条全部存在，总数 168。
- 9 条非果实候选不会生成 fruit；未知来源会使同步/审计失败。
- 每条有效果实都有合法家族编号范围，火神为 `[5, 7]`。
- 所有精灵类列表显式按编号排序。
- 状态“全部”时不渲染收集状态分组标题；页面中不再渲染分页控件。
- 运行现有全部数据/UI 校验、Excel 审计和在线 API 检查。
