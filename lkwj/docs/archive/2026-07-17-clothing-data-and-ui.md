# 2026-07-17 服装数据与界面阶段归档

## 阶段目标

把服装从混合列表整理为可持续补录的套装/单品模型，并让页面在保持套装展开明细的同时，与其他收集标签页使用一致的顶部结构。

## 已完成的界面行为

- 服装页顶部统一为：标题 → 单行统计 → 搜索 → 筛选 → 规则说明 → 内容。
- 套装继续使用手动展开卡片，一次只展开一个套装。
- 套装部件集中连续显示，不在每个部件行重复套装获取方式。
- 套装和独立单品名称前分别显示类型标签。
- 未知获取方式使用 `待补充` 保存，但前端隐藏占位文本。
- 只有套装名称和总件数、尚无具体部件名称的套装也会显示，进度分母使用 `requiredPieceCount`。
- 付费组件显示为“付费 · 非收集目标”，不可勾选，也不进入完成率。
- 分类、套装/单品类型和收集状态筛选继续可用。

## 已确认的数据规则

- `requiredPieceCount` 以游戏内显示件数为准。
- 华丽魔法列出的非收集组件都是额外组件，不包含在解锁所需件数内。
- 所有付费额外组件通过积分卡解锁，只需要标记为非收集目标。
- 获取方式未知时先留空，不作为当前补录任务。
- 套装名称匹配且必需件数吻合后才允许自动归套装；近似名称不能直接合并。
- “追忆”和“回忆”可以是不同单品。
- 服装侧名称使用“魔草巫灵”；果实阶段名称不在本阶段处理。
- 异色套装统一使用“印象”后缀。
- `初始发型1` 至 `初始发型3`、`面妆1` 至 `面妆8` 就是正式名称，均为系统默认新手独立单品。

## 后续补录方式

随机商店只有刷新时才能看到具体部件名称。后续每次由用户提供：

1. 刷新出的部件完整名称。
2. 其中实际购买的部件。

维护时只追加真实看到的部件，不根据图片或套装总件数猜测部件位置；购买状态只在用户明确说明后更新。
