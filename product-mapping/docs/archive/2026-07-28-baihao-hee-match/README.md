## 重复编码与人工修正

本轮存在三组不同商品链接复用同一 platformCode。处理时保留每条
`productCode + platformCode` 记录、独立图片和独立识图结果，不按 platformCode 去重。

这一规则既防止链接被覆盖，也把重复编码变成完整性检查：图片与 ERP 明细不一致时，可以定位
错误绑定。已有匹配异常不由自动流程换绑；用户在平台把 `0409fs` 的错误编码人工改为
`260805-9` 后，脚本只迁移本地链接身份并重新回读，再把它作为普通未匹配项处理。

## 固化的防护

- `sku-records.json` 使用 `productCode::platformCode`；图片使用
  `{productCode}__{platformCode}.jpg`。
- 匹配日志、活动范围和后置核对都按复合链接身份处理。
- 档案查询精确验证返回编码，子品弹窗空明细重试一次。
- “套件处理”通过触发按钮的 `aria-controls` 精确绑定菜单，兼容后台标签页菜单高度为 0。
- 点确定后轮询“选择商品关闭”或“换对应商品出现”，避免固定等待 2 秒造成假失败。
- 重复 platformCode 写识图时必须指定 productCode，避免一条结论覆盖多个链接。
