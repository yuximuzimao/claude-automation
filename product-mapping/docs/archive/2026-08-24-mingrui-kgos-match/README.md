## 三层身份与串图修复

本轮同时出现多个商品链接复用 `260827-27/28/29`。正确身份分三层：

1. 商品链接：`productCode`
2. 链接下 SKU：`platformCode`
3. SKU 当前绑定：`erpCode`

图片只由前两层定位。2026-07-28 的复合身份改造已经覆盖记录键、文件名、报告和
识图，但漏掉 `lib/correspondence.js` 上游 `imgMap`，它仍只按 `platformCode`
缓存 URL，导致不同链接可能保存同一张图。本轮修正为
`productCode::platformCode → imgUrl`，并实测 75 个对应表产品、205 个 SKU 得到
205 张链接级图片；新增回归测试验证两个链接复用同一规格编码时仍保留不同图片。

## 本轮修正

| 现象 | 根因 | 修正 |
|---|---|---|
| 重复 platformCode 的不同链接串图 | 上游图片 URL 仍按单字段缓存 | 图片 URL、运行态和文件名统一使用复合身份 |
| 对应表偶发读到 0 条 | 全局选择器先命中隐藏套件表 | 所有主表读取限定 `.prod-correspondence-table` |
| `商品×3` 被归为单品 | 识图类型按商品种类数判断 | 仅总数量为 1 才是单品 |
| 首个套件报 10 秒超时但稍后保存成功 | ERP 保存超过旧确认窗口 | 确认轮询延长到 30 秒；先回读再续跑 |
| 下载首次出现 0 店铺 / 旧进度层 | 页面残留状态与诊断修改叠加 | 下载逻辑恢复原版；干净页面实测确认后 29 秒完成 |

首个 `0827zp7` 虽被旧门限记为失败，但 ERP 随后生成正确档案；回读三个子品
和数量无误后，本轮先运行 check 回填，再从剩余 55 个继续，最终没有重复写入。
