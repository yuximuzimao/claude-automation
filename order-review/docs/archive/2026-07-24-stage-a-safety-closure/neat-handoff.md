## 2. 完成范围

### 2.1 单实例与并发写入

- 审单悬浮窗使用跨进程单实例锁。
- 第二实例启动时返回退出码 2，不允许形成两个独立审单进程。
- 案例仓库的完整“读取 → 计算 → 校验 → 备份 → 原子替换 → 写后校验”事务持有跨进程文件锁。
- 单实例是第一道保护，案例仓库写锁是第二道保护；即使未来出现其他写入入口，也不能用旧状态静默覆盖新状态。

### 2.2 案例写入、校验与失败回滚

- 写入前先验证待写 payload。
- 覆盖正式案例前，只对当前可读取且通过健康检查的文件创建有效备份。
- 正式文件通过同目录临时文件、`fsync` 和 `os.replace` 原子替换。
- 写后再次执行统一健康检查。
- 写后校验失败时：
  - 错误产物隔离为 `cases.write-failed-时间戳.json`。
  - 如存在有效旧备份，自动恢复写入前版本。
  - 恢复失败时保留有效备份路径并明确报错，不能静默继续。

### 2.3 多版本备份与人工恢复

- 应用内有效案例备份默认保留 30 份。
- 备份目录：

```text
~/Library/Application Support/Order Review/backups/
```

- 人工恢复必须明确指定来源并提供 `--yes`。
- 应用启动时绝不静默自动回滚。
- 恢复时必须先取得目标案例对应的单实例锁；悬浮窗仍在运行时拒绝恢复。
- 当前正式案例有效时，恢复前创建 `pre-restore-*` 恢复点。
- 当前正式案例损坏时，原始字节先移动为 `cases.corrupt-*`，再恢复有效备份。
- 恢复后的正式文件必须重新通过健康检查。
- 恢复失败产物隔离为 `cases.restore-failed-*`，故障文件和恢复来源均保留。

### 2.4 有效备份统一排序

`case_restore --list` 与工作区降级归档共用 `list_valid_backups()`，不维护两套排序逻辑。

排序规则：

1. `cases-*`、`pre-restore-*` 及其他前缀统一进入候选集合。
2. 先逐个执行案例健康检查，无效文件不参与排序。
3. 文件名尾部包含合法 UTC 时间戳时，按该真实时间排序。
4. 没有合法时间戳时，回退到文件修改时间。
5. 时间相同时再使用修改时间和文件名保证结果确定。

这修复了旧逻辑中“较老的 `pre-restore-*` 因字母顺序被错误视作最新”的问题。

### 2.6 统一案例健康检查

只读命令：

```bash
PYTHONPATH=src python3.13 -m order_review.case_audit
```

校验覆盖：

- JSON 与 schema。
- 包裹商品引用、数量守恒、空包裹、负数、超分配和漏分配。
- 重复 case ID、assignment ID。
- `previousCaseId`、`previousAssignmentId` 版本链断裂、跨订单、版本跳号和循环。
- assignment 指向不存在的案例。
- 同一订单重复最新版本造成的歧义。
- `ruleStats` 结构、计数与孤立统计。
- 商品身份和可靠平台订单身份缺失警告。

错误会阻止写入、正式备份和回放；警告用于数据质量提示。合法的同订单版本和方案分支不得被误判为重复损坏。

### 2.7 推荐事件 best-effort 隔离

事件类型：

- `shown`
- `confirmed_direct`
- `confirmed_modified`
- `abandoned_unknown`

长期约束：

- `abandoned_unknown` 只表示没有得到确认结果，不能作为拒绝或负反馈。
- 同会话按订单签名和推荐 ID 去重。
- 事件写入、读取或初始化失败只记录 warning。
- 事件文件故障不能影响：
  - 案例或 assignment 保存结果。
  - 草稿清理。
  - 刷新和切换订单。
  - 人工创建方案。
  - 关闭窗口。
- 核心案例已经落盘时，界面必须按成功处理，不能因辅助遥测失败显示为确认失败。

推荐事件只读检查：

```bash
PYTHONPATH=src python3.13 -m order_review.recommendation_event_audit
```

坏行会报告行号和原因；离线统计只读取有效行，不阻断案例主流程。

### 2.8 无数据泄漏的历史回放

命令：

```bash
PYTHONPATH=src python3.13 -m order_review.case_replay
```

历史表现：

- 每个订单使用首次确认方案作为测试目标。
- 只允许使用目标确认时间之前的其他订单案例。
- 排除同订单版本链，避免自我验证。
- 同订单 assignment 和规则采用关系不虚增完整案例多样性。

当前成熟度：

- 使用每个订单最新 `orderVersion`。
- 统计当前最终单包/多包分布、数量档位、单包到多包临界组合和同结构多分支。

报告区分：

- 有无推荐。
- 唯一候选与实际方案完全一致。
- 候选集合是否包含实际方案。
- 推荐冲突。
- 有推荐但所有候选都不符合实际方案。
- 各匹配类型覆盖率和实际方案命中率。
