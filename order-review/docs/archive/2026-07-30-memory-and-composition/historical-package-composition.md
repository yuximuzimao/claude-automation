# 历史包裹模块精确组合

状态：第一版已实现并通过离线回放；后续规则已修订

> 唯一且无冲突的精确组合可直接进入可编辑草稿和拆分入口，仍不自动确认或执行

## 1. 用户要解决的问题

当前推荐主要匹配“整单历史结构”。如果一个新订单同时包含两个已经分别反复
确认过的标准包裹，例如“酵素 18”和“咖啡 7 盒”，系统仍不会把两个历史包裹
组合成新方案。

第一版目标是把人工确认过的单个包裹当作不可缩放的模块，对未见过的整单做逐
商品精确覆盖。用户看到的是一份可解释、可编辑的本地草稿，不是系统自行判断
纸箱容量。

## 2. 固定安全边界

- 只读取当前有效、非物流案例中的已确认包裹；同一模块至少需要来自 3 个独立
  有效案例，并且至少有 1 次来自多包订单中的明确包裹边界，避免把一次性拆法
  或“曾经单独发过”误当成组合时必须分开的标准包裹。
- 每个历史包裹的商品身份与数量原样复用；允许根本规则第 3.4 节的等体积口味
  白名单映射，其他商品不得替换。
- 当前每种商品的全部数量必须由同一个历史模块一次完整覆盖，不允许把同一商品
  拆给多个小模块后拼出更大数量。
- 组合后必须逐商品精确等于当前订单，不允许余量、超量、比例缩放或容量推算。
- 优先最少包裹数，第一版最多 5 包。
- 多种最少包裹方案并存时全部作为冲突候选，不静默选择。
- 唯一组合候选也不自动采用；人工采用后进入现有包裹编辑器。
- 直接确认组合候选时保存当前订单的新完整案例，因为它是新的复杂组合证据。
- 推荐层不执行 ERP；后续拆分并审核仍必须由用户针对当前订单单独点击。
- 第 3 项连续 20 单验收延期但不取消；完成前不提高自动化权限。

## 3. 搜索与排序

1. 从当前有效案例的每个已确认包裹提取规范化模块，并合并相同模块的来源证据；
   少于 3 个独立案例、或从未在多包订单中形成独立边界的模块不进入搜索。
2. 删除包含当前订单不存在商品，或不能一次完整覆盖其所含商品当前总量的模块。
3. 在最多 5 个包裹内搜索无余量的精确覆盖。
4. 只保留包裹数最少的解。
5. 同包裹数的不同拆法按历史证据数和稳定键排序展示，但仍标记冲突。
6. 搜索设置状态和候选上限，超过边界时不猜测、不生成不完整方案。

## 4. 推荐优先级

固定顺序：

1. 同一订单历史恢复。
2. 子订单结构精确匹配。
3. 商品总量相同的历史单包方案。
4. 历史包裹模块精确组合。
5. 单包容量内人工参考。
6. 人工创建方案。

## 5. 验收

- 两个未曾作为整单共同出现、但各自存在历史包裹证据的模块可以组合成精确草稿。
- 缺少任一数量、需要缩放模块或超过 5 包时不推荐。
- 多种最少包裹拆法显示冲突。
- 等体积口味只映射包裹规划身份，草稿仍引用当前订单真实商品。
- 组合候选不会自动采用；直接确认后新增完整案例并记录推荐来源。
- 离线回放单独统计该匹配类型的覆盖与实际方案命中率。
- 完整测试、案例健康检查和推荐事件检查通过。

## 6. 第一版实现结果

当前 271 条完整案例折叠为 264 个有效非物流订单，共包含 332 个已确认包裹
实例、192 种包裹模块。算法只使用每个订单最新方案版本，排除物流和被后续版本
替代的旧拆法。

真实商品身份模拟“酵素4.0 ×18 + 拿铁（新）×7”时，得到唯一候选：

```text
包裹 1：酵素4.0 ×18
包裹 2：拿铁（新）×7
```

两个模块分别有 5 次和 7 次历史包裹证据，至少各有一次来自多包订单边界。
算法未使用容量、比例或剩余量推算。

离线无泄漏回放结果：

- 组合推荐覆盖：`1 / 264`。
- 组合候选包含人工实际方案：`1 / 1`，命中率 `100%`。
- 全部推荐覆盖：`102 / 264`。
- 全部推荐错误：`1`，来自既有 `single_package_capacity`，不是组合算法。

同一进程连续计算上述真实组合 20 次：

- 第 1 次 RSS：`225,580 KiB`。
- 第 20 次 RSS：`226,012 KiB`。
- 增加约 `0.42 MiB`，没有随计算次数线性增长。

验证结果：

- 完整测试：`201 passed`。
- 正式案例健康：271 案例、684 订单索引、135 规则统计，错误和警告均为 0。
- 推荐事件健康：942 条有效记录、0 条坏行。

完成验证后已重启正式悬浮窗加载第一版组合算法：旧 PID `64251` 已退出，新
PID `65937` 已启动。重启未操作浏览器、ERP 或正式案例数据。

第 3 项连续 20 个合适真实订单验收仍保留。第一版组合推荐虽然已经可以显示和
采用，但在该验收完成前继续维持“人工采用、本地确认、逐单点击 ERP 执行”的
权限边界。
