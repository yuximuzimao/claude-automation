# 物流独立标记与单件默认草稿 — neat 归档

日期：2026-07-27  
状态：已完成并归档  
项目：`order-review`

## 1. 阶段边界

本阶段解决两个高频人工判断问题：

1. 大单即使在 ERP 中暂不拆单，也可能实际形成多个快递包裹并改用物流，不能继续保存成普通“单包”案例。
2. 总商品数量为 1 且非套件时，不需要人工重复点击“单包方案”，可以直接生成待确认草稿。

本阶段只写本地案例和界面状态，没有审核、拆单、发货或修改 ERP。

## 2. 已完成能力

### 2.1 物流成为独立运输决策

- `Decision.shippingMode` 区分 `parcel` 与 `freight`。
- 物流案例保留完整原订单快照和数量守恒兼容方案。
- 物流案例不参与精确包裹方案、单包总量或单包容量推荐。
- 同一订单再次读取时恢复“已确认物流”，不会伪装成物理单包。
- 历史相同商品总量曾选择物流时，只显示人工复核提醒，不自动确认。
- 物流订单不进入普通单包 ERP 审核 v1。

### 2.2 提醒只表达证据，不假装估算

- 总件数达到 70 时显示“建议复核物流”。
- 系统明确说明：只按总件数和历史案例提醒，不估算包裹数。
- 包裹数、原箱、重量和商品组合仍由人工判断。
- 人工估计达到约 5～6 个快递包裹以上、重货多箱或复杂混合大单时，可以选择“物流发货”。
- 已保存案例中存在人工包裹区间时，界面标为“人工估计”，不再使用含义不清的“快递粗估”。

### 2.3 单件非套件默认草稿

- 订单总商品数量恰好为 1 且不是套件时，读取后直接生成普通单包草稿。
- 草稿仍需人工确认才会保存。
- 套件阻断保持不变。
- 默认草稿不触发任何 ERP 操作。

## 3. 案例迁移与真实使用

首批三条此前误存在普通单包集合中的物流案例已迁移：

- 121 件：人工估计 7+ 个快递包裹。
- 97 件：人工估计 6+ 个快递包裹，包含重货原因。
- 85 件：人工估计 5～6+ 个快递包裹，包含复杂混合原因。

迁移只修改这 3 个案例及其 3 条订单关联，写入前后均经过锁、有效备份和统一健康检查。

随后用户通过新入口保存了 239 件物流案例。该案例记录 `high_quantity` 与 `complex_mix` 作为提醒证据，没有虚构系统包裹数。
