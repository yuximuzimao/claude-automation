## 1. 阶段结果

本阶段完成了人工连续审单所需的单包闭环：

- 默认手动刷新，应用启动不会点击或展开 ERP 订单。
- 用户可主动开启或停止自动刷新；自动模式只负责等待新订单稳定并最多展开一次，不会自动审核。
- 可靠的历史单包方案可直接显示“修改方案”和“审核当前订单”，减少重复确认步骤。
- 用户每次点击“审核当前订单”只授权当前订单执行一次普通审核。
- 执行前、勾选后、菜单打开前、弹窗提交前和提交后分别重新读取页面事实。
- “确定”最多点击一次；结果无法证明时进入 unknown，绝不自动重试。
- 单包流程中底部计数只作反向保护：`2+` 阻断，`0/1` 不作正向证明。
- 审核成功后不依赖固定等待：每 `500ms` 探测一次，新订单号连续两次一致且稳定至少 `0.5` 秒，页面无勾选、弹窗或加载状态后才读取，并在展开前再次核对预期订单号。

该能力只适用于已经确认的普通单包订单。物流、拆分订单、强制审核、右键审核、套件转换、合单和批量操作均未开放。

## 2. 等体积口味白名单

用户确认以下六个包装规格组可双向复用拆包方案：

| 规格组 | 商家编码与商品 |
|---|---|
| 咖啡正装 | `6977987940138` 美式咖啡（绿） ↔ `6979151090014` 生椰拿铁（新包装） |
| 咖啡体验装 | `6979499760068` 美式咖啡（绿）体验装 ↔ `6978430740022` 生椰拿铁体验装 |
| 黑茶正装 | `6979499760044` 茉莉味 ↔ `6979265440002` 普洱味 |
| 黑茶体验装 | `6979499760099` 茉莉味体验装 ↔ `6979265440019` 普洱味体验装 |
| 蛋白粉正装 | `6977987940046` 牛油果猕猴桃味 ↔ `6977987940039` 莓果味 |
| 蛋白粉体验装 | `6977987940107` 牛油果猕猴桃味三袋体验装 ↔ `6977987940084` 莓果味三袋体验装 |

实现边界：

- 白名单只改变包裹方案推荐的匹配身份。
- 同一订单识别、原商品身份、案例快照、界面商品名和 ERP 审核核对仍使用真实口味。
- 正装与体验装不互换，不同品类不互换，未知编码不按名称猜测。
- 推荐应用后使用当前订单的 `sourceProductId`、名称和数量，不复制历史口味引用。
- 精确结构和单包总量推荐算法升级为 `v2`；单包容量推荐升级为 `v3`。

## 3. 关键代码

- `src/order_review/package_equivalence.py`：六个规格组的唯一白名单。
- `src/order_review/package_plan.py`：分开真实商品身份与包裹规划身份。
- `src/order_review/order_identity.py`：保留订单身份签名，新增包裹规划签名。
- `src/order_review/recommendations.py`：按包裹规划身份匹配、投影并重新映射当前商品。
- `src/order_review/case_replay.py`：按同一包裹语义评估推荐方案。
- `src/order_review/audit_runner.py`、`src/order_review/ui.py`：单包审核保护链路与双模式刷新交互。

## 4. 验证

最终全量回归：

```text

```

等体积白名单测试覆盖：

- 六个规格组全部双向复用多包方案。
- 生成方案只引用当前订单商品。
- 正装与体验装不串用。
- 未登记口味不猜测。
- 同一订单和真实商品身份仍区分口味。
- 等体积口味可复用更小数量的已确认单包容量。

macOS Tk 测试继续在同一测试进程只创建一个根窗口。ERP 写动作搜索和最终静态检查以当前代码为准；本次白名单实现与归档过程中没有点击、勾选或提交任何 ERP 订单。

真实单订单审核日志共 `105` 次：`99` 次成功，`6` 次由安全关卡停止，没有 `failed` 或 `unknown`。用户经过多次实际使用后确认暂未发现问题，单包普通审核据此进入稳定基线。

回放最初把同一包裹里的等体积口味分行与合并数量误判为不同方案，现已统一先按包裹规划身份汇总。剩余 1 个不一致已确认不是订单或人工方案错误：酵素4.0 `18` 盒可用约 `20` 盒箱单包，`9` 盒却因没有合适箱型而需拆成 `6 + 3`。这证明离散纸箱规格下装箱能力并非随数量单调；容量候选仍需人工采用，没有自动审核风险。

## 6. 后续边界

下一阶段方向已明确为：单独采集拆分前后页面事实，为拆分订单建立只读识别和 dry-run 方案；在真实样本稳定前不开放拆分写操作。商品与纸箱尺寸模型安排在拆分实际功能完成后再独立设计，第一版允许商品旋转、侧放和叠放，暂不考虑重量、纸箱承重或缓冲空间，空隙比例待实际样本确定。

不得把单包审核的“唯一选中一行、弹窗数量 1、底部 `2+` 阻断”直接套用于拆分订单。拆分可能合法产生多条结果订单，必须按本地多包方案重新定义身份、数量和成功证据。
