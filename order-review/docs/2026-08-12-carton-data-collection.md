# 纸箱与商品尺寸数据采集清单

## 目标

这批数据用于判断“哪些商品能放进哪个实际可用纸箱”，进而比较包裹数，而不是
建立一套看起来精确、实际无法落地的理论体积模型。数据可以分批提供；精确值、
估算值和未知值必须分开标记。

用户可以直接提供 Excel、CSV、照片、现有台账或文字记录。下一会话先整理和审计，
不要求用户预先转换成程序格式。

## 第一优先级

### 1. 纸箱

每种实际可用箱型尽量记录：

| 字段 | 要求 |
|---|---|
| 箱型编号或常用名称 | 能稳定区分不同纸箱即可 |
| 内长、内宽、内高 | 推荐毫米；优先量可实际使用的内部空间 |
| 尺寸类型 | `内尺寸`、`外尺寸` 或 `未知`；外尺寸不能直接当内尺寸计算 |
| 是否仍在使用 | 停用箱型不能作为线上候选 |
| 备注 | 折边、内衬、明显不可用空间等实际限制 |

只有外尺寸也可以先交付，但必须保留“外尺寸”标签，后续不能静默扣减成猜测的
内尺寸。

### 2. 商品

按最终发货时的单件包装记录，不量裸产品：

| 字段 | 要求 |
|---|---|
| 商家编码 | 优先使用 ERP 稳定编码 |
| 商品标准名称 | 便于人工核对 |
| 包装长、宽、高 | 推荐毫米，包含外盒、袋装鼓起等实际占用 |
| 尺寸精度 | `实测`、`供应商数据`、`估算` 或 `未知` |
| 摆放限制 | 可自由旋转、可侧放、必须直立、不可叠压或未知 |
| 备注 | 易压、形状不规则、多件会嵌套等情况 |

同名商品如果包装规格不同，必须拆成不同记录；口味相同体积白名单仍只按项目
根本规则使用，不能因为名字相近自动合并。

## 同样有价值的不完整证据

### 3. 已知装箱案例

即使不知道纸箱，也请记录真实发生过的组合：

- 包含哪些商品、各多少件。
- 结果是确定能装、确定不能装，还是只知道最终用了几个包裹。
- 如果知道箱型就填写；不知道则明确写“箱型未知”。
- 证据来源标记为实际打包、人工经验、历史系统记录或估算。

“确定能装但箱型未知”可以证明组合可行，不能证明任何一个已知箱型可行；算法
必须保留这层区别。

### 4. 大概容量

例如“这个箱大约放 6～7 盒”“20 盒箱通常能装 18 盒”都可以记录：

- 对应箱型（不知道可留空）。
- 商品或商品组合。
- 大概数量或范围。
- 是实际装过、长期经验还是目测估计。

这类数据用于缩小候选和安排人工复核，不直接当作绝对容量上限。

## 推荐表格结构

如果准备 Excel，四张表最清楚：

1. `纸箱`：箱型编号、名称、长、宽、高、尺寸类型、是否在用、备注。
2. `商品`：商家编码、名称、长、宽、高、尺寸精度、摆放限制、备注。
3. `装箱案例`：案例编号、箱型编号（可空）、结果、证据来源、备注。
4. `案例商品`：案例编号、商家编码、数量。

案例商品单独成表，可以表达一个箱子里混装多种商品，不需要把组合塞进一个单元格。

## 第一版可以暂缺

- 商品重量和整箱重量。
- 纸箱承重。
- 缓冲材料的精确厚度。
- 纸箱成本和快递计费体积。
- 所有商品、所有箱型一次性全覆盖。

这些字段以后可以扩展，但当前不应阻塞尺寸模型与算法可行性判断。第一轮更重要的
是确认：内尺寸是否可信、商品包装尺寸覆盖多少真实订单、旋转限制是否明确，以及
未知箱型的历史可行证据能覆盖哪些组合。
