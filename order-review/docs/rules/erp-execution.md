# ERP 执行与读取关卡

适用于普通审核、混合拆分、自动刷新及其测试。最小安全红线见项目 `AGENTS.md`，
业务方案语义见[根本规则](../2026-07-23-package-rule-foundation.md)。本文件保存执行
关卡、身份核对和等待时序，不表示真实业务已对所有场景验收。

普通单包审核仍按原关卡执行。混合拆分当前临时收窄为：审核前检查当前订单与方案 → 勾选唯一目标订单 → 打开混合拆分 → 按原订单行序填写各包数量 → 核对倒数第二包和最终剩余包 → 点击主“确定” → 核对并点击二次确认 → 立即停止。授权仍只来自用户对当前订单的单次点击。

点击拆分二次确认后，浮窗不安装或读取拆分网络结果观测器，不读取结果行，不做逐包明细核验，不滚动结果列表，不打开普通审核菜单，不点击审核子菜单或审核确定，也不自动刷新下一单。界面明确提示用户回到ERP人工核对，并阻止当前订单从浮窗重复提交拆分。

装箱规划的优先级与品牌/箱型限制见根本规则；是否已接入线上以CURRENT为准。

混合拆分弹窗添加包裹后，ERP 会让已经分完的商品行保留本次填写数量并禁用输入框；只有仍有剩余量的行才恢复为 `0` 且保持可编辑。确认前验证必须按“剩余量 + 禁用状态”联合判断，不能要求所有输入框都恢复为 `0`。填写、添加包裹和两级确认之间保留 `300ms` 人工可见停顿，状态轮询间隔仍为 `100ms`。

混合拆分目标为 N 个包裹时，只把前 N-2 个包裹逐个加入“待拆分”；倒数第二包填写数量后不点“添加待拆分”，直接点“确定”，由 ERP 同时确认当前数量并把最终剩余量生成最后一包。确认前必须证明当前填写量等于倒数第二包，且扣除后剩余量精确等于最后一包。

## 暂停的后半段

网络响应判定、1→N结果行单向核验、虚拟列表滚动、审核菜单、审核弹窗与提交后结果确认均已停用。旧实现和历史测试只能作为后续重构参考，不能代表当前可执行能力。恢复时必须重新设计确认点击后的状态模型、人工可见停点、幂等边界和真实订单验收；不得仅删除当前停止点重新启用旧链路。
