- 装箱实验页面、只读服务层、HTTP入口和静态前端位于主干。固定地址为 `http://127.0.0.1:3466/`，只从 `/Users/chat/claude/order-review` 的 main 启动；`/api/catalog` 的 `dimensionCatalogPath` 应指向 main 的 `data/packing-dimensions.json`。历史worktree不作为回退来源。
- 实验服务按用户要求保持停止；需要实验时再从项目启动器手动启动，不与浮窗联动或长期托管。服务只允许绑定回环地址，不连接ERP/CDP，不写正式案例。
- 页面保留“装箱实验 / 包装资料”两个入口。KGOS当前开放单箱实验；悦希当前只展示资料，不自动开放装箱计算。手动指定纸箱失败时不能偷偷换箱；自动模式先评估同品牌普通候选纸箱，没有确定解时再评估满足单一商品/数量边界且尺寸已知的产品原箱。
- 产品原箱只在当前实际占空间商品为单一品种、原箱允许该商品、数量落在已确认范围时属于适用候选；尺寸已知时可进入手动下拉和自动兜底计算。适用原箱若缺尺寸，自动结果保持 `UNKNOWN` 并列出缺尺寸原箱，不能把普通箱失败升级成“单箱装不下”。
- 历史订单只读正式案例库并折叠到同订单最新有效版本。人工保存的原方案只在算法完成后作为只读对照，不给求解器提示答案，也不改写 `cases.json`。
- 页面与正式浮窗保持运行隔离；正式审单浮窗尚未接入装箱实验服务。页面当前用作单箱内核的人工3D复核入口。

- 普通单包审核按现役[执行关卡](rules/erp-execution.md)运行，真实ERP操作仍遵守[AGENTS](../AGENTS.md)的当前订单授权边界。
- 历史包裹方案按ERP商家编码识别实际商品；普通/秒杀等平台链接以及平台SKU、规格和活动名称变化不拆散同一商品的历史方案。平台字段继续保留在原订单快照与ERP执行核对中，不因推荐匹配放宽执行安全检查。
- 多包按钮为“拆分当前订单”。执行只到填写数量、点击主确定、核对并点击拆分二次确认为止，随后立即停止。
- 拆分确认后的网络结果读取、逐包明细核验、结果列表滚动、普通审核菜单、审核弹窗与审核提交全部停用；自动刷新同时关闭。用户需回到ERP人工核对，浮窗会阻止当前订单重复提交。
- 后半段重构与真实订单验收只见 `tasks/todo.md`，不得通过移除停止点直接恢复旧链路。
- 批量活动自动化尚未实现完整SPU/SKU活动清单、逐环节批量脚本或浮窗接入；套件转单品、批量拆分、批量审核和赠品转异常均未开放。

## 算法当前状态

- 当前单箱内核版本为 `single-carton-geometry-stability-split-v3`，已支持物件顺序搜索、确定性排序、等价类/旋转去重和共享deadline。
- 几何有效性与稳定性已拆层：边界/碰撞是硬条件；离地物件至少需要实际承重点；完整底面支撑是独立指标。求解器优先完整支撑方案，当前预算内没有时可返回部分支撑方案，并报告最低底面支撑覆盖率供3D人工复核。
- 候选点采用混合frontier / Extreme-Point风格，保留表面坐标笛卡尔组合兜底和同类物件规则网格fast path。自动选箱按剩余候选公平分配节点预算。
- `pack_order()` 1～N箱外层仍未实现，只保留为[可选技术研究](2026-09-12-packing-algorithm-research.md)，未排为默认下一任务。装箱用于按需验证，不统一以包裹数最少代替发货判断；历史答案不参与几何盲测，`UNKNOWN`不解释为装不下。
