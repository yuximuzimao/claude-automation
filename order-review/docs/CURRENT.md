## 待办：优化“保存方案”的界面等待

- 现象：在审单悬浮窗点击“保存方案”后，界面会等待数秒才显示成功。
- 当前原因：`ui._confirm_package_plan()` 在 Tk 主线程内同步调用 `PackagePlanWorkflow.confirm()`。新案例写入需依次完成文件锁、整份状态流式序列化与 `fsync`、写前隔离进程校验、有效旧版备份、原子替换、写后隔离进程校验和未使用内存回收；这些安全步骤全部阻塞 UI 事件循环。
- 下次先做分阶段耗时记录（等锁、序列化/`fsync`、写前校验、备份、写后校验、内存回收），用真实案例文件确认主要耗时，不凭感觉删减安全门禁。
- 目标方案：把完整的 repository `confirm` 持久化移到单一后台 worker；Tk 主线程立即显示“正在保存…”并禁用重复保存、刷新和修改当前草稿。后台完成后只通过 Tk 主线程回写成功/失败状态；成功前不得清空草稿或显示“已保存”，失败时必须保留草稿以便人工重试。
- 安全边界：保留现有跨进程锁、写前/写后校验、有效备份、原子替换和失败回滚；不为提速把校验改成 best-effort。保存中关闭窗口、切换订单和连续点击必须有明确且可测试的单次任务语义。
- 验收：保存期间悬浮窗仍能绘制“正在保存…”状态；双击只产生一条案例；成功后独立读回验证；写入/校验失败保留草稿且不损坏原案例；测试前后零新增 pytest、Tk 窗口和 worker 线程残留。

## 下一阶段：把尺寸计算接到推荐兜底

线上调用顺序已经确定，不能调整成每单都计算：

1. 同一订单保存方案、唯一无冲突精确历史、相同总量单包、唯一历史包裹模块精确
   组合、固定业务规则或确认箱规命中时，直接复用，不运行三维计算。
2. 精确规则存在冲突时交给人工，不用尺寸计算替某个分支背书。
3. 只有没有可靠结果的新组合才运行三维求解；`single_package_capacity` 等近似
   容量可以显示为参考，但不能阻断更可靠的尺寸结果。
4. 新组合先判断整单一箱；确需拆分时先保持平台子订单完整，再只拆无法整体安排的
   子订单。同包裹数下减少被拆子订单、跨包片段和交叉混装片段。
5. 尺寸不足、搜索超限或没有同品牌可用纸箱时保持人工处理，不输出虚假的确定方案。
6. 尺寸推荐只生成本地可解释候选，必须带箱型、摆放证据和规则来源；不得自动保存、
   拆单、审核或执行其他 ERP 写操作。

实现前先确定线上候选数据结构、搜索耗时上限和缓存方式，再用现有回放问题集比较
覆盖率、错误率、包裹数和耗时。不要重新扩展多包比例投影、容量单调性或按历史次数
静默排序。

## 2026-09-08：独立实验模拟页面与包装资料

状态：用户已明确实验性质、页面能力及本节业务要求；模拟器尚未开发，未接入浮窗
或正式推荐。正式集成前先在独立页面验证，同一份底层逻辑以后供浮窗调用。

### 页面范围

- **装箱实验**：查看原订单、人工分包和算法候选；既支持自动找箱，也允许用户从
  完整箱型目录手动指定同品牌纸箱，对当前订单/某包尝试摆放或分箱。指定后结果
  必须确实使用该箱型，不能悄悄换成推荐箱；固定用途不适用时解释原因。
- **立体展示**：使用真实求解坐标展示可旋转箱体、逐层布局和商品明细对应关系；
  纯容量规则支持但无尺寸/坐标时只显示组合示意，不能伪造几何证明。
- **包装资料**：按品牌展示全部普通箱、专用箱、停用箱与待补箱，显示箱型数、
  原始外径和计算内径、商品塑封外盒尺寸及取整值、产品原箱容量/尺寸、礼盒活动
  组合、缺失资料、证据级别。不能用算法候选过滤器代替完整资料目录。
- 用户可逐项补充/修正实验资料；确认事实、估计和待测结果分开保存。调整资料
  后结果按新版本重新计算，旧结果保留版本说明，不能伪装成仍按最新资料有效。

### 计算与回放边界

- 保存案例只读加载；历史验证分为“按人工分包检查每包”和“隐藏目标答案后重新
  规划”。同订单版本、等价组合及目标自身不得泄漏；固定规则解释与几何计算
  分开统计。不同但人工认可的方案可以有效，缺资料/未知不得算通过。
- 礼盒先按活动确认组合投影为实际入箱的礼盒和礼袋，已装入礼盒的内部商品不再
  重复计体积；原始明细及数量必须完整可追溯。该投影能力尚待实现。
- 模拟器与未来浮窗共用业务限制、候选生成和独立校验；界面不另算一份摆放。
  用户反馈仅保存实验记录，不能自动修改正式案例或触发ERP；现役套件阻断不变。
- 全部历史通过不等于新订单可靠，保留未参与调参的组合和真实新订单检验；同时
  关注几何/规则误放行、数量守恒、整单耗时及超限未知。多个可行拆法保留比较。
