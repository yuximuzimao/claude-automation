## 装箱实验当前阶段

- [装箱实验计划](2026-09-08-packing-simulator-plan.md)仍是活跃执行材料；P1前端基础结构已由用户确认“目前基本就这样”，本阶段不再继续扩页面，包装规则展示和自由旋转暂缓。
- 新入口为 `packing_simulator_web.py`：本地服务只绑定回环地址，不连接ERP/CDP，不写正式案例；包装资料、历史订单和实验结果均为只读或实验副本。
- 装箱实验是纯算法验证层：不读取固定箱量、固定拆箱答案或历史人工方案给算法提示答案。左侧用品牌按钮、搜索添加商品和滚动商品列表；右侧统一纸箱选择与模拟结果。当前仍只有单箱求解能力，页面不再反向限定算法。
- 纸箱下拉除普通候选箱外，现支持产品原箱：只有当前实际占空间商品为单一品种、原箱明确允许该商品、数量落在已确认可发范围且原箱尺寸已知时才显示；显示即允许手动指定并进入几何模拟。缺尺寸的原箱继续只在资料页显示“待补”，不会出现在算法下拉框；自动模式仍只搜索普通单箱候选，不自动采用原箱规则答案。
- 包装资料保留“包装纸箱 / 单品尺寸 / 包装规则”三个入口。包装纸箱与单品尺寸在桌面端按品牌双列展示（左KGOS、右悦希）；卡片宽度已扩展，单品收起状态统一高度，简称与小字全称同行、编码/尺寸分两行，详情在当前卡片下展开原始数据。纸箱标签保持“待补尺寸”在前、“产品原箱”在固定最右位置。商品范围仍由 `product-mapping` 的 features/pending/当前单品记录决定；`product-mapping/data/products/erp-identities.json` 保存 ERP 商品档案当前200条只读身份快照，只负责补正式简称/编码，不代表当前在售目录。审单装箱现役品牌只保留 KGOS 与悦希，KOKO/RITEKOKO、希凝、钥黑从现役目录和实验历史入口排除；历史事实文件不做破坏性改写。
- 下一步不继续在现有简化单箱求解器上直接叠多箱逻辑，而是先研究完整1～N箱算法：追溯原理论/已验证算法、论文与成熟/GitHub实现，先解释原算法完整机制和适用场景，再明确哪些部分直接借、哪些按我们的多SKU/多数量/合单场景改造。禁止先删掉核心机制再拼一个看似可用的简化版。
- 当前求解器本轮未修：现有搜索仍固定增量放置并把完整底面支撑当硬条件。用户已明确完整支撑不应作为普遍几何硬约束；几何可行性与运输稳定性/摆放偏好需要后续拆层，UNKNOWN继续不得解释为装不下。

## 当前可用能力及实测边界

- 原订单只读展示、本地方案、精确历史复用、历史包裹模块组合、用户单次触发的单包审核和混合拆分并审核可用。
- 模块重复次数限于同一历史案例已有证据；不把尾包复制成新规则，不记录确定性采用次数。
- 拆分结果已按1→N单向核验；只有短两包路径有用户实测确认，3个以上滚动/虚拟卸载仍待复验。
- 保存方案仍在Tk主线程同步执行持久化，存在数秒等待；后台保存是待办，不是已完成能力。
- 现有案例校验、版本链、备份、恢复、离线回放保持原有边界。本轮未重新做真实案例全量审计。

## 本地资料与实现的区别

- `data/packing-dimensions.json`只保留纸箱、原箱、规则与证据；单品装箱尺寸已拆到 `data/packing-product-dimensions.json`，通过稳定的商品匹配源标签 `productKey` 挂接。前台正式简称可以随 ERP 身份资料更新而变化，不会因此打断已确认尺寸的关联。
- 新版两款7条装咖啡已正式进入 `product-mapping` 待补商品目录，编码分别为 `6980319670023` / `6980319670030`；当前主要缺平台商品图、稳定视觉特征和共同单盒尺寸，因此可选但会红标待补尺寸、不能进入几何模拟。六款悦希截图新品同样已进入待补目录，尺寸已记录。
- 商品目录口径：正式售卖商品及有独立纸盒/塑封的“体验装”可进入；只有瓶器/散装的“小样”不进入现役目录。ERP 200条参考快照仍可保留小样事实，但不会因此启用。
- 黑茶茉莉花茶味说明卡片与悦希雪梨纸被记录为零体积配件：订单事实保留，几何计算忽略，默认可随货放入。KGOS体脂秤记录为一件代发排除项，不参与仓库发货装箱。
- `pendingMappings`中含待编译为实验输入的资料；加载器只把它们当元数据，不表示新品或新箱已被启用。
- `giftPackingFitChecks`保留5组显式布局；输入厚度估计与自动求解结果分开记录。现有求解既有固定增量排序漏解，也有完整支撑硬门禁过严问题；显式布局证明有可行坐标，不代表未来必须保持“袋先铺底”顺序。
- 活动笔记 `data/packing-campaign-notes-2026-09-08.txt`仍未解析；商品匹配后的固定组合定义需要用户逐条确认。
- 商品映射待补索引现同时有 `../product-mapping/data/products/hee/pending-products.json` 和 `../product-mapping/data/products/kgos/pending-products.json`；前者6个悦希截图新品、后者2个新版7条装咖啡均已明确为在售待补资料。
