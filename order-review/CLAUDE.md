# 订单审核系统

## Session 启动

1. 读 `SKILL.md`，按导航读取 `tasks/todo.md`、`docs/INDEX.md` 和 `docs/CURRENT.md`。
2. `AGENTS.md` 是本项目共同遵守的ERP安全与数据边界，Claude Code同样适用。
3. 涉及包裹判断时读根本规则；涉及ERP执行时再读执行关卡文档，均由INDEX导航。

## 稳定边界

- 原订单事实不可编辑；包裹草稿与实验结果是独立决策层，必须逐商品数量守恒。
- 真实ERP写操作只在用户针对当前订单明确授权后执行；不自动处理下一单，不重试业务提交。
- 保存/历史命中不等于ERP已执行；物流与普通单包分开。
- 可靠确认规则优先，尺寸计算兜底；历史冲突不能靠计算静默选边。未知不是装不下。
- 品牌箱型不能混用，真实商品身份与包装等体积身份分开；具体白名单以根本规则为准。
- 活动原文不自动解释为规则；商品完整名称与简称分字段，保留空格和符号。
- 不根据旧计划或历史测试方便性改变业务约定。新冲突先与用户明确讨论再修改规则。

## 数据与验证

正式案例在 `~/Library/Application Support/Order Review/`；真实案例验证只读，写入/恢复测试用临时目录。
修改代码后按项目要求运行 `python3.13 -m pytest -q`；测试创建的窗口、端口和进程必须清零。
仅资料/文档修改优先验证数据、引用及相关契约，不为归档启动ERP、浮窗或服务。
代码/文档按工作区规则提交；`data/`默认不提交，不能把其他未提交工作一并带入。

运行、恢复和诊断命令见 `docs/usage.md`。项目当前能力只由 `docs/CURRENT.md` 维护。
