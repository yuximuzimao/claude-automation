# 商品宣传图工作台规则索引

## §0 核心定位

本项目保存的是一套可迁移的设计工作流，不依赖某个 GPT 账号的聊天记忆。GPT 负责理解模糊需求、视觉分析、构图判断、提示词和局部修改指令；本地项目负责素材、描述、规则、任务状态、版本和最终文件。

第一版不要求先把所有宣传图归类。任何未知任务都从以下五个维度拆解：
1. 商业目的；
2. 视觉主体；
3. 信息与层级；
4. 风格与参考来源；
5. 硬约束与允许变化。

## §1 输入角色

每张输入图必须登记角色，不能无差别交给生成模型：
- `product_source`：真实产品素材；
- `product_set`：已排好相对比例的产品组合；
- `brand_logo`：品牌标识；
- `demo_layout`：信息层级和大致布局；
- `style_reference`：色调、光影、材质、构图或气质参考；
- `designer_output`：历史成品和评价依据；
- `edit_target`：本轮直接修改对象；
- `generated_draft`：AI 或合成产生的草稿。

历史描述解决素材身份复用，但以下情况仍需重新看图：新构图判断、当前草稿质检、局部修改定位、文件版本疑似变化。

## §2 Demo 解析

- 默认输入是“Demo 截图 + 可复制文字”。截图用于理解人眼可见的信息层级、分组、相对位置和布局意图；用户提供的可复制文字是内容真值。
- 共享 Excel、在线表格或结构混乱的原文档不要求 GPT 直接读取。下载后的 Excel 只做可选归档、文字核对或局部辅助解析，不能因为单元格结构混乱而覆盖截图所表达的人类视觉结构。
- Demo 通常只代表信息层级，不代表最终绝对坐标。
- GPT 先提取必须出现的文字、层级、分组、顺序和产品要求，再根据产品摆放重新安排最终排版。
- 设计师描述很短时，GPT主动补齐可执行判断，但只询问真正阻塞的歧义。
- 未指定尺寸时使用 `1080 × 1920`，9:16 竖版。

## §3 双输出对齐

每个任务必须同时保存：

### 人话版 `human-alignment.md`
控制在设计师能快速判断的长度，至少说明：
- 这张图要做什么；
- 主体是谁；
- Demo 如何理解；
- 参考图具体借鉴什么；
- 产品和文字哪些不能错。

### 机器版 `design-intent.json`
至少包含：
- `objective`；
- `canvas`；
- `asset_ids`；
- `content_hierarchy`；
- `layout_freedom`；
- `product_constraints`；
- `style_features`；
- `forbidden_reference_elements`；
- `exact_copy`；
- `open_questions`。

## §4 分层制作原则

每次根据当前素材动态选择技术，不固定成单一模板：
1. 背景与场景：生成式图像或现有素材；
2. 产品层：优先直接使用真实 PNG；
3. 融合层：轮廓光、表面反射、接触阴影、倒影、环境色；
4. 图形层：SVG、Canvas 或可编辑图层；
5. 文字层：确定性排版；
6. 质检层：文字、产品、构图、风格和不变量。

黑色产品不能仅加均匀外发光。需要主光、辅光、局部反射、边缘高光和接触关系，保证瓶身层次与 Logo 可识别。

### §4.1 生图授权门禁

本项目采用“一次性显式授权”，禁止根据连续对话自行维持图片编辑状态：

1. 默认状态永远是 `discussion`。查看图片、讨论需求、评价草稿、提出意见、整理提示词和询问下一步都只允许文字回复。
2. 是否执行只判断用户当前消息，不读取上一轮的执行意图。上一轮刚生成过图片，也不得推定下一轮仍要生成或修改。
3. 当前消息必须明确包含执行动作，例如“现在生成”“开始生图”“按这个方案生成”“现在修改这张图”，才可调用一次内置生图工具。
4. “可以”“继续”“再看看”“就这个方向”“背景简洁一点”“产品再大一点”等短确认和设计反馈不属于执行授权。应回复对反馈的理解、影响和拟修改项，不得直接生图。
5. 一次调用完成后，无论成功或失败，都立即恢复 `discussion`；后续再次执行必须取得新的明确授权。
6. 用户明确说“先讨论”“不要生成”“不要修改”“只分析”时，视为强制禁止生图，持续到出现新的明确执行消息。
7. 禁止使用 `scripts/image_gen.py`、OpenAI Images API、`OPENAI_API_KEY` 或任何 CLI/API 备用路径。内置通道不可用时只报告不可用，不自动切换、不要求配置 API Key。

推荐对话协议：
- 普通沟通无需前缀，默认只讨论。
- 需要真正执行时使用“现在生成：……”或“现在修改：……”。
- 模型认为方案已成熟但尚未收到执行授权时，只能说明“方案已具备执行条件”，不能自行调用工具。

## §5 产品硬约束

直接判定不合格：
- 产品形状、瓶盖、长宽比或 SKU 相对比例改变；
- 产品被明显不真实地透视或拉伸；
- Logo、产品名称或标志性特征被遮挡；
- 包装文字被生成模型重绘为乱码；
- 产品数量或组合关系错误。

通常允许：缩放、平移、轻微旋转、前后交错、合理局部遮挡、独立光影处理。遮挡优先落在无关边缘区域。

## §6 参考图边界

可以借鉴：
- 配色；
- 光线方向与明暗关系；
- 材质；
- 构图倾向；
- 主体大小与视觉冲击；
- 视觉密度；
- 品牌气质；
- 可泛化场景元素。

禁止带入：
- 水印和账号；
- 他牌 Logo；
- 他牌产品；
- 他牌原文案；
- 高识别度完整构图的机械复制。

## §7 修改循环

每轮修改只改变一个明确问题或一组强相关问题。记录格式：
- `change`：本轮改什么；
- `preserve`：哪些必须保持；
- `reason`：为什么改；
- `result_asset`：产生哪个版本；
- `qa`：修改后不变量是否通过。

例：增强三个产品正面层次和局部反光；保持画布、产品位置、比例、文字、背景结构和 Logo 区域不变。

## §8 素材归档与去重

- 文件进入长期目录前计算 SHA-256、像素尺寸、色彩模式、透明通道和 dHash。
- SHA-256 相同：完全重复，只保留一个二进制文件，其他来源写入 `source_aliases`。
- 感知哈希相近：只标记 `possible_duplicate`，不得自动删除；不同抠图、不同透明边缘、不同角度可能具有实际价值。
- 每个资产必须有稳定 `asset_id`、自然语言描述、标签、适用方式和保护规则。
- 不能只依赖原始文件名或聊天上下文。

## §9 迁移

迁移时复制完整 `product-ad-studio/` 目录。目标环境只需：
- Python 3.11+；
- `pip install -r requirements.txt`；
- 能读取本地工作区的 GPT Work、CodexPro 或 Codex CLI。

所有品牌规则、素材指纹、案例总结和任务历史均在本地文件中。聊天记录不是迁移依赖。

## §10 已知限制

ChatGPT 对话附件与 CodexPro 本地文件系统目前不是自动互通的同一目录。对话中看过但未导入本地的图片，只能保存描述和附件引用，不能视为已完成长期归档。需要长期保留时，应把原文件放入本地导入目录，再运行素材导入。
