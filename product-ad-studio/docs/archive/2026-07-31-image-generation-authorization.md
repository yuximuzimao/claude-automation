# 2026-07-31 生图授权门禁归档

## 背景

首个黑金兰花宣传图任务完成了需求拆解、结构化 brief 和一次会话内图片生成，但生成后连续多轮普通沟通被错误识别为继续编辑图片。与此同时，Codex 本机 `imagegen` Skill 暴露了需要 API Key 的 CLI 备用路径，增加了通道混淆和意外切换风险。

## 根因判断

- ChatGPT 外层内置生图工具、CodexPro 本地工作区工具和 Codex 本机 `imagegen` Skill 是不同层级。
- Skill 文档存在不代表当前 CodexPro 调用上下文实际拥有内置生图工具。
- 图片生成后的连续误调用属于会话工具路由持续继承上一轮编辑意图，而不是本机 API Key 缺失导致。
- 当前平台没有可依赖的独立“退出图片编辑上下文”项目开关，因此不能继续依赖模型自行判断状态。

## 稳定决策

项目采用一次性显式授权门禁：

1. 默认状态永久为 `discussion`，普通沟通只允许文字回复。
2. 是否执行只判断用户当前消息，不继承上一轮生图或编辑意图。
3. 只有当前消息明确包含“现在生成”“开始生图”“按这个方案生成”“现在修改这张图”等执行动作，才允许调用一次内置生图工具。
4. “可以”“继续”“再看看”“产品再大一点”“背景简洁些”等确认和反馈只用于需求讨论，不构成执行授权。
5. 每次生成或编辑完成后，无论成功或失败，都立即恢复 `discussion`。
6. 用户声明“先讨论”“不要生成”“只分析”时，持续禁止生图，直到出现新的明确执行消息。
7. 禁止使用本机生图脚本、Images API、API Key 或任何 CLI/API 备用路径；内置通道不可用时不得自动降级。

## 推荐对话协议

- 普通需求、图片评价和修改意见直接自然表达，默认只讨论。
- 真正执行时使用 `现在生成：...` 或 `现在修改：...`。
- 方案已经成熟但没有执行授权时，模型只能说明已具备执行条件，不能自行调用工具。
