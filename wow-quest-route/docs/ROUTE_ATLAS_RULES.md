# Route Atlas 总规则

状态：长期权威规则。本文只保存跨会话、跨地图、跨批次仍应遵守的方法与产品约束；地图特定状态、某批角色经验、R快照、局部路线尝试和一次性异常必须放在对应CURRENT、NEAT或日期化分析文档中。

发生冲突时，永久方法以本文为准；具体当前状态以`docs/verified-routes/CURRENT.md`为准；某地图已验收的局部事实仍以该地图任务知识、实跑记录和最新Questie/用户现场证据为准。

## 1. 产品分层与职责

Route Atlas不是单纯的路线图片，也不是Questie的替代品。长期分层固定为：

`Questie Raw（不可改写） → Questie Effective/派生事实 → 单任务知识节点 + typed relations + numeric features → 路线版本/路线节点 → HTML执行工作台`

- Questie Raw保存插件原始事实，实跑观察不得回写覆盖。
- 单任务知识节点保存与某条具体路线无关的可复用知识。
- 路线节点保存“这次为什么把该任务放在这里、与谁合并、产生多少边际移动/服务成本”等版本特定信息。
- HTML是当前唯一主前端。地图承担宏观走向，Questie继续承担游戏内精确目标定位，任务知识卡承担需要额外记忆和解释的信息。

## 2. 任务知识不是操作备注

每个任务知识节点应能够关联或保留：

- Questie派生事实；
- typed facts；
- typed relations；
- numeric features；
- 稳定的人类可读标签；
- Target Cluster与必要时的Spatial Instance；
- 五开机制、地形、特殊操作、掉落与等待风险；
- source / confidence；
- 实跑observation与历史纠错。

稳定标签用于解释，不替代底层事实。常用家族包括`scope:*`、`objective:*`、`chain:*`、`trip:*`、`terrain:*`、`route:*`。机器关系至少支持`precedes`、`same_accept_npc`、`same_turnin_npc`、`same_direct/resolved_creature`、`same_direct/resolved_object`、`same_required_item`、`spatial_overlap`、`same_chain`、`same_excursion_block`等。

Questie已经直接显示的普通等级、经验、基础坐标、基础目标默认不占前端卡片版面，但后台数据不得因此删除。

## 3. 从零复用主路线与当前执行路线必须分离

永久保留两类路线：

1. **从零复用主路线**：面向下一批从该地图正常起步的角色，必须包含本批已经做过但下一批仍需要的任务。
2. **当前执行路线**：只服务当前角色的真实任务状态，可删去已完成任务、改变起点、局部重排和重新选择炉石节点。

当前角色完成某任务时：

- 只从当前执行路线删除相应执行动作；
- 不从从零复用主路线、任务知识节点、任务宇宙、关系库或历史快照删除；
- 删除后必须重新检查剩余目标的几何关系、前置链、Hub停靠和炉石收益，不能只是把原路线节点挖空后机械连接前后两点。

当前路线的起点不必等于从零路线起点。应以“当前状态下最低剩余总成本”为准选择可执行起点。

## 4. 当前状态与证据新鲜度

回答“现在还要做什么”时必须优先使用最新状态，不能让旧缓存覆盖新证据。默认优先级：

1. 用户在当前会话明确给出的现场状态、等级、经验和异常行为；
2. 当前客户端最新Questie人物历程/现场可接状态；
3. 项目中最近一次明确标记为当前的结构化状态；
4. 较旧的脱敏人物缓存、历史CURRENT、旧路线版本；
5. 通用数据库和历史资料只用于补任务结构，不能覆盖当前时光服实况。

Questie历程能证明接取、完成/交付、放弃、等级和时间戳；不能证明死亡、真实移动路线、找怪耗时、暂停原因或目标进度细节。

## 5. 异常顺路行为只更新状态，不自动学习成路线

玩家可能因为学技能、买物品、处理现实事务、测试机制等原因临时跨图，并顺手完成或接取任务。

这类事件：

- 完成/接取结果必须进入当前状态真值；
- 临时绕路本身不得自动写进从零复用路线；
- 只有当独立成本分析或后续多轮实跑证明该绕路本身更优时，才可升级为长期路线规则。

即“结果影响剪枝，原因不自动成为路线证据”。

## 6. Target Cluster、Spatial Instance与Background Layer

- 完全相同的真实目标实体优先形成Target Cluster。
- Questie刷新点或静态坐标不能直接代表真实可走的一次服务区域。
- 必须人工结合道路、桥梁、洞穴、地形和实跑，把目标簇解析为真实Spatial Instance。
- 广域累计、沿途杀怪、背景拾取、低掉率自然触发等任务应进入Background Layer。
- Background Layer跟随主体路线完成；主体路线不得为了背景任务反向绕路，除非边际成本经过单独验证后确实值得。

## 7. 路线构建的长期方法

当前冻结的人工可审计流程为：

1. 建立Questie/人工事实层；
2. 形成Target Cluster；
3. 建Prerequisite Network；
4. 人工解析Spatial Instance；
5. 分离Background Layer；
6. 以首个目标簇建立R1；
7. 后续逐任务/逐簇执行`插A → 插C → 插T → 局部稳定 → 重算炉石 → 保存Rn`；
8. 已验收旧路线原则上只做局部重排，除非发现明确错误或新增硬约束；
9. 不同Target Cluster默认没有先后关系，只有显式前置或真实成本证据才建立顺序。

“一个一个插”指路线构建与可审计快照粒度，不意味着每插一个任务就做一次全图动态图审查。

## 8. 删除已完成任务后的恢复流程

当根据最新历程裁当前路线时，固定流程为：

1. 识别任务状态：completed / active / unseen / conditional；
2. 从当前执行动作中移除completed任务；
3. 检查active任务是否仍需C/T，以及unseen后续是否由剩余路线正常解锁；
4. 对因为删除节点而改变的局部区域重新排列，不机械保留旧顺序；
5. 检查原本隐藏在已完成任务之后的关键前置是否仍会及时接取；
6. 重新评估起点、Hub停靠、炉石落点和条件分支；
7. 完成整张当前路线恢复后再看动态图全局异常；
8. 当前裁剪结果另存，不覆盖从零复用主路线。

## 9. 炉石与时间成本

炉石是独立可重算的路线资源，不是固定“一图一次”：

- 每次局部稳定后都应重新评估；
- 只要冷却与收益成立，可以0次、1次或多次；
- 不为等待炉石冷却而停工；
- 炉石节点必须明确绑定地点和使用目的。

总成本长期按以下结构理解：

`T_total = T_travel + T_objective_service + T_accept_turnin + T_forced_wait + T_other_known_cost`

角色移动速度变化只作用于真实受该效果影响的纯移动段。坐骑光环、骑术或装备加速不得乘到护送、脚本飞行、战斗、拾取、交互、炉石和等待时间上。具体速度数值属于当前角色参数，不是永久常量。

## 10. 精确优化器的定位

PC-SP、state-space DP / labeling、MILP、Branch-and-Cut、CP-SAT、flexible service location、shared-service/covering等模型保留为：

- 理论母模型；
- 局部插入成本估计；
- 顺序枚举；
- 异常检测；
- 与人工路线对照。

它们不直接替代玩家路线。只有模型边界、地形、服务位置和状态约束都足够准确且求解器证明optimal时，才允许称“理论全局最优”。

## 11. 动态整图审查的固定时机

动态图是固定验收流程，但执行时机为：

- 先完成整张地图的任务插入或当前状态恢复；
- 再生成/播放全图动态路线；
- 检查大范围反向折返、异常跨图、炉石落点、阶段切换和局部顺序；
- 发现异常后回到对应局部修正。

不得在每插一个任务后都做整图动态图审查。前端可直接建立在这份动态HTML之上。

## 12. HTML前端长期约束

当前稳定交互与视觉约束：

- 地图全宽置顶；当前步骤与任务知识卡在地图下方；完整步骤列表更下方。
- 玩家步骤以中文任务名和“接/做/交”语义显示，任务ID只作为内部键。
- 多任务步骤可点击任务名切换知识卡。
- 知识卡优先显示特殊操作、稳定标签、关系、Target Cluster/Spatial Instance、当前路线编排理由和可审计数值特征。
- Questie普通基础字段默认隐藏但后台保留。
- 路线箭头视觉冻结：普通线宽`1.25`，当前段`3.0`，炉石普通`1.8`、当前炉石`3.4`，箭头marker `5×5`，使用`markerUnits="strokeWidth"`和`vector-effect="non-scaling-stroke"`。

除非用户明确要求改变视觉系统，否则后续版本不得无理由漂移这些参数。

## 13. 永久规则与阶段文档的边界

应写入本文的内容：跨地图、跨批次仍然成立的方法、证据优先级、数据分层、恢复流程、前端长期契约。

只写入日期化NEAT/analysis/version文档的内容：

- 某地图R1–Rn快照；
- 某批角色等级/经验；
- 某次Questie哈希与任务状态集合；
- 某次临时跨图行为；
- 地图特定条件任务、掉率、局部顺序和炉石次数；
- 当前尚在验证的假设或优化实验；
- 理论模型某次求解结果。

阶段性结论只有在被明确提升为长期规则时，才迁入本文；迁入后，日期文档保留形成过程与证据，不再作为永久规则的唯一入口。
