# 路线设计与修订强制流程

用途：这是本项目所有“新建路线、修订路线、重算后续路线、回答跨区怎么走、根据实跑反馈继续规划”的统一 SOP。本文件只规定**什么时候检查什么以及检查顺序**；具体永久规则从 `docs/rules/README.md` 按当前阶段渐进式加载，`ERROR-BOOK.md` 保存历史错误。

任何涉及任务路线或跨区移动的答案，都不能只凭当前执行稿正文直接回答。必须先完成与问题范围对应的流程。新建/重构完整路线必须执行全流程；单纯问“从A怎么去B”至少执行阶段0、1、2、8。

---

## 阶段0：确定本次规划范围

先明确这次属于哪一种：

1. 完整新路线；
2. 当前路线局部修订；
3. 实跑异常后的后续重算；
4. 单个区域任务块；
5. 单纯跨区/营地导航。

明确共同终点。比较两条路线时，必须比较“从当前状态到同一个后续里程碑”的完整序列：未满级时可以是同一等级/下一任务中心，满级清图时可以是同一Hub、同一任务链闭合状态或同一地图出口；不能拿一个单任务和另一个整地图直接比较。

同时先确定**修改授权边界**：

- 已完成/已验证路线默认冻结；用户没有明确要求改路线结构时，不得因为审计、测试、历史资料或顺手发现的问题自行调整任务集合、顺序、交通或任务链。
- 用户明确指出某条文本/某个任务的问题，只处理该范围；若发现其它疑似问题，先报告证据并询问是否修改。
- 只有用户明确说“同类问题全部修”“整图复审/重构”或等价指令，才允许把修改扩展到其它已完成路线。
- 自动测试失败不能自动扩大修改权限；先判断测试是否仍对应当前契约。

### 0.1 本轮若触碰永久规则，先做受影响规则一致性门禁

只有当本轮**新增、修改或准备提升**一条跨地图长期规则/机制时才触发，不要求普通路线局部修订每次全文读取全部规则。按`docs/rules/README.md`的永久规则准入标准检查：该内容是否真的跨批次、是否放在唯一owner、是否与邻近规则重复/冲突、是否夹带CURRENT状态/单任务案例/阶段数字、是否仍服从项目第一目标，以及现有代码/测试/正式数据是否同步。发现问题先修规则架构或实现，再继续把新规则用于路线发布。

# 阶段1：建立唯一可信的当前状态

## 1.1 必读文件

每次新建、修订或继续路线，先读取：

- `docs/verified-routes/CURRENT.md`
- `docs/rules/README.md`，再按本次工作类型加载其路由的子规则；SOP不自行维护另一份“固定必读子规则清单”
- 按本轮变更类型/风险定向检索并读取 `docs/verified-routes/ERROR-BOOK.md` 相关错题；不默认全文加载
- `docs/verified-routes/FLIGHT-POINTS.md`
- `CURRENT.md` 指向的当前执行稿
- `docs/task-library/`中本轮任务已经存在的人工核验卡片

不要因为“我记得”跳过CURRENT、规则路由和相关错题；但也不要为了一个局部问题一次性加载全部 `docs/rules/`、整本错题本、全部历史NEAT或全部任务卡。完整新地图第一次建立风险视野时可以扩大错题检索范围，但后续局部修订只读对应失败模式。

人工任务卡片存在且版本、等级、队伍和路线上下文仍适用时直接复用，不重复计算。只有卡片缺失、适用条件变化、底层来源更新或用户实服反馈冲突时，才重新核验受影响任务；核验结果必须回写任务卡片。

## 1.2 当前角色状态

确认并记录：

- 五个角色各自等级/经验；
- 最低经验角色，作为唯一预算基准；
- 当前地图、营地或坐标；
- 当前炉石绑定点；
- 当前普通五人小队/团队状态；
- 当前任务日志关键任务；
- 已知每个角色之间的任务完成差异；
- 任务日志占用数；
- 最近一次实跑产生的新机制证据。

如果 Questie 当前历程只能代表一个角色，必须明确写“只能证明该角色状态”，不能外推五号完全一致。

## 1.3 状态冲突处理

证据优先级：

**用户当前实测 > 最新实跑记录/Questie当前状态 > verified route/observations > Questie数据库 > 公开社区资料 > 旧路线假设。**

发现冲突时先修正状态，再设计路线。

# 阶段2：先解交通问题，再设计任务顺序

这是强制前置步骤，不能等路线写完后再看飞行点。

## 2.1 读取已开启交通网络

以 `FLIGHT-POINTS.md` 为真值，列出当前能使用的：

- 已开启飞行点；
- 炉石；
- 飞艇；
- 船；
- 已验证直飞关系；
- 必须陆路首次开启的新节点。

未记录的飞行点按未开启处理，不能猜。

## 2.2 每次跨区必须比较交通方案

至少比较：

- 直接飞；
- 飞到最近已开启点＋短程骑马；
- 炉石＋飞行；
- 飞艇/船＋飞行；
- 全程陆路。

目标是**最大化可用飞行距离、最小化玩家实际骑马距离和中转次数**。

例如当前“加基森→蕨墙村首次开点”，因为陶拉祖已经开启，所以应先飞陶拉祖再陆路进入尘泥，不能让玩家从加基森全程骑过去。

## 2.3 新飞行点处理

路线第一次经过新任务中心时：

1. 明确写出飞行管理员位置/入口；
2. 五号分别开启；
3. 实跑确认后立即更新 `FLIGHT-POINTS.md`；
4. 把该点加入从这一动作开始生效的 `opened_flight_points` 状态；
5. 重新检查新节点是否产生新的直飞路线；
6. 对后续尚未执行的所有跨片区交通边重新比较交通方案，删除不再需要的旧中转/骑马段。

不得出现“飞行点已经开了，但路线仍沿用旧枢纽绕路”。

## 2.4 按任务时点重放飞行网络

飞行网络不是地图级静态清单，而是随路线推进逐步扩张的状态。设计/复审时必须从起点顺序重放：

1. 每个接取、交付、开飞行点、炉石绑定和转场动作后形成新的交通状态；
2. 对下一任务/任务块，记录当时已开启飞行点集合，而不是使用整图最终飞行点集合；
3. 凡下一段需要明显跨片区移动，至少比较：直飞、飞到最近点＋骑马、炉石＋飞行、其它系统交通、纯骑马；
4. 如果路线仍选择骑马，必须确认骑马在完整墙钟上更优，例如沿路有必须完成的生产性任务、飞行管理员绕远或落点更差；
5. 新飞行点一旦开启，对未执行后缀重复步骤2—4，禁止旧交通决策被冻结。

内部审计必须能回答：**“做到任务Q时已经开了哪些飞行点？Q→下一任务为什么不是飞？”** 玩家页面只显示最终采用的交通动作，不显示这套内部审计过程。

# 阶段3：建立完整任务候选集合

自动候选只能召回，不能证明完整。

候选集合必须取以下并集：

1. 当前任务日志；
2. 当前区域自动候选；
3. 当前已完成任务的直接后续；
4. 所有单前置、组合前置和跨地图前置闭包；如果某条链在路线成稿后才被发现，也必须从第一个真实解锁节点回插并重新排序受影响后缀，禁止把整条漏链追加到地图末尾；跨地图中间环同样属于闭包，不能因`assigned_zone`不同而漏掉；
5. 当前营地及路线经过营地所有可接/可交任务；
   - 同一营地、同一时刻可接、已确定会做、且任务日志不会接近25个上限的任务，默认**一次接齐**；不得仅因攻略章节分段而人为拆成多次接取。
   - **NPC级首次接触检查**：第一次站到某个NPC面前时，必须检查该NPC当前所有可接任务；凡后续确定会做且日志有空间，全部当场接走，不能因为任务被写在后面的章节而留到第二次回来。
   - **交任务后二次扫描**：每次向NPC交任务后，在离开该NPC前必须重新检查其新出现的任务；刚被前置解锁、后续会做的任务必须立即接取。多个连续对话/交接应在同一次NPC访问中推进到当前可推进的最远节点。
   - 只有存在明确前置尚未完成、等级门槛、任务日志容量压力、任务互斥/阶段冲突，或该任务已明确排除时，才允许不接，并必须写明原因。
6. 目的地NPC及附近NPC任务；
7. 野外护送NPC、巡逻NPC；
8. 地面物体触发任务；
9. 掉落物右键触发任务；
10. 跨区引导/送信任务；
11. 当前等级暂缓、但后面会回访该地图的任务。

在前往洞穴、城堡、矿区、海岸、虫巢、营地等远端地点之前，再执行一次“同目的地聚合”：所有指向同一目的地的任务尽量同趟完成。

最终必须执行一次**遗漏复查**，而且不是只做任务ID差集：

`候选并集 -（路线纳入任务 + 明确跳过任务 + 明确延后任务）`

差集中的每一项必须被明确归类为：

1. **故意跳过**：已审计过，确实不值得做；
2. **明确延后**：有具体回访节点；
3. **顺路补回**：路线本来就经过同NPC/同地点/同目标区，额外成本接近零，之前只是遗漏——必须补回正文；
4. **真正未覆盖**：说明路线审计尚未完成，不能发布。

尤其要单独检查“白送型任务”：同NPC顺手接交、同一路上送信、同目的地对话、已经要去的任务点顺手完成、已经要杀的同一批怪额外带一个任务。像这类任务不能因为经验少、旧攻略没写或自动候选没召回就漏掉。

# 阶段4：逐项确认任务真实机制

每个准备进入主路线的任务必须先分类，不能只看任务标签或Questie坐标。

## 4.1 任务机制类型

至少区分：

- 共享击杀；
- 普通多数量任务物＋FFA；
- 每角色独立掉落/个人判定；
- Party Loot / 单命名任务物；
- 单尸多件掉落；
- 地面固定物；
- 固定容器逐号点击；
- 对怪使用任务道具；
- 护送；
- 事件/召唤；
- 命名怪刷新等待；
- 潜行/隐形目标、黄色非主动目标及其显形/主动攻击方式；
- 对话救援、事件触发、击杀触发与护送之间的真实区别；
- 洞穴/多层建筑/路径复杂任务。

对于`event`、`rescue`、潜行NPC、黄色非主动NPC或数据库`count_confidence`异常的目标，必须额外确认**目标可见性、阵营反应、玩家实际触发动作和所在楼层/入口**。不能把数据库`objective_type`直接翻译成“杀掉/点击/救援”。

## 4.2 FFA普通多数量任务物

当前实测规则：

- 五号总需求量仍要累计；
- 每具尸体只让一个当前需要物品的角色拾取一次；
- 不让五个角色依次检查同一尸体；
- 一具尸体可能掉多件任务物，按实际件数推进；
- 不能把“一只怪五个角色各拿一份”当默认机制。

不同任务若表现不同，必须单独记录，不能用一条泛化规则覆盖全部任务物。

## 4.3 不确定机制必须验证

如果某个任务的掉落/共享机制会显著改变路线价值：

1. 查本地 Questie/参考数据库；
2. 查公开 Classic/WotLK 社区讨论或任务资料；
3. 优先采用用户当前服务器实测；
4. 仍不确定时，把任务列为“未验证/可选”，不得计入保证经验。

## 4.4 刷新与目标等级

使用实际任务目标/掉落来源怪等级，而不是只看任务等级。至少确认：

- min / 常见区间 / max；
- 强制目标数量；
- 高等级目标是否可跳；
- 刷新密度；
- 是否存在明显优于散点的高密度刷怪区；
- 是否在洞穴；若在洞穴，必须确认入口、洞内主刷区、可循环路径和洞口补怪点；
- 命名怪是否需要等待；
- 从入口到目标的沿路敌对怪等级。

个人掉落任务如果同时存在地图散点与洞穴/营地密集刷新，必须先按最高密度路线估算任务时间，再评价掉率。首次实跑因为不知道密集刷点而产生的长耗时记录为学习成本，不能直接写成该任务固有长尾。

# 阶段5：先算“剩余边际成本”，再决定删不删已接任务

这是已接任务的强制审计。

## 5.1 区分沉没成本

对于已经接到、已经解锁、已经拿到稀有触发物的任务：

- 已支付的前置；
- 已支付的触发物掉落成本；
- 已支付的接取跑图；

全部视为沉没成本，不得再次计入“现在做这个任务还要多久”。

只算从当前状态开始的剩余成本。

## 5.2 按任务包而不是单任务计算

同一地图/同一圈的多个已接任务：

- 地图进入成本只算一次；
- 公共骑马路径只算一次；
- 重叠击杀只算实际总击杀量；
- 同一区域命名怪只算额外偏移/等待；
- 回城/交任务合并计算。

不能分别给每个任务都加一次“去菲拉斯20分钟”。

## 5.3 删除前执行反向替代测试

任何准备放弃的已接任务/任务包，都必须把“保留执行”和“从当前状态放弃”推到同一个后续里程碑，再比较完整影响：损失的直接金币/物品价值、经验状态价值、后续链可达性、未来回访，以及节省的真实墙钟。

未满级阶段如果删除会造成等级/经验缺口，必须明确后面需要新增哪些具体任务来达到同一里程碑，并比较替代任务的剩余墙钟；已经满级或当前里程碑不依赖经验时，不强行要求“找一组替代经验任务”，而是直接比较任务打金周期的总金币、总墙钟和后续链变化。

不能仅凭“这张地图不在主轴上”“这是掉落任务”或其它标签删除已经解锁的高价值任务。

# 阶段6：组装并比较“区域任务块”

路线优化单位是**区域任务中心/连续任务包**，不是单只怪，也不是单个任务。

## 6.1 每个任务块的总成本

完整计算：

- 进入区域的飞行/炉石/骑马；
- 本地接任务；
- 本地骑马；
- 规定战斗；
- 个人拾取动作；
- 固定物逐号点击；
- 搜索/刷新；
- 洞穴/楼层/跟随风险；
- 返回交付；
- 离开区域；
- 对下一任务中心的最终位置价值。

比较必须服从`docs/rules/README.md`定义的项目第一目标：最终看任务打金周期的**净金币 / 真实墙钟**。未满级阶段的确定任务经验与强制击杀经验是重要状态变量，用来证明等级门槛、后续可接性和80级XP折金时点；它们不能再单独作为路线的最终效率指标。满级阶段则直接把XP折金、直接金币、装备/物品变现与完整墙钟放在同一经济账里。

每次生成/重排可执行路线时，还必须按`docs/rules/timing-and-benchmarking.md`把上述成本落到**每个玩家逻辑步骤/自然任务块的预计分钟数与整段总时间**；路线没有分段估时和总估时不得发布。实跑后把实际墙钟与clean baseline成对写入`data/observations/route-timing-runs.json`，异常/学习时间单列，不能拿一次带失误的整段墙钟线性外推其它任务块。

怪物等级差是重要成本项，但不是机械禁区。

## 6.2 替代路线必须到同一里程碑

比较路线A和B时，必须把二者都推到同一个后续节点/同一阶段目标再比较，不能拿“一个单任务”对比“另一整图”。未满级时里程碑可以是相同等级/下一任务中心；满级清图时可以是相同后续Hub、相同任务链闭合状态或相同地图出口。只有把边界对齐，才能判断一次转场、一次折返或删除一个任务包是否真的更优。

## 6.3 至少向后看一个任务块

不能只优化当前块。

必须检查：当前选择会不会让下一地图进入更理想的怪物等级带、减少后续高等级任务、减少一次跨大陆往返，或者反而造成回头路。

# 阶段7：未满级经验闭合 / 满级经济闭合

角色尚未满级时执行7.1—7.3的经验闭合与无衰减校验；角色已经满级时不再为了等级/经验截止重排路线，改为按`timing-and-benchmarking.md`核对XP折金、直接金币、物品/装备变现、后续链和完整墙钟的经济闭合。

## 7.1 未满级：下界经验账 + 上界等级账

每个任务块同时维护两套账：

**下界经验账**用于证明能够达到阶段等级：
1. 精确任务奖励；
2. 任务规定强制击杀经验；
3. 探索、清路、误拉、随机额外击杀等按0进入保证预算。

**上界等级账**用于证明尚未交付的低等级任务不会进入经验衰减：
1. 当前角色真实经验；
2. 本轮确定任务奖励；
3. 强制击杀的合理高值；
4. 为个人掉落可能产生的额外击杀；
5. 首次探索新区域经验；
6. 当前角色休息经验可能额外提供的杀怪经验。

最低经验角色仍是“是否能达到目标等级”的唯一基准；但无衰减校验要看**可能升级最快的角色/最高经验上界**，因为任何一个角色提前越过任务等级+5都会在该角色上损失任务经验。

任何未满级路线发布前，都必须为会受经验衰减影响的一次性任务记录`任务等级 → 最晚满经验交付等级(任务等级+5) → 预计交付等级/上界等级`。任一任务上界可能超过截止等级，路线不得发布，必须重排交付顺序或地图循环。

## 7.2 结构变化重算；顺路补回不强制重算

如果是会改变地图顺序、任务块规模、进入等级或保证当前阶段闭合的**结构性增删**，仍然要把影响传导到当前阶段目标，检查后续进入等级和最终停止点。

但实跑中补回的“白送型/近零边际成本任务”不强制重新跑整条跨等级段理论模拟，例如：同NPC顺手交接、同一路上送信、同地点对话、同一批怪顺带完成。此类任务直接记为额外实际经验即可，不为了几百到几千经验反复维护一套越来越失真的预测表。

每完成一个区域任务块，以用户实跑的**最低号实际等级/经验**覆盖旧预测，作为下一块的新基线。多出来的经验留到后半程再从尚未开始的低效率任务中裁掉。

## 7.3 多出来的经验用于删后面的差任务

如果前面出现更高效的新经验：

优先从**尚未开始的后续任务**中删除边际成本最高的一组，而不是让角色最后多出一大截经验。

已经进入并正在高效执行的区域块，不因为中途达到某个等级就机械撤离。

# 阶段8：任务日志与执行细节检查

## 8.1 任务日志容量

记录：

- 当前占用；
- 本区域链展开峰值；
- 默认预留至少5格；
- 跨区任务标注“必接 / 可提前接 / 不要占格”。

## 8.2 玩家可执行性

输出前按玩家正在游戏中边走边看的视角检查：

- 下一步从哪里出发；
- 飞到哪里/骑到哪里；
- 是否应先用炉石；
- 新飞行点在哪里；
- 沿路做哪些任务；
- 玩家可见任务引用必须至少写完整`《任务名称》`；**任务编号永远不得裸写，也不得代替任务名**。Route Atlas等紧凑执行页可以不重复展示ID；若玩家可见文案中确实出现ID，则必须写成`《任务名称》（ID）`。像“交11169”“11207是货物”“595→597→599”全部视为格式错误；
- 发布前对当前执行稿执行一次裸任务ID扫描：凡玩家可见文案出现Questie任务ID但没有与完整任务名绑定，必须清零后才能交付；结构化数据和内部审计仍保留ID用于精确定位；
- 目标坐标紧跟地点名；
- 回营地逐项交什么、接什么；
- 哪些明确不要接/不要做；
- 是否需要五号逐号操作；
- 什么时候离开这个区域；
- 每一个玩家可见步骤摘要是否真的在说“这一段要做什么”，而不是在解释路线设计；
- 每一条任务备注是否真的帮助完成任务，而不是在解释Questie缺陷、人工锚点、候选覆盖、为何合并/排序或测试结论。

不能要求玩家自己把任务列表重新组织成路线，也不能要求玩家在攻略里过滤掉内部审计信息后再寻找真正动作。

## 8.3 Route Atlas新路线前端标准化

凡本轮产出会进入Route Atlas的**新地图/新路线**，玩家执行稿写完后必须立即按龙骨荒野第45步确认的`semantic-hud-v45`标准生成前端；这是新路线设计SOP的一部分，不是旧路线专项优化步骤，也不是发布后的美化工作。

固定动作顺序：

1. 在route数据声明`uiStandard: "semantic-hud-v45"`；
2. 每个`stepGroup`直接生成最终`actionHtml`；有真实执行备注时生成`noteHtml`，无备注允许为空；
3. 地点浅蓝普通字，NPC偏白稍粗；`交/接/做`普通字；流程任务名去`《》`并下划线，交绿/接黄/做蓝；同一动作多任务用`、`；从交接进入执行时另起`↳ 做`；
4. 备注任务名保留`《任务名》`并按任务分块；楼层/危险/短时限等关键字使用普通红字，不加粗、不做胶囊/边框；
5. 不增加地点/NPC点击、脉冲、闪烁，不恢复无行动价值图例/常驻说明；
6. 重建统一HTML后必须从最终页面复读，确认semantic HUD实际渲染，而不是只在JSON里存在；
7. 构建器对旧路线白名单之外的新route key强制执行v45契约：缺`uiStandard`、缺`actionHtml`、actionHtml任务名仍带`《》`、或plaintext动作里的任务名在semantic HUD中丢失，均直接失败。

旧地图“逐段重写旧文案→再套v45格式”仍属于当前专项迁移流程；**不得把这套旧稿修复顺序误写成新地图设计SOP。** 新地图没有“先发布旧样式，之后再统一改格式”的阶段。

# 阶段9：发布前薄门禁

阶段9不是把阶段1—8重新跑一遍。凡前面在任务簇插入、任务卡核验、交通决策和局部重放中已经闭合的事实，后续没有状态传播触及时直接复用，不再次逐任务证明。

发布前只检查以下**无法靠单个插入窗口独立保证的全局性质**：

- [ ] 候选差集全部解释；正式任务池无漏项、无重复、无无解释残留任务；
- [ ] 全图看不到异常重复Spatial Instance、大范围折返、反向跨图，且后续插入没有产生新的“一次进场可合并”机会；
- [ ] 上一地图真实出口 → 当前地图真实入口，以及当前地图真实出口 → 下一地图真实入口仍逐动作闭合；
- [ ] 最终玩家可见步骤摘要/动作/备注只保留导航、执行、避免失败、五开操作和必要离开条件；内部设计、审计、测试、候选覆盖解释全部迁出；
- [ ] 若本轮生成/修改Route Atlas前端，当前route继续满足`semantic-hud-v45`并能正常构建；若没改HTML/UI，不为了形式重复跑前端检查；
- [ ] 本轮若新增/修改永久规则，只检查受影响规则邻域与相关实现是否一致；
- [ ] 当前停止点与下一地图切换条件明确。

发现问题后只打开它对应的受影响窗口修正。比如发现同一Spatial Instance被异常访问两次，只比较这两次访问之间的前置/解锁/交通，不因此重验地图其它任务；发现出口变化，只重算出口到下一地图入口这一条状态链。

如果某个局部问题修改了会向后传播的RouteState——例如飞行点/炉石、声望/阵营、任务日志容量、跨图携带任务、等级/经验截止——就从该状态节点开始向后扩大窗口，直到重新接回原路线；除此之外禁止默认全图重跑。

发布审计记录/NEAT只需简短注明：本轮薄审查发现了什么全局问题、打开了哪些受影响窗口、最终是否闭合。玩家路线正文不得为了证明审计完成而加入这些内部说明。

## 9.1 对抗式复审只攻击“新出现的全局风险”

成稿后的对抗式复审不再从玩家当前点逐任务重走整张地图，也不重复前面已经闭合的前置/机制。它只主动找局部构建阶段不容易看出的全局问题：后续插入产生的新合并机会、异常Hub回访、跨图方向错误、遗漏白送任务、出口不对接，以及最终玩家页面是否变得难用。

发现问题时先确认它真正影响哪些任务卡/状态边，再修改对应窗口；没有被影响的位置保持冻结。

# 阶段10：实跑反馈后的更新流程

用户反馈任何一个新事实后，先判断影响范围：

### A. 仅局部机制变化
例如某任务掉率、FFA、命名怪刷新不同：

- 更新对应 observations/实跑记录；
- 重算该任务块；
- 未满级时重算受影响的后续经验闭合；满级时重算受影响的经济账与总墙钟；
- 不无理由推翻前面已经验证的地图轴。

### B. 新飞行点/新直飞关系

- 立即更新 `FLIGHT-POINTS.md`；
- 从开点动作开始更新`opened_flight_points`并向后重放交通状态；
- 重算后续所有尚未执行的跨片区交通边，不只检查下一跳；
- 逐条检查是否出现“当时已经可飞，但旧稿仍写骑马/绕Hub/先炉石到无任务Hub”的情况；
- 删除旧中转。

### C. 当前等级/经验偏差

- 以最低号新经验作为新基准；
- 保留已验证路线机制；
- 从尚未执行的下一任务开始重新做经验闭合和后半程裁剪。

### D. 新错误属于通用错误

- 追加/更新 `ERROR-BOOK.md`；
- 若形成稳定规则，从 `docs/rules/README.md` 路由到对应永久规则文件；只有流程顺序本身变化才修改本 SOP；
- 不只修当前攻略正文。

# 一句话原则

**先确认真实当前状态和交通网络 → 完整召回任务 → 验证真实机制 → 按当前阶段目标组成区域任务包 → 比较完整替代序列或单地图全清顺序 → 未满级做经验/等级闭合、满级做任务经济闭合 → 最后才写玩家攻略。**
