# 路线设计与修订强制流程

用途：这是本项目所有“新建路线、修订路线、重算后续路线、回答跨区怎么走、根据实跑反馈继续规划”的统一 SOP。本文件只规定**什么时候检查什么以及检查顺序**；具体永久规则从 `docs/rules/README.md` 按当前阶段渐进式加载，`ERROR-BOOK.md` 保存历史错误。

任何涉及任务路线或跨区移动的答案，都不能只凭当前执行稿正文直接回答。必须先完成与问题范围对应的流程。新建/重构完整路线必须执行全流程；单纯问“从A怎么去B”至少执行阶段0、1、2、8。

---

## 阶段0：确定本次规划范围

先明确这次属于哪一种：

1. 完整新路线；
2. 当前路线局部修订；
3. 实跑异常后的后续重算；
4. 单个区域任务块；
5. 单纯跨区/营地导航。

明确共同终点。例如比较两条路线时，必须比较“从当前状态到同一个等级/同一个下一任务中心”的完整序列，不能拿一个单任务和另一个整地图直接比较。

---

# 阶段1：建立唯一可信的当前状态

## 1.1 必读文件

每次新建、修订或继续路线，先读取：

- `docs/verified-routes/CURRENT.md`
- `docs/rules/README.md`，再按当前阶段加载对应子规则；完整路线设计通常需要 `leveling-and-selection.md`、`execution-and-mechanics.md` 和 `state-and-validation.md`
- `docs/verified-routes/ERROR-BOOK.md`
- `docs/verified-routes/FLIGHT-POINTS.md`
- `CURRENT.md` 指向的当前执行稿
- `docs/task-library/`中本轮任务已经存在的人工核验卡片

不要因为“我记得”跳过CURRENT、规则路由和错题本；但也不要为了一个局部问题一次性加载全部 `docs/rules/`、全部历史NEAT或全部任务卡。

人工任务卡片存在且版本、等级、队伍和路线上下文仍适用时直接复用，不重复计算。只有卡片缺失、适用条件变化、底层来源更新或用户实服反馈冲突时，才重新核验受影响任务；核验结果必须回写任务卡片。

## 1.2 当前角色状态

确认并记录：

- 五个角色各自等级/经验；
- 最低经验角色，作为唯一预算基准；
- 当前地图、营地或坐标；
- 当前炉石绑定点；
- 当前普通五人小队/团队状态；
- 当前任务日志关键任务；
- 已知每个角色之间的任务完成差异；
- 任务日志占用数；
- 最近一次实跑产生的新机制证据。

如果 Questie 当前历程只能代表一个角色，必须明确写“只能证明该角色状态”，不能外推五号完全一致。

## 1.3 状态冲突处理

证据优先级：

**用户当前实测 > 最新实跑记录/Questie当前状态 > verified route/observations > Questie数据库 > 公开社区资料 > 旧路线假设。**

发现冲突时先修正状态，再设计路线。

# 阶段2：先解交通问题，再设计任务顺序

这是强制前置步骤，不能等路线写完后再看飞行点。

## 2.1 读取已开启交通网络

以 `FLIGHT-POINTS.md` 为真值，列出当前能使用的：

- 已开启飞行点；
- 炉石；
- 飞艇；
- 船；
- 已验证直飞关系；
- 必须陆路首次开启的新节点。

未记录的飞行点按未开启处理，不能猜。

## 2.2 每次跨区必须比较交通方案

至少比较：

- 直接飞；
- 飞到最近已开启点＋短程骑马；
- 炉石＋飞行；
- 飞艇/船＋飞行；
- 全程陆路。

目标是**最大化可用飞行距离、最小化玩家实际骑马距离和中转次数**。

例如当前“加基森→蕨墙村首次开点”，因为陶拉祖已经开启，所以应先飞陶拉祖再陆路进入尘泥，不能让玩家从加基森全程骑过去。

## 2.3 新飞行点处理

路线第一次经过新任务中心时：

1. 明确写出飞行管理员位置/入口；
2. 五号分别开启；
3. 实跑确认后立即更新 `FLIGHT-POINTS.md`；
4. 把该点加入从这一动作开始生效的 `opened_flight_points` 状态；
5. 重新检查新节点是否产生新的直飞路线；
6. 对后续尚未执行的所有跨片区交通边重新比较交通方案，删除不再需要的旧中转/骑马段。

不得出现“飞行点已经开了，但路线仍沿用旧枢纽绕路”。

## 2.4 按任务时点重放飞行网络

飞行网络不是地图级静态清单，而是随路线推进逐步扩张的状态。设计/复审时必须从起点顺序重放：

1. 每个接取、交付、开飞行点、炉石绑定和转场动作后形成新的交通状态；
2. 对下一任务/任务块，记录当时已开启飞行点集合，而不是使用整图最终飞行点集合；
3. 凡下一段需要明显跨片区移动，至少比较：直飞、飞到最近点＋骑马、炉石＋飞行、其它系统交通、纯骑马；
4. 如果路线仍选择骑马，必须确认骑马在完整墙钟上更优，例如沿路有必须完成的生产性任务、飞行管理员绕远或落点更差；
5. 新飞行点一旦开启，对未执行后缀重复步骤2—4，禁止旧交通决策被冻结。

内部审计必须能回答：**“做到任务Q时已经开了哪些飞行点？Q→下一任务为什么不是飞？”** 玩家页面只显示最终采用的交通动作，不显示这套内部审计过程。

# 阶段3：建立完整任务候选集合

自动候选只能召回，不能证明完整。

候选集合必须取以下并集：

1. 当前任务日志；
2. 当前区域自动候选；
3. 当前已完成任务的直接后续；
4. 所有单前置、组合前置和跨地图前置闭包；
5. 当前营地及路线经过营地所有可接/可交任务；
   - 同一营地、同一时刻可接、已确定会做、且任务日志不会接近25个上限的任务，默认**一次接齐**；不得仅因攻略章节分段而人为拆成多次接取。
   - **NPC级首次接触检查**：第一次站到某个NPC面前时，必须检查该NPC当前所有可接任务；凡后续确定会做且日志有空间，全部当场接走，不能因为任务被写在后面的章节而留到第二次回来。
   - **交任务后二次扫描**：每次向NPC交任务后，在离开该NPC前必须重新检查其新出现的任务；刚被前置解锁、后续会做的任务必须立即接取。多个连续对话/交接应在同一次NPC访问中推进到当前可推进的最远节点。
   - 只有存在明确前置尚未完成、等级门槛、任务日志容量压力、任务互斥/阶段冲突，或该任务已明确排除时，才允许不接，并必须写明原因。
6. 目的地NPC及附近NPC任务；
7. 野外护送NPC、巡逻NPC；
8. 地面物体触发任务；
9. 掉落物右键触发任务；
10. 跨区引导/送信任务；
11. 当前等级暂缓、但后面会回访该地图的任务。

在前往洞穴、城堡、矿区、海岸、虫巢、营地等远端地点之前，再执行一次“同目的地聚合”：所有指向同一目的地的任务尽量同趟完成。

最终必须执行一次**遗漏复查**，而且不是只做任务ID差集：

`候选并集 -（路线纳入任务 + 明确跳过任务 + 明确延后任务）`

差集中的每一项必须被明确归类为：

1. **故意跳过**：已审计过，确实不值得做；
2. **明确延后**：有具体回访节点；
3. **顺路补回**：路线本来就经过同NPC/同地点/同目标区，额外成本接近零，之前只是遗漏——必须补回正文；
4. **真正未覆盖**：说明路线审计尚未完成，不能发布。

尤其要单独检查“白送型任务”：同NPC顺手接交、同一路上送信、同目的地对话、已经要去的任务点顺手完成、已经要杀的同一批怪额外带一个任务。像这类任务不能因为经验少、旧攻略没写或自动候选没召回就漏掉。

# 阶段4：逐项确认任务真实机制

每个准备进入主路线的任务必须先分类，不能只看任务标签或Questie坐标。

## 4.1 任务机制类型

至少区分：

- 共享击杀；
- 普通多数量任务物＋FFA；
- 每角色独立掉落/个人判定；
- Party Loot / 单命名任务物；
- 单尸多件掉落；
- 地面固定物；
- 固定容器逐号点击；
- 对怪使用任务道具；
- 护送；
- 事件/召唤；
- 命名怪刷新等待；
- 潜行/隐形目标、黄色非主动目标及其显形/主动攻击方式；
- 对话救援、事件触发、击杀触发与护送之间的真实区别；
- 洞穴/多层建筑/路径复杂任务。

对于`event`、`rescue`、潜行NPC、黄色非主动NPC或数据库`count_confidence`异常的目标，必须额外确认**目标可见性、阵营反应、玩家实际触发动作和所在楼层/入口**。不能把数据库`objective_type`直接翻译成“杀掉/点击/救援”。

## 4.2 FFA普通多数量任务物

当前实测规则：

- 五号总需求量仍要累计；
- 每具尸体只让一个当前需要物品的角色拾取一次；
- 不让五个角色依次检查同一尸体；
- 一具尸体可能掉多件任务物，按实际件数推进；
- 不能把“一只怪五个角色各拿一份”当默认机制。

不同任务若表现不同，必须单独记录，不能用一条泛化规则覆盖全部任务物。

## 4.3 不确定机制必须验证

如果某个任务的掉落/共享机制会显著改变路线价值：

1. 查本地 Questie/参考数据库；
2. 查公开 Classic/WotLK 社区讨论或任务资料；
3. 优先采用用户当前服务器实测；
4. 仍不确定时，把任务列为“未验证/可选”，不得计入保证经验。

## 4.4 刷新与目标等级

使用实际任务目标/掉落来源怪等级，而不是只看任务等级。至少确认：

- min / 常见区间 / max；
- 强制目标数量；
- 高等级目标是否可跳；
- 刷新密度；
- 是否存在明显优于散点的高密度刷怪区；
- 是否在洞穴；若在洞穴，必须确认入口、洞内主刷区、可循环路径和洞口补怪点；
- 命名怪是否需要等待；
- 从入口到目标的沿路敌对怪等级。

个人掉落任务如果同时存在地图散点与洞穴/营地密集刷新，必须先按最高密度路线估算任务时间，再评价掉率。首次实跑因为不知道密集刷点而产生的长耗时记录为学习成本，不能直接写成该任务固有长尾。

# 阶段5：先算“剩余边际成本”，再决定删不删已接任务

这是已接任务的强制审计。

## 5.1 区分沉没成本

对于已经接到、已经解锁、已经拿到稀有触发物的任务：

- 已支付的前置；
- 已支付的触发物掉落成本；
- 已支付的接取跑图；

全部视为沉没成本，不得再次计入“现在做这个任务还要多久”。

只算从当前状态开始的剩余成本。

## 5.2 按任务包而不是单任务计算

同一地图/同一圈的多个已接任务：

- 地图进入成本只算一次；
- 公共骑马路径只算一次；
- 重叠击杀只算实际总击杀量；
- 同一区域命名怪只算额外偏移/等待；
- 回城/交任务合并计算。

不能分别给每个任务都加一次“去菲拉斯20分钟”。

## 5.3 删除前执行反向替代测试

任何准备放弃的已接任务/任务包，都必须问：

> 如果其他任务都保持不变，删掉这批经验以后，为了达到同一个当前阶段终点，后面具体必须新增哪一项或哪一组任务？新增任务的剩余墙钟成本真的更低吗？

如果无法明确指出更便宜的替代任务，就不能仅凭“这张地图不在主轴上”删除已经解锁的高价值任务。

# 阶段6：组装并比较“区域任务块”

路线优化单位是**区域任务中心/连续任务包**，不是单只怪，也不是单个任务。

## 6.1 每个任务块的总成本

完整计算：

- 进入区域的飞行/炉石/骑马；
- 本地接任务；
- 本地骑马；
- 规定战斗；
- 个人拾取动作；
- 固定物逐号点击；
- 搜索/刷新；
- 洞穴/楼层/跟随风险；
- 返回交付；
- 离开区域；
- 对下一任务中心的最终位置价值。

比较指标概念上是：

`（确定任务经验 + 强制击杀经验） / 完整墙钟时间`

每次生成/重排可执行路线时，还必须按`docs/rules/timing-and-benchmarking.md`把上述成本落到**每个玩家逻辑步骤/自然任务块的预计分钟数与整段总时间**；路线没有分段估时和总估时不得发布。实跑后把实际墙钟与clean baseline成对写入`data/observations/route-timing-runs.json`，异常/学习时间单列，不能拿一次带失误的整段墙钟线性外推其它任务块。

怪物等级差是重要成本项，但不是机械禁区。

## 6.2 替代路线必须到同一里程碑

比较路线A和B时，必须把二者都推到同一个后续节点/等级，例如：

- A：留在当前地图完成整个块 → 到48级；
- B：转场10分钟 → 新地图完整块 → 到48级。

只有这样才能判断10分钟转场是否值得。

## 6.3 至少向后看一个任务块

不能只优化当前块。

必须检查：当前选择会不会让下一地图进入更理想的怪物等级带、减少后续高等级任务、减少一次跨大陆往返，或者反而造成回头路。

# 阶段7：经验闭合、无衰减校验与后半程反向裁剪

## 7.1 下界经验账 + 上界等级账

每个任务块同时维护两套账：

**下界经验账**用于证明能够达到阶段等级：
1. 精确任务奖励；
2. 任务规定强制击杀经验；
3. 探索、清路、误拉、随机额外击杀等按0进入保证预算。

**上界等级账**用于证明尚未交付的低等级任务不会进入经验衰减：
1. 当前角色真实经验；
2. 本轮确定任务奖励；
3. 强制击杀的合理高值；
4. 为个人掉落可能产生的额外击杀；
5. 首次探索新区域经验；
6. 当前角色休息经验可能额外提供的杀怪经验。

最低经验角色仍是“是否能达到目标等级”的唯一基准；但无衰减校验要看**可能升级最快的角色/最高经验上界**，因为任何一个角色提前越过任务等级+5都会在该角色上损失任务经验。

外域58→68发布路线前，必须为所有纳入全清的任务记录`任务等级 → 最晚满经验交付等级(任务等级+5) → 预计交付等级/上界等级`。任一任务上界可能超过截止等级，路线不得发布，必须重排交付顺序或地图循环。

## 7.2 结构变化重算；顺路补回不强制重算

如果是会改变地图顺序、任务块规模、进入等级或保证当前阶段闭合的**结构性增删**，仍然要把影响传导到当前阶段目标，检查后续进入等级和最终停止点。

但实跑中补回的“白送型/近零边际成本任务”不强制重新跑整条跨等级段理论模拟，例如：同NPC顺手交接、同一路上送信、同地点对话、同一批怪顺带完成。此类任务直接记为额外实际经验即可，不为了几百到几千经验反复维护一套越来越失真的预测表。

每完成一个区域任务块，以用户实跑的**最低号实际等级/经验**覆盖旧预测，作为下一块的新基线。多出来的经验留到后半程再从尚未开始的低效率任务中裁掉。

## 7.3 多出来的经验用于删后面的差任务

如果前面出现更高效的新经验：

优先从**尚未开始的后续任务**中删除边际成本最高的一组，而不是让角色最后多出一大截经验。

已经进入并正在高效执行的区域块，不因为中途达到某个等级就机械撤离。

# 阶段8：任务日志与执行细节检查

## 8.1 任务日志容量

记录：

- 当前占用；
- 本区域链展开峰值；
- 默认预留至少5格；
- 跨区任务标注“必接 / 可提前接 / 不要占格”。

## 8.2 玩家可执行性

输出前按玩家正在游戏中边走边看的视角检查：

- 下一步从哪里出发；
- 飞到哪里/骑到哪里；
- 是否应先用炉石；
- 新飞行点在哪里；
- 沿路做哪些任务；
- 玩家可见任务引用必须至少写完整`《任务名称》`；**任务编号永远不得裸写，也不得代替任务名**。Route Atlas等紧凑执行页可以不重复展示ID；若玩家可见文案中确实出现ID，则必须写成`《任务名称》（ID）`。像“交11169”“11207是货物”“595→597→599”全部视为格式错误；
- 发布前对当前执行稿执行一次裸任务ID扫描：凡玩家可见文案出现Questie任务ID但没有与完整任务名绑定，必须清零后才能交付；结构化数据和内部审计仍保留ID用于精确定位；
- 目标坐标紧跟地点名；
- 回营地逐项交什么、接什么；
- 哪些明确不要接/不要做；
- 是否需要五号逐号操作；
- 什么时候离开这个区域；
- 每一个玩家可见步骤摘要是否真的在说“这一段要做什么”，而不是在解释路线设计；
- 每一条任务备注是否真的帮助完成任务，而不是在解释Questie缺陷、人工锚点、候选覆盖、为何合并/排序或测试结论。

不能要求玩家自己把任务列表重新组织成路线，也不能要求玩家在攻略里过滤掉内部审计信息后再寻找真正动作。

## 9.1 对抗式复审不是润色

成稿后的复审必须暂时摒弃写稿时形成的解释，从玩家当前点冷启动阅读。复审目标是主动推翻路线，而不是证明原稿正确。至少逐任务攻击：可接状态和完整前置、预计交付等级和经验衰减、目标怪等级与密度、五开掉落/共享机制、真实地形和新手入口、同路线重叠是否成立、交付后续是否闭合，以及删除或失败后的当前阶段替代路径。

发现问题时先修正人工任务卡片的当前有效事实，再修改攻略正文；旧值和错误原因追加到纠错流水。只改措辞、不改任务库事实，视为复审未完成。

# 阶段10：实跑反馈后的更新流程

用户反馈任何一个新事实后，先判断影响范围：

### A. 仅局部机制变化
例如某任务掉率、FFA、命名怪刷新不同：

- 更新对应 observations/实跑记录；
- 重算该任务块；
- 重算受影响的后续经验闭合；
- 不无理由推翻前面已经验证的地图轴。

### B. 新飞行点/新直飞关系

- 立即更新 `FLIGHT-POINTS.md`；
- 从开点动作开始更新`opened_flight_points`并向后重放交通状态；
- 重算后续所有尚未执行的跨片区交通边，不只检查下一跳；
- 逐条检查是否出现“当时已经可飞，但旧稿仍写骑马/绕Hub/先炉石到无任务Hub”的情况；
- 删除旧中转。

### C. 当前等级/经验偏差

- 以最低号新经验作为新基准；
- 保留已验证路线机制；
- 从尚未执行的下一任务开始重新做经验闭合和后半程裁剪。

### D. 新错误属于通用错误

- 追加/更新 `ERROR-BOOK.md`；
- 若形成稳定规则，从 `docs/rules/README.md` 路由到对应永久规则文件；只有流程顺序本身变化才修改本 SOP；
- 不只修当前攻略正文。

# 一句话原则

**先确认真实当前状态和交通网络 → 完整召回任务 → 验证真实机制 → 按当前阶段目标组成区域任务包 → 比较完整替代序列或单地图全清顺序 → 经验闭合到当前阶段终点 → 最后才写玩家攻略。**
