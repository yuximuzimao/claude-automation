# 首组五开飞行点进度

更新时间：2026-08-25（UTC+8）

## 使用规则

- 只有用户明确确认开启，或首组实跑现场/当前执行记录明确确认可用的点，才标记为“已开启”。
- 未记录的飞行点一律按“未开启”处理，路线不得假设可直飞。
- **每次跨区域规划前必须先读取本文件，用现有飞行网络最大化飞行距离、最小化陆路距离；不得先写陆路方案再事后检查飞行点。**
- 飞行点状态按路线时间推进：某点只有在实际开点动作之后才进入`opened_flight_points`；每个后续任务/任务块都使用当时已开启的集合做交通判断，不能拿整图最终已开点状态倒推前半段。
- 新到主城、营地或任务中心时，优先让五个角色分别开启飞行点，再继续交任务或离开；一旦开点，必须从这一时刻向后重算尚未执行的跨片区交通，检查是否已有“可以飞却还在骑马/绕旧Hub”的步骤。
- 飞艇、传送门和陆路到达不等于该地点飞行点已经开启。
- 后续新号复用路线时，凡主路线经过或只需极短偏移即可到达的飞行点，都在第一次路过时开启，以删除首组补点产生的额外陆路。

## 首组补点原则

历史补点只解释首组为何拥有当前网络，不作为下一批固定路线。以后新号在第一次自然经过对应Hub时立即逐号开点；每次新开点后只从该时刻向后重算尚未执行的交通边，不倒推修改此前步骤。
