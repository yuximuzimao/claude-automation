# 路线规划错题本

用途：记录已经造成漏任务、额外往返、错误等级判断或无效搜索的规划错误。每次生成、修订或审计路线时，必须先读本文件，并在交付前逐项执行“固定复查清单”。自动候选、Questie区域列表和已有任务日志都只能作为输入，不能单独证明任务覆盖完整。

## 固定复查清单

每次路线交付前必须完成以下检查；任何一项未检查，路线只能标为草稿：

- [ ] **当前状态**：已读取`CURRENT.md`和当前执行稿；最低号等级/经验、当前位置、炉石、小队状态、关键任务差异已确认。
- [ ] **交通网络**：已读取`FLIGHT-POINTS.md`；跨区方案已比较直飞、最近飞行点＋骑马、炉石、飞艇/船和全陆路；没有忽略已开飞行点，也没有沿用失效中转。
- [ ] **候选并集**：合并自动区域候选、当前任务日志、已完成任务、当前与途中NPC全部可接任务、物品触发任务、固定物体触发任务、护送任务和跨区引导任务。
- [ ] **任务链闭包**：检查`preQuestSingle`、`preQuestGroup`、直接后续和交付后立即出现的下一环；列出无法纳入的链并说明原因。
- [ ] **同NPC检查**：到达或即将离开的每个任务中心，枚举该NPC及附近NPC当前可接、可交、交后新出现的全部任务，不能只检查自动候选中已有的任务。
- [ ] **同目的地聚合**：前往洞穴、城堡、营地、海岸、矿区或远端区域前，检查所有指向同一目的地或同一路线的任务。
- [ ] **现场任务检查**：单独核对野外护送NPC、巡逻NPC、地面物体、掉落物右键触发和不在常规任务中心内的任务。
- [ ] **回访聚合**：路线以后再次经过同一地图时，把当前因等级、命中率或前置不足而延后的任务写到明确回访节点，禁止只写“以后顺路做”。
- [ ] **任务机制分类**：共享击杀、FFA普通任务物、个人独立掉落、Party Loot、单尸多件、固定物、逐号使用物、护送、事件、命名怪刷新已区分；未知机制不得直接套通用规则。
- [ ] **掉率与刷新密度**：随机掉落已检查数据库/公开讨论/本服实测；击杀/掉落任务按集中刷新区设计，不按散点覆盖率画大环线。
- [ ] **沉没成本审计**：已接/已解锁/已拿触发物的任务只算剩余边际成本；同区域多个任务共享一次转场和公共路线成本。
- [ ] **反向替代测试**：任何准备放弃的已接任务都已把“保留/放弃”推到同一后续里程碑比较；未满级且存在经验缺口时明确替代任务，满级时直接比较损失收益、后续链和节省墙钟，不强行寻找“替代经验任务”。
- [ ] **区域块比较**：候选路线按完整区域任务块比较到同一后续里程碑，至少向后看一个任务块；怪物等级差不是唯一筛选条件。
- [ ] **遗漏对账**：将“候选并集任务ID”与“路线任务ID＋明确跳过ID＋明确延后ID”做差集；差集逐项分类为“故意跳过 / 明确延后 / 顺路补回 / 真正遗漏”。凡同NPC、同路线、同地点、同目标怪的近零边际成本任务，如果不是明确故意跳过，必须补回正文。
- [ ] **阶段闭合**：结构性增删必须重新验证当前阶段目标。未满级时重算等级/经验、衰减风险和后半程；满级时重算XP折金、直接金币、装备/物品价值、后续链与总墙钟。近零边际成本的白送型补回不强制重跑整套跨图模型。
- [ ] **实际交付状态**：未满级时任务经验按预计交付等级重算并用用户最新等级覆盖旧模拟；满级时按满级收益口径入账。无论是否给完整经验，都要另外比较五开个人需求、掉率和真实墙钟。
- [ ] **后半程裁剪**：仅在未满级且前段新增经验造成真实余量时，从尚未开始的后续任务中优先审查边际成本最高的任务包；满级清图不因“经验多了”删除任务。
- [ ] **日志容量**：记录当前任务日志占用和链展开峰值，默认预留5格；提前接取任务必须标为必接、可提前接或不要占格。
- [ ] **最终交接**：达到路线终点时，检查当前位置可顺手接取的下一阶段引导任务；不值得专程绕路的任务也要明确写成“不专程回接”。
- [ ] **玩家可执行性**：飞行/骑马起点、新飞行点、任务完整名称、方向、坐标、逐号操作、返回交接和明确跳过项均已写清；Route Atlas等紧凑执行页可省略重复ID，但任何出现的ID都必须与完整任务名绑定，绝不能用ID代替任务名；玩家无需自己重新组织路线。
- [ ] **攻略第一目标复审**：单独逐条阅读玩家可见步骤摘要、动作和任务备注；只保留导航、任务执行、避免失败、五开现场操作和离开条件。Questie/数据库缺陷、人工锚点、候选覆盖、为什么合并/排序/不折返、测试与实现解释全部迁出玩家执行稿。此项不能被“自动测试已通过”替代。
- [ ] **永久规则一致性**：本轮若新增/修改/提升长期规则，已按`docs/rules/README.md`检查永久性、唯一owner、重复/冲突、当前状态泄漏、项目目标一致性和实现/测试同步；没有把本次错误案例直接当成新永久规则。
- [ ] **当前阶段停止点**：明确本轮是达到等级门槛、完成单地图一次性全清，还是进入下一张地图；停止条件必须以`CURRENT.md`当前目标为准，禁止沿用历史停止线。

## 错题001：自动区域候选漏掉野外护送《回家》（4770）

- 日期：2026-08-03。
- 现象：30→35千针完整路线初版依赖`data/routes/world-candidate/*/route.json`等自动候选做覆盖审计，但《回家》（4770）没有出现在任何自动候选目录中，导致路线和经验预算漏掉该任务；用户提醒后才补入。
- 根因：自动候选以区域分类、常规任务NPC和已索引任务为主，无法保证覆盖野外护送NPC、跨区域归属、特殊分类、物品/物体触发及现场任务。把“自动候选未出现”错误解释成“该任务不存在或不属于本路线”。
- 正确做法：自动候选只作为召回入口。经过风巢高地、波卡·雨山等现场NPC时，必须反查NPC全部任务、前后任务链和现场可接状态；所有自动候选外任务进入人工补充清单。
- 本次修正：《回家》（4770）并入收集双足飞龙蛋的同一路线，千针本地核心任务经验由73000修正为74380，30→35完整路线任务奖励由197260修正为198640，静态缺口由2371缩小为991。
- 防复发检查：每次生成路线后执行“现场任务检查＋遗漏对账”，并在审计中单列“自动候选外任务”。

## 错题002：同一远端目的地只带了一项任务

- 日期：2026-08-02。
- 现象：第一次前往敦霍尔德只安排《通缉：辛迪加成员》（549），没有同时检查并接取同地点的《拯救行动》（498），交付后被迫再次往返。
- 根因：只围绕用户当前任务日志和单条任务链规划，没有枚举当前营地全部可接任务及同目的地支线。
- 正确做法：任何远端区域出发前执行“同目的地聚合”，同时检查已接任务、当前可接任务、交付后立即出现的后续以及邻近建筑内任务。
- 防复发检查：固定复查清单中的“同NPC检查＋同目的地聚合＋任务链闭包”。

## 错题003：返回任务中心时漏列可交任务

- 日期：2026-08-02。
- 现象：返回乱风岗交《异型卵》时，路线没有同时列出可交的《清除半人马》，导致交付状态不清晰。
- 根因：按单条任务叙述返回流程，没有在每次回到任务中心时重新枚举全部可交任务。
- 正确做法：每个“返回营地/主城/任务中心”地点块都必须列出本轮全部可交、可接后续和应保留任务。
- 防复发检查：固定复查清单中的“同NPC检查＋最终交接”。

## 错题004：把分散坐标连成大环线，忽略集中刷新点

- 日期：2026-08-04。
- 现象：闪光平原《含盐的蝎毒》（1104）、《硬化龟壳》（1105）和《减轻负重》（1176）被规划成沿盐湖外围逆时针绕圈。实跑发现乌龟、食腐鹫和蝎子各有明显集中区，大环线在稀疏区浪费大量时间，三种个人掉落成为本晚最大耗时块。
- 根因：把Questie散点坐标当成路线节点，只优化地图覆盖，没有按怪物刷新密度、同类集中程度和五号个人掉落需求设计刷怪路线。
- 正确做法：三个任务分别直达同类目标最密集的成片区域；清完一类再切下一类，缺口只回对应集中点补，不绕完整盐湖。
- 防复发检查：固定复查清单中的“刷新密度验证”；未实跑的击杀环线必须标为候选，并在首轮记录集中点坐标和实际用时。
- 复发：2026-08-08。《群龙之首》（1169）两类个人任务物显示约25%掉率，龙类散布范围很大；若按Questie全散点追怪会明显变慢。用户实跑确认地图偏南有一块目标相对集中，后续固定优先在该密集块循环清，不按全图覆盖设计。

## 错题005：未验证任务的组合前置，提前写成首次到场可接

- 日期：2026-08-04。
- 现象：路线把《流放者马特克》（1106）写成首次抵达赛车场即可接取。Questie历程实跑显示，03:37先完成并交付《硬化龟壳》（1105）和《含盐的蝎毒》（1104），随后才接到1106。
- 根因：虽然规则要求检查`preQuestGroup`，但正文编排时仍按NPC任务列表误判为无前置任务，没有验证“多个前置都完成后才出现”的实际可接状态。
- 正确做法：首次到赛车场只接1104、1105、1176和1111；1104与1105都交完后再接1106，同时接1107。
- 防复发检查：任务链闭包不仅要查单前置，还要把组合前置写进玩家执行顺序；任何交付后新出现的任务不得提前列入“到场接齐”。

## 错题006：新飞行点开启后仍沿用旧枢纽中转

- 日期：2026-08-04。
- 现象：悲伤沼泽任务结束后，路线写成“斯通纳德 → 格罗姆高 → 藏宝海湾”。首组实跑确认斯通纳德已经可以直接飞藏宝海湾，经格罗姆高属于多余中转。
- 根因：路线只验证了各飞行点已经开启，没有在新节点开启后重新检查起点到目的地的实际直飞列表，机械沿用了既有东部王国枢纽假设。
- 正确做法：每次首次开启飞行点后，立即检查当前目标是否出现直飞航线；以游戏内飞行列表为真值，删除不再需要的中转。
- 本次修正：30→35路线、飞行点文档和通用规则均改为“斯通纳德直接飞藏宝海湾”。
- 复发：2026-08-07。用户询问“蕨墙村怎么去”时，回答直接引用当前路线正文，没有先读取`FLIGHT-POINTS.md`，因此给出“从加基森全程骑马”的劣化方案；实际上陶拉祖早已确认开启，应“加基森飞陶拉祖＋短程陆路”。同时发现`FLIGHT-POINTS.md`没有持续回填后续已确认的莫沙彻、加基森节点。
- 复发根因：交通检查没有成为回答导航问题的前置硬门禁，且飞行点总表没有在实跑后即时维护。
- 再次复发：2026-08-17。北风路线虽然已经在流程中开启战歌、牦牛村、琥珀崖等飞行点，但后续交通仍保留了“牦牛村系统鸟回战歌”“琥珀崖先回战歌再转牦牛村”等旧方案；其中最终琥珀崖收尾时战歌已经没有任务，琥珀崖与牦牛村又都已开点，应直接飞牦牛村。说明“开点后只检查一次直飞”仍不够，必须按任务时点重放动态飞行网络。
- 再次复发根因：路线状态只记录“某点已开”，没有让`opened_flight_points`成为后续每个任务节点的动态状态；交通方案在早期排定后被冻结，后续新开点没有向后触发重算。
- 再次复发：2026-08-18。北风步骤57把“Transitus Shield系统鸟回琥珀崖”后续误写成“落地直接转乘博古洛克”，并把进入博古洛克的边标成`taxi`；但博古洛克飞行点要到下一步抵达前哨站后才开启。修正为“系统鸟只到琥珀崖，随后沿道路骑马北上博古洛克，抵达再开点”。同轮按任务时点自动重放北风与龙骨荒野全部系统航线，未开目的地违规与未知目的地均为0。
- 同日追加纠错：第一次走廊复查把Questie的`exclusiveTo`误读成“前置”，错误声称必须先接11591《钢腭的车队》才能接11592《攻击！》/11593《亡者的尊严》/11594《让他们安息》。首组实跑直接证明三条战场任务可在未接11591时正常接取并完成；正确语义是11591属于可选面包屑，后三条一旦接取/完成会使11591失去可接资格。当前从零路线因此删除11591，并把三条战场任务前移到琥珀崖→博古洛克必经走廊顺路完成。
- 防复发补充：`exclusiveTo`只能按“互斥/替代可接关系”解释，不能当作前置。任何Questie关系字段在用于改变路线顺序前，都要与`pre_any`/`pre_all`/`parent_active`分开核对；一旦用户实跑与静态解释冲突，以当前服务器实跑为最高优先级并立即撤销旧推论。
- 再次复发根因：动态飞行网络虽然已成为设计规则，但尚未有发布门禁验证“每一条`taxi`/系统航线边的目的地在该边发生前已经进入`opened_flight_points`”；玩家可见文案与transport元数据也可能同时保留错误假设。
- 防复发检查：任何跨区/营地导航问题至少执行`ROUTE-DESIGN-PROCESS.md`阶段0、1、2、8；先读`FLIGHT-POINTS.md`再给路线。新飞行点或已验证节点一旦确认，必须当次回填总表，并从开点时刻向后重放所有未执行任务的飞行点状态；逐条检查“此时已开哪些点、为什么这一段不用飞”，重新计算直飞/最近飞行点/炉石/陆路方案。Route Atlas发布前额外运行`audit_route_atlas_flight_state.py`，要求系统航线目的地未知数=0且未开目的地违规数=0；文案与transport必须同时通过。

## 错题007：把阶段等级目标误解为顺路任务的停止线

- 日期：2026-08-04。
- 现象：最低角色达到35级后，初步结论直接停止《坚硬的尾鳍》（1107）、《兄弟》（5361）和猎虎后续，只保留地精固定链。用户指出这些任务并非孤立兜底，其中一部分与荆棘谷收尾、凄凉之地入口和后续地图自然重合；提前删除会减少进入加基森/菲拉斯前的经验储备。

## 错题008：只核对直接前置，误把未完成跨地图前置的任务写成现场可做

- 日期：2026-08-07。

## 错题017：玩家逻辑步骤为了压缩数量而过度聚合

- 日期：2026-08-16。
- 现象：北风牦牛村后半曾把多轮Hub交接、泵站外出、天灾外衣和腐化土地压在同一逻辑步骤；龙骨荒野更严重，23个逻辑步骤中存在一次覆盖十几个甚至十九个几何点的长链，玩家展开后需要连续阅读大量交接、外出和再次交接。反向审计还发现赞加、纳格兰仍没有显式`stepGroups`，前端实际退化为“一个几何点就是一步”。
- 根因：设计时过度追求减少步骤按钮数量，把“连续路线”误等同于“必须属于同一个玩家步骤”，没有把玩家在Hub完成一轮交接、开始下一轮外出当作认知边界；早期地图也没有在逻辑步骤模型上线后做结构迁移。
- 正确做法：几何路线与玩家逻辑步骤独立维护。连续局部扫图可以合并；一旦出现多轮Hub交接与多轮外出，优先在Hub交接完成或下一轮外出开始处拆段。批量交接本身允许单独成一步。正式Route Atlas每张地图必须显式维护`stepGroups`，不得依赖point=step回退。
- 本次修正：从赞加开始统一回审。赞加43个几何点整理为13个玩家步骤；纳格兰14点整理为4步；北风221点由58步重新审到68步；龙骨193点由23步拆为51步。没有改变任何地图几何走法，只重划玩家操作边界和压缩过长摘要。
- 防复发检查：Route Atlas发布/大改后导出纯玩家视图冷读；检查是否有单步同时跨多轮交接和外出、是否出现六七行以上仍无自然边界的长块，并验证所有地图`stepGroups`连续覆盖全部几何点且无缺口/重叠。数字只作报警信号，不把固定点数上限当成机械拆分规则。

## 错题018：把副本任务重新混入五开户外升级主线

- 日期：2026-08-17。
- 现象：北风考达拉Route Atlas错误加入《他们丝毫不感到羞愧吗？》《延缓灾难》《苏醒》《战争的囚徒》四条魔枢副本任务，并安排“一次魔枢”执行/回收；用户明确指出当前五开练级不打副本。
- 根因：北风foundation生成器把`is_dungeon=true`显式分类成`include_leveling_dungeon`，并且视频参考组校验又错误要求视频中出现的魔枢任务必须继续留在scope；旧项目“副本与户外升级路线分开”的边界没有进入该新生成器的硬门禁。
- 正确做法：当前五开户外升级主线默认排除所有`is_dungeon`/raid任务，仅保留任务知识；只有用户明确开启专项副本路线时才单独建模。视频只提供参考，不能反向强迫被策略排除的任务进入路线。
- 本次修正：四条魔枢任务全部改为`exclude_dungeon_or_raid`；考达拉完成《触动陷阱》后直接回永生之盾乘系统鸟转北部；foundation新增`no_dungeon_or_raid_included`对抗校验并已PASS。
- 防复发检查：任何地图foundation/Route Atlas发布前都检查执行scope中`is_dungeon`/raid数量必须为0，除非CURRENT存在用户明确开启副本专项路线的状态。

## 错题019：路线有成本模型但发布稿没有固定分段估时和总估时

- 日期：2026-08-17。
- 现象：项目早已存在逐任务墙钟模型和五开时间参数，但北风Route Atlas发布时没有把每个玩家任务块预计时间与整段总时间固化；复盘时一度错误用已跑任务数/剩余任务数做线性外推，无法用于以后同路线批次的效率比较。
- 根因：旧估时算法主要留在35—55脚本和历史analysis，没有提升为当前Route Atlas发布硬门禁，也没有统一保存“预测baseline + 实际墙钟 + 异常成本”的长期观测文件。
- 正确做法：所有可执行路线固定使用`T_move + T_objective_service + T_accept_turnin + T_wait + T_special`逐任务/逐块估时；发布时同时保存每个逻辑步骤/自然任务块的预计时间、整段/整图总时间和合理区间。实跑必须用相同终点比较clean baseline与实际墙钟，迷路/学习/死亡/竞争等异常单列。
- 本次修正：新增`docs/rules/timing-and-benchmarking.md`、`data/observations/route-timing-runs.json`和`scripts/estimate_route_atlas_timing.py`；今晚同终点clean baseline重算为279.5分钟，实际317.85分钟，超额38.35分钟（13.72%）；北风第48—68步户外剩余逐任务中心值220.1分钟。
- 防复发检查：`ROUTE-DESIGN-PROCESS.md`发布门禁要求分段估时+总估时齐全；禁止以任务数、步骤比例或单一XP/h线性替代逐任务成本模型。
- 2026-08-17补充前端固定契约：不仅后台要“算过”，四张现有Route Atlas都必须把地图级总估时直接写到右上状态卡，并把每个`stepGroup`估时写到HUD第二行；右上不允许“炉石与时间/当前状态”等小标题，直接炉石一行、时间一行；旧“本段 起点→终点 (x,y)”固定槽位废弃。炉石按真实绑定链显示，可靠局部实测必须标scope，无可靠实测则不显示实测行。`build_route_atlas_workbench.py`和`tests/test_route_atlas_timing_ui.py`现作为自动防回归门禁。

## 错题020：HUD只显示摘要/末点动作，完整接交任务被藏到下层

- 日期：2026-08-17。
- 现象：北风第48—51步的数据点本身已经记录多数完整接交动作，但玩家实际看地图左上HUD时只能看到被简写的步骤信息，出现“交任务/推进后续”却不知道具体交什么、接什么；第50步还没有在摘要里明确“法师塔二楼”，导致第49步结束后现场感觉任务链断掉。
- 根因：逻辑步骤上线后，HUD仍沿用旧的单停靠点展示假设，没有把`stepGroup.start..end`覆盖的全部point action作为当前步骤的主执行内容；同时个别`stepGroup summary`过度压缩，把任务链交接写成泛化短句。
- 正确做法：HUD当前动作区必须逐条显示当前逻辑步骤内全部停靠点的完整动作，不能用summary或最后一个点替代；涉及接取、交付、连续后续、建筑/楼层时，任务名和实际位置必须直接写出来。summary只做概括，不承担唯一执行信息。
- 本次修正：第49—51步摘要补齐完整接交任务名，第50步补成“法师塔二楼·诺曼提斯”；`build_route_atlas_workbench.py`构建时固定注入整组point action到HUD，`tests/test_route_atlas_workbench.py`新增防回归检查。
- 防复发检查：纯玩家视角复读时必须只看最终页面/HUD确认“当前步骤需要做的每一次接、交、任务链推进是否无需展开其它区域就能执行”；多点逻辑步骤若HUD未逐条列全动作，直接判发布失败。

## 错题021：估时器解析玩家动作时漏掉显式执行任务

- 日期：2026-08-20。
- 现象：龙骨步骤11《刨冰 → 柔软的包装》曾被估为约4分钟，`objectiveMinutes=0`，而首组《柔软的包装》本身实测就需要25分钟；进一步重算发现北风、龙骨、灰熊、祖达克都存在同类系统性低估。
- 根因：`objective_names_for_group()`先把`《任务名》`从句子中剥离，再搜索任务执行token；`做《任务名》`剥离后只剩“做”，而旧token依赖`做《`，导致最常见的显式执行语句被判成没有任务目标。
- 正确做法：在剥离标题前识别显式`做《...》`，并把玩家动作明确执行/完成的任务与估时器`objectiveTasks`做语义对账；另一方面，`沿路/顺手/自然`背景任务与其它前台任务共享目标时只计真实新增边际成本，不能为了修漏算而重复收费。
- 本次修正：修复通用解析器；用《柔软的包装》25分钟用户实测（Journey接取→完成26.68分钟）校准任务服务时间；四张诺森德正式地图全部重算；`tests/test_route_atlas_timing_ui.py`新增所有显式`做《...》`零漏识别的回归门禁。
- 防复发检查：任何动作解析规则修改后必须重算所有使用同一估时器的正式地图；发布前显式执行任务与`objectiveTasks`差集必须为空。永久规则见`docs/rules/timing-and-benchmarking.md`第2.1节。

## 错题022：覆盖审计后发现完整任务链，却按发现顺序追加到路线尾部

- 日期：2026-08-25。
- 现象：冰冠路线已经推进到中西部/南部后，覆盖差集才暴露布雷登布莱德`《勇气的传说》→《黑暗中的光明》`整条链。若按“最后发现就最后补”的方式处理，会把本应从北伐军之峰自然展开的东部跨图链追加到苦难高地收尾之后，制造一次人为的西/南→东大回头路。
- 根因：把覆盖审计当成“漏项补清单”，而不是重新打开任务首次解锁节点后的受影响路线窗口；同时地图foundation只按`assigned_zone`检查依赖，漏掉归属龙骨荒野但实际位于冰冠链中间的`《达莉亚之泪》`，会产生“地图候选100%覆盖但真实链断一环”的假PASS。
- 正确做法：后发现的任务链必须回到第一个真实解锁节点做插入式重排；按每一环自然Hub/交通/地理拆段，完成后再接回原后缀。跨地图唯一前置/直接后续必须纳入当前链闭包。只有依赖本身或成本比较证明末尾就是最优合法位置，才允许最后执行。
- 本次修正：`《勇气的传说》`仍在第一次到北伐军之峰时接走；整条布雷登布莱德救治链插入`《提里奥的尝试》`传送回北伐军之峰之后、奥尔杜萨持续向西扫图之前，使该链从北伐军之峰出发并最终回到同一Hub，再无缝接回西向主路线；`《达莉亚之泪》`作为跨图桥接任务纳入冰冠foundation闭包。
- 防复发检查：覆盖差集每补回一条后续链，必须记录“首次真实解锁节点→候选插入窗口→后缀状态重放”；禁止存在“因为是最后审计发现所以追加到最后”的理由。foundation依赖审计必须能跨`assigned_zone`追踪唯一硬前置。

## 使用规则

- 新错误先追加到本文件，不删除旧案例。
- 同一错误再次发生时，在原错题下增加复发日期、触发条件和修正规则，不另写含义重复的条目。
- 稳定通用规则从`docs/rules/README.md`路由到对应永久规则文件；具体实跑机制写入对应`segments/`、task-library或`data/observations/`。
- 发布审计记录/NEAT必须注明本次已执行错题本复查，并记录自动候选外任务、明确跳过任务和未来回访任务；玩家路线正文只保留会改变实际执行的跳过/回访动作，不得加入“已完成审计”之类内部证明文字。
