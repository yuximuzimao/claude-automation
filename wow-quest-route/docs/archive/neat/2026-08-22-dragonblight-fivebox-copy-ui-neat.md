## 玩家文案结构：本轮形成的最终方向

### 1. 流程明细只承担“路线顺序”

- 地点/NPC标题不再写“第二次 / 第三次 / 第几轮 / 回收 / 收尾”等路线作者过程词；只写真实地点、层级、NPC或目标。
- 同一地点/NPC的交接在一行内用`→`串联，例如：`斯古莉 → 交 A → 接 B`。
- 从交接进入实际做任务时另起一行，用`↳`制造明显视觉断点，例如：`↳ 做 B`。
- 普通任务目标位置若Questie已经足够明确，流程中只需要任务名，不强行重复坐标/地点；洞穴、楼层、入口、水下、悬崖等Questie不足以表达的情况仍必须在备注说明。
- 交/接任务发生转场时必须写真实地点/NPC；尤其跨Hub、跨建筑、跨楼层、炉石、系统鸟、传送等不能省略。

### 2. 备注按任务归属拆分

- 单任务攻略必须以`《任务名》`独立分块，不能把多个任务说明一句接一句堆成同一段。
- 备注保留真正影响现场操作的信息：入口、楼层、任务物用法、共享/个人机制、同尸拾取、失败条件、等待/刷新、容易杀错或漏做的动作。
- 只有真正同时约束整个步骤的共同楼层/地形/机制才允许出现步骤级备注。
- “跟着路线就不会折返”“本段任务都在同一区域”“任务备注本来就要看”等不改变现场操作的信息一律删除。

### 3. 当前认可的视觉语义

第45步已做样板，用户认可方向如下：

- 地点：浅蓝色普通文字。
- NPC：偏白、稍粗普通文字；与地点颜色不同。
- 地点/NPC都不加下划线、边框、底色，也不做点击定位等附加交互。
- `交 / 接 / 做`三个字保持普通文字，不加标签效果。
- 流程里的任务名去掉`《》`，使用下划线并按动作着色：
  - 交任务：绿色；
  - 接任务：黄色；
  - 做任务：蓝色。
- 同一动作多个任务之间用`、`分隔。
- 备注中的任务名暂时继续保留`《任务名》`。
- 备注里的关键楼层/危险词（例如`顶层 / 一层 / 地下 / 不要杀死 / 不要跳下 / 先停手`）使用普通红色文字，不做胶囊/边框/大色块。
- 页面整体保持克制，避免把每类语义都做成标签造成新的视觉噪音。

### 4. 明确放弃的方案

- 地点/NPC点击后地图脉冲闪点：连续多版在当前页面没有实际显示效果，收益很小，用户明确放弃。相关CSS、JS、测试和长期规则已经删除；后续不要恢复。
- 龙骨底部颜色图例、固定“五开待实测”解释、提醒“任务备注需要看”等常驻说明：无行动价值，已经清空；没有动态信息时允许区域完全留空。
