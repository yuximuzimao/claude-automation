# 赞加沼泽：从R4回滚的约束门控重建 v1

日期：2026-08-14
状态：约束正确性草案；用于替代R5以后旧插入顺序的重建分支。尚不是最终从零执行稿，也尚未覆盖用户仍在变化的当前实跑状态。
基线：R4任务/目标簇状态；R4炉石不冻结。
规则冲突审计：`docs/archive/analysis/2026-08-14-route-atlas-constraint-gate-conflict-audit.md`。

## 1. 为什么从R4开始

R5第一次插入9726《既然我们是朋友......》时，只验证了：

- 任务链`9726 → 9727`；
- 舒特/血鳞区/莉萨奥之间的局部几何；
- 服务时间与炉石冷却。

当时没有验证Questie `requiredMinRep`。

现在已确认：

- 9726：Sporeggar阵营970声望`>=3000`；
- 9727：`>=3000`；
- 9729：`>=42000`；
- 9919：`>=0`；
- 9806/9807：`>=0`；
- 9739/9742：`<3000`；
- 9743/9744：`<3000`；
- 9808/9809：`<3000`。

所以R5的“A9726直接插到第一次孢子村/舒特停靠”是第一处确定的Availability硬错误。R4因此是声望错误前最后一个可用的**任务插入基线**。

注意：R4的`炉石1→萨布拉金`不再视为合法冻结事实；从零角色尚未自然绑定萨布拉金时，该交通边必须重新求解。

## 2. 第一轮候选淘汰记录

### 候选：R4后直接A9726

结果：`FAIL availability`

原因：只有当前Sporeggar声望`>=3000`才可接。旧R5没有这一状态。

处理：不是永久删除9726，而是进入`DEFERRED_UNTIL_REP_3000`；每次阵营970状态变化后重新枚举。

### 候选：把9729继续留作“现场可见就做”的普通分支

结果：普通练级路线下`FAIL/DEFERRED availability`

原因：9729要求阵营970声望`>=42000`。它不应污染普通赞加线性路线或制造护送/水泵死节点。

处理：从普通路线移出，仅作为`rep>=42000`条件模块。9720沼光湖泵必须有不依赖9729的主体完成位置。

### 候选：像旧R19一样把9739/9743拖到西部后半段再补

结果：可能`FAIL availability`

原因：这两条及其后续要求声望`<3000`。一旦前面其它孢子村任务把声望推过3000，旧R19/R20位置会直接消失。

处理：9739/9743提升为**声望解锁前置服务包**，必须在跨3000前优先插入。

### 候选：像旧R28一样第一次自然经过法恩森就无条件A9919

结果：声望<0时`FAIL availability`

原因：9919要求声望`>=0`。

处理：法恩森仍是几何最佳A点，但动作变成`REP_GATE_0`后的候选；未到0时继续低声望服务，不伪造A9919。

## 3. R4后新的第一段：先做低声望法恩森/孢殖林包

R4中莉萨奥链的这一段保留为几何骨架：

`莉萨奥 → 法恩森 → 孢殖林调查/西南巨人区 → 法恩森 → 莉萨奥`

但任务内容改为：

```text
莉萨奥：T9697 + A9701
↓
法恩森：
  若rep970 < 3000：A9739 + A9743
  若rep970 >= 0：9919进入可接候选；否则暂不接
↓
孢殖林调查：C9701；同时拾9739成熟孢子囊
↓
西南巨人区：
  C9743
  继续拾9739孢子囊
  若9772仍未完成且报告自然掉落，则机会完成；不为9772单独刷返程
↓
法恩森：
  T9739
  T9743
  不接零经验重复后续9742/9744
↓
REP_GATE_0 / REP_GATE_3000按当前实跑状态更新
```

这里继续沿用旧R7/R19的空间事实：法恩森位于莉萨奥与C9701之间；9739地面孢子囊与C9701/9743巨人区重合。旧R20关于9742、旧R7后半关于9744的重复回访只保留为历史资料，**不再进入当前练级路线**。

2026-08-15用户确认当前自然刷怪分支中，正常完成并交9743《天敌》后已经可以接9726《既然我们是朋友......》。因此当前从零重建先把“T9743后9726可见”当作实跑门槛证据，而不是继续为了声望追加零经验重复任务。若下一批用拍卖行/交易减少巨人击杀，这一门槛必须重新测试。

## 4. REP_GATE_0：先解锁9919/9806，再进入真正孢子村任务

### 若rep970 < 0

不能A9919、9806/9807。

继续利用仍有经验的一次性法恩森任务，以及这些任务过程中自然产生的巨人击杀声望，直到`rep970 >= 0`；**不通过9742/9744等零经验重复交付补声望**。

公开WotLK Classic资料已补到巨人系杀怪声望：枯萎巨人/枯萎沼泽领主/饥饿真菌巨人/挨饿沼泽领主/普通真菌巨人/沼泽领主均按`+15 Sporeggar声望/eligible kill`记录；当前Titan客户端若实跑不同，以用户现场值覆盖。公开资料同时确认从零初遇为Unfriendly，结合Questie Neutral门槛绝对值`0`，从零起始值暂推导为`-3000`，标记`public_inference`而非用户实测。数据保存于`data/observations/sporeggar-reputation-sources.json`。

`REP_SERVICE_TO_0`现在只允许从“本来就值得做的一次性任务服务”与“其自然击杀”获得声望。若一次性练级任务全部完成后仍未过门槛，再单独判断是否值得补杀声望怪或直接放弃后续声望任务；不能因为后续任务存在就自动塞入无经验重复轮次。

### 达到rep970 >= 0

下一次法恩森：A9919。

此时建议先完成距离很近的莉萨奥状态衔接：

`法恩森 → 莉萨奥T9701+A9702`

然后把第一次真正的孢子村访问与9702后续移动组合起来，而不是先插9726。

## 5. 第一次真正孢子村停靠：只接当前声望合法的任务

到孢子村后逐项验证：

- T9919：若已接；奖励阵营970 +250；
- A9806：仅`rep970>=0`；
- A9808：仅`rep970<3000`；
- 9726：只有此时已经`rep970>=3000`才允许出现，否则继续DEFER；
- 9729：普通路线不显示；只有`rep970>=42000`条件模块才显示。

9814《爆顶蘑菇》若当前已从萨布拉金接取，则在这里执行用户实跑确认的**萨布拉金/孢子村本地采集圈**，不再标成0秒全程背景任务。

9806《成熟的孢子》已被2026-08-15实跑重新分类：24449确认可交易，本轮在“去穆玛基”与“去9822《战斗迫近》”两段自然移动中持续获得，最后自然回孢子村时补齐/交易并交付。因此旧R15的孢子村北/西北大型孢子蝠本地环降级为`explicit local fill fallback`，不再作为默认服务段。默认先把9806放入北部Background Layer；只有下一次自然回孢子村前总可分配库存仍不足，才在当前附近补刷。

## 6. 从孢子村离开后的机会层调整

9911《沼泽中的伯爵》不再等到旧R47“9842走廊阶段”才启用。

新规则：

- 一旦角色已具备任务物触发条件，昂古拉`(32.81,59.53)`始终属于全局Opportunity Layer；
- 主体路线自然经过时见到就杀；
- 掉出下颚骨则立即更新当前任务状态；
- 不为它原地等刷新；
- 已触发后在下一次自然经过莉萨奥时交。

用户本轮实跑已经出现：`孢子村接任务 → 顺路昂古拉拿下颚骨 → 继续往9702《狼吞虎咽》目标点`。这证明“只在9842走廊阶段才开始关注昂古拉”过窄；但这次顺路行为本身仍不自动证明从零路线必须强制经过昂古拉点。

若9702此时已接，允许利用这条自然方向：

`孢子村 → （昂古拉机会） → C9702丢弃食物 → 莉萨奥T9702+A9708`

若9702尚未接，则必须先去莉萨奥A9702，不能因为机会路线好看而违反objective_ready。

## 7. REP_GATE_3000：这是新路线最关键的非单调状态边界

跨3000仍然是非单调边界，但练级目标已经进一步简化：零经验重复后续9742/9744/9809不再需要为了“别被关掉”而保留；9727也不接。

真正需要保护的是**仍有经验的一次性低声望任务**，例如9739、9743、9808。任何可能把声望推到3000的击杀/交付前，仍要检查这些一次性任务是否已经合法接取或完成，避免为了提前解锁9726反而丢掉有经验任务。

跨过3000后，本项目普通练级路线只重新激活9726《既然我们是朋友......》；9727虽然数据库可接，但因零经验重复任务策略直接过滤。

2026-08-15当前自然刷怪分支提供了一个更实用的运行时证据：T9743《天敌》后用户现场已经能接9726。当前重建先使用这个实跑门槛，不再人为安排重复声望轮次。若下一批通过拍卖行购买成熟孢子囊/卷须，使9743之前的巨人击杀显著减少，则这一门槛重新变成待验证分支。

## 8. 达到rep970 >= 3000后的血鳞包

只有跨过3000后，9726才重新成为合法候选；9727因零经验重复任务策略直接过滤：

```text
孢子村/舒特：A9726
↓
血鳞区：C9726 + C_partial9728
  若9720沼光湖泵尚未完成，可在同一区域自然处理
↓
不要为了交9726立刻折返舒特
↓
继续穆玛基 / 鱼人笼 / 格罗阿克 / 战斗迫近等北部主体
↓
下一次自然回孢子村时：T9726 + T9806（若成熟孢子已完成）
```

2026-08-15本轮实跑曾采用`C9726 → 立即T9726 → 穆玛基`。由于不再接9727，立即回交没有解锁收益。按目标区→舒特→穆玛基与目标区→穆玛基的当前平面代理比较，延后T9726可少约788.6 yd，按16.8 yd/s纯骑乘约47秒；9726满经验截止69级，当前65级也没有立即兑现压力。因此下一版默认把T9726延后到后面自然回孢子村的停靠，由State Replay再次确认。

## 9. 9729处理

9729《弗沃尔发怒了！》要求阵营970声望`>=42000`。

普通赞加练级主路线：

- 不放护送节点；
- 不放“护送返回”死节点；
- 9720沼光湖泵由主体血鳞/沼光区域自然完成。

只有运行时RouteState已证明`rep970>=42000`，才加载独立9729模块并重新计算它是否值得插入。

## 10. 后续旧版本如何复用

R6–R47不按旧序继续拼接，而按以下方式回收：

- R6安葛洛什终局：保留`9708→9709`、`9820→9822→9823`共享目标事实；重新等待前置状态合法后插入。
- R7/R19/R20：9739/9743的一次性空间事实保留并前移；9742/9744零经验重复后续从练级路线删除。
- R10黑钉：固定点与插入成本事实保留；T9898需同时过XP deadline复审。
- R15/R16：R15关于成熟孢子来源分布仍保留，但9806默认改为北部Background Layer；R16的9807零经验重复后续从练级路线删除。
- R17/R18：9808的一次性亮顶蘑菇空间事实保留并受`rep<3000`硬控制；R18的9809零经验重复后续从练级路线删除。
- R21：9814从“0秒背景”改为用户确认的本地采集圈。
- R26：当前角色“已接9846所以黑钉后顺做蛮沼”的结论只服务当时状态；从零版不能直接继承。
- R28：9919法恩森→孢子村的零目标结构保留；A动作受REP_GATE_0控制。
- R44：9729线性条件节点废弃，改成rep>=42000独立模块。
- R47：昂古拉空间点保留，但任务触发从局部9842阶段提升为全局机会层。

## 11. 当前这版已经解决与尚未解决

已解决：

1. 确认R5为第一处声望Availability错误，R4作为任务插入回滚点；
2. 低声望一次性任务不再后补，而是优先在声望关闭前完成；零经验重复后续不再作为补声望手段；
3. 9726延后到rep>=3000；9727因零经验重复任务策略直接排除；
4. 9729移出普通线性路线；
5. 9919/9806受rep>=0门控；9806已改为北部Background Layer并以本地刷圈作fallback；
6. 9808、9739、9743等有经验一次性低声望任务继续受rep<3000保护；9809/9742/9744从练级路线删除；
7. 昂古拉/9911改为全局机会层；
8. 旧R快照只复用事实与候选证据，不继承错误顺序；
9. 公开WotLK资料补齐巨人系`+15/kill`声望来源，从零初始声望由Unfriendly+Questie Neutral=0推导为`-3000`并单独标注public inference；
10. Questie field24确认Repeatable真值，状态机仍记录turnin_count，但练级路线不生成第二轮；
11. 当前自然刷怪实跑分支确认T9743《天敌》后9726已可接；AH购买任务物导致击杀声望减少的分支留待下一批验证；
12. 9726本轮立即回交被识别为可优化点，下一版默认尝试延后到后续自然回孢子村，平面代理约省47秒纯骑乘。

尚未解决，不能伪装成完成：

1. 当前Titan客户端是否与公开WotLK的`+15/kill`完全一致，以及五开五号在同一次共享击杀中是否都同步获得该声望；这属于客户端/五开现场验证，若用户后续报告不同立即覆盖公开参考；
2. 若下一批通过拍卖行/交易减少9739/9743相关自然击杀，T9743后是否仍能解锁9726；该分支必须实测，不能沿用当前自然刷怪结论；
3. R4旧炉石1在从零路线中的重新落点；
4. 全路线XP滚动上界，因此还不能证明所有低级T节点都在满经验窗口内；
5. 当前用户仍在实跑，9847之后的T9822/A9823与炉石窗口尚未完成现场回放。

本文件仍是重建草案；当前声望重复循环已经从问题列表移除，因为练级策略明确不做零经验重复轮次。下一步集中处理9847之后的运输/后缀以及完整XP状态。
