# Route Atlas 前端、逻辑步骤与地图资源规则

用途：修改 Route Atlas HTML、步骤/HUD/动画、地图底图、中文标签和离线复制结构时读取。路线状态和插入算法见 `route-atlas-optimization.md`。

## 1. 唯一通用工作台

- Route Atlas正式运行时永远只保留 `data/routes/route-atlas-workbench.html` 一份HTML。
- 所有地图通过顶部地图选择器切换，不创建 `<zone>-preview.html`、`<zone>-current.html`、`<zone>-authoritative.html` 等分支。
- 版本历史只保存Markdown审计/NEAT；结构化层只保存当前有效路线。
- 当前地图路线统一在 `data/route-atlas/workbench-routes.json`，由 `scripts/build_route_atlas_workbench.py` 嵌入HTML。
- 目标游戏电脑运行时只依赖 `route-atlas-workbench.html + maps/`，不读取JSON、Python、manifest或网络资源。
- “预览”也使用正式工作台，不另做简化模板。是否冻结只体现在状态文字和审计文档。

## 2. 页面布局与视窗

已验收布局固定为：

`标题/状态 → 控制条 → 全宽地图 + 左上HUD → 图例 → 步骤列表 → 页脚`

- 地图默认全图。
- 切步骤、上一/下一段、播放、切地图不得自动放大。
- 只有用户主动勾选“跟随当前段”才允许自动裁剪；取消后回全图。
- 地图左上HUD固定宽度、内容高度自适应且可收起。
- 不重复展示同一当前步骤信息；坐标、当前动作和下一站集中到HUD。

## 3. 几何停靠点不等于玩家步骤

数据层可以保存多个几何点以保持真实线路，但玩家步骤必须按自然任务块合并。

同一个连续任务块、局部扫图、NPC批量交接或无需决策的连贯路径，应合成一个逻辑步骤。

以下都按逻辑步骤工作：

- 步骤列表；
- HUD；
- 上一段/下一段；
- “播放当前段”；
- 当前步骤高亮。

动画在一个逻辑步骤内依次走完该组几何线。禁止为了给每条线编号而把自然行动拆碎。

## 4. 停靠点动作语义

- 当前地图点表示“本段最终要到达的目标点”。
- HUD动作描述“到这个点后做什么”。
- 连线只回答“从上一个停靠点怎样到这里”。
- 原地接取、交付、脚本、对话等没有开放世界位移的动作仍归当前停靠点。

不能把起点动作错误挂在前往下一个目标的长连线上。

## 5. 备注与玩家可见文本

- 任务备注只写能直接帮助完成任务的机制、操作、条件、等待/不等待和地形。
- “为什么这样排、为什么合并、为什么裁掉”属于路线设计审计，不进入玩家备注。
- 所有执行路线任务都必须完成逐任务人类可执行性审计；有特殊做法才产生备注。
- 有有效备注的逻辑步骤标题显示“有备注”，HUD显示具体 `备注：...`；无备注不显示空区域。
- 玩家可见标题/HUD/步骤/备注/图例/页脚禁止出现内部 `A1234 / C1234 / T1234`、裸任务ID或“用编号代替任务名”。
- 发布前扫描全部用户可见路线字符串；发现内部动作记号或裸ID即验收失败。

## 6. 当前稳定控制行为

- 播放控制至少区分“当前段”和“剩余路线”。
- 点击上一段/下一段后自动播放一次所选当前段。
- 当前步骤可在步骤列表直接点击跳转。
- 多任务步骤可按需要切换任务知识卡，但执行备注优先汇总到HUD，不重复占用知识卡。
- `MANUAL_SPATIAL_REVIEW`任务必须展示可用目标点/区域边界、宏观进入方向和“局部刷法待现场决定”，不得为了动画好看伪造局部最优折线。

## 7. 地图底图原则

- 清晰度优先，但必须保持现有0–100坐标几何一致。
- 替换底图前先做边界、比例和锚点配准；未通过不能切换。
- 不为了内嵌中文地名退回低分辨率图。
- 高清英文底图没有中文时，用独立HTML/SVG小标签叠加，不把中文烘焙进底图，也不把标签当坐标真值。
- 中文标签低干扰、可开关；视窗裁剪时同步当前viewBox。
- 无可靠zhCN区域数据时允许只用高清英文底图，禁止机器直译冒充客户端真值。

可靠标签生成：

- `data/routes/maps/labels-zhcn.json`
- `scripts/build_route_map_labels.py`
- `lib/route_map_assets.py`

## 8. 地图资源池与离线复制契约

- HTML固定在 `data/routes/`。
- 地图统一在同级 `data/routes/maps/`。
- HTML只允许通过 `maps/<实际文件名>` 引用底图。
- 浏览器运行时不得依赖 `../route-atlas/`、Python、manifest、网络请求或项目其它目录。
- 中文标签等运行时数据必须构建时内嵌进HTML。
- 玩家复制到游戏电脑时只需复制HTML和整个同级`maps/`目录。

地图资源池应提前缓存任务宇宙覆盖地图，而不是每做一张攻略临时下载。

文件稳定命名：`<zone_id>-<slug>.<ext>`。

`manifest.json`记录来源、缺失、回退和HD元数据；生成期默认优先经过验收的 `hd_file`，只有manifest明确回退时才用普通底图。

相关生成器：

- `scripts/download_route_map_assets.py`
- `scripts/build_hd_route_maps.py`
- `lib/route_map_assets.py`

## 9. 冻结视觉参数

除非用户明确要求修改视觉系统：

- 普通路线线宽 `1.25`
- 当前段线宽 `3.0`
- 炉石普通 `1.8`
- 当前炉石 `3.4`
- 箭头 marker `5×5`
- `markerUnits="strokeWidth"`
- `vector-effect="non-scaling-stroke"`

不得因新地图无理由漂移。

## 10. 发布门禁

修改工作台后至少验证：

1. 路线JSON可解析；
2. stepGroups覆盖有效几何范围且无重复/遗漏；
3. HTML重新构建成功；
4. JS语法检查通过；
5. 用户可见文本无内部ID泄漏；
6. 当前地图底图路径使用 `maps/` 相对路径；
7. 默认全图、不自动zoom；
8. “有备注”只在有效执行备注存在时出现；
9. 被废弃的单地图HTML没有重新产生；
10. 相关自动测试通过。
