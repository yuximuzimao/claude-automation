# 当前状态、完整性审计与归档规则

用途：继续当前角色、裁路线、导入Journey、做候选完整性/发布审计、写NEAT或恢复点时读取。

## 1. 当前状态证据优先级

回答“现在还要做什么”时按以下顺序：

1. 用户当前会话明确给出的现场状态、等级、经验、任务行为；
2. 最新Questie人物历程/现场可接状态；
3. 项目最近一次明确标为当前的结构化状态；
4. 较旧Journey缓存、历史CURRENT、旧路线；
5. 通用数据库和历史资料只补结构，不能覆盖当前服实况。

Questie Journey能证明接取、完成/交付、放弃、升级和时间戳；不能证明死亡、移动路线、找怪耗时、暂停原因或目标进度细节。

## 2. 当前执行路线与从零复用路线分离

永久保留：

- **从零复用主路线**：下一批正常进入地图时完整需要的任务。
- **当前执行路线**：按当前角色真实状态裁掉已完成动作、改变起点和局部顺序。

当前角色完成任务时，只从当前执行动作删除；不能从任务宇宙、任务知识和下一批路线里一起删掉。

删除节点后重新检查：

- 前置/后续；
- 当前起点；
- Hub停靠；
- 炉石/飞行点；其中系统飞行点必须按任务发生顺序维护`opened_flight_points`，不能只保存整图最终“已开”集合；
- 条件分支；
- 被删除节点之间的几何连接。

裁剪或重排后必须从受影响起点向后重放动态交通状态。任何新飞行点一旦在更早位置开启，后续尚未执行的跨片区步骤都要重新比较飞行/炉石/骑马方案；不能机械把旧节点前后直接连起来，也不能冻结旧交通方式。

## 3. 异常顺路行为只更新结果，不自动学习成路线

学技能、买物品、测试机制、死亡跑图等造成的临时绕路：

- 产生的任务完成/接取结果进入当前状态真值；
- 绕路原因本身不自动写入下一批路线；
- 只有独立成本分析或多轮实跑证明更优才升级为长期方案。

即：**结果影响剪枝，原因不自动成为路线证据。**

## 4. 自动候选完整性审计

自动区域候选、Questie区域分类和当前日志都只负责召回。

新建/修订路线的候选集合至少取并集：

- 当前日志；
- 自动区域候选；
- 已完成任务的直接后续和完整前置闭包；
- 当前/途中/目的地任务中心NPC的全部可接可交任务；
- 野外护送、巡逻NPC；
- 物品触发、固定物体触发；
- 跨区引导/送信；
- 当前等级暂缓、后续会回访的任务。

发布前执行：

`候选并集 -（路线纳入 + 明确跳过 + 明确延后）`

每个差集项只能归为：纳入、明确延后到具体节点、日志容量原因暂不接、前置不满足、明确跳过。不能无解释消失。

每次生成/修订/审计前按本轮影响范围定向读 `docs/verified-routes/ERROR-BOOK.md` 的相关失败模式；不为局部修改机械执行与当前变更无关的全量复查清单。

## 5. 可接性不是只看等级和前置

Questie compact DB中的声望与其它Availability条件都是硬约束：

- `preQuestSingle`：列表中任意一个完成即可；
- `preQuestGroup`：列表全部完成；
- compact quest DB字段19 `requiredMinRep`：当前声望必须达到，判断为 `current_rep >= requiredMinRep`；
- 字段20 `requiredMaxRep`：当前声望必须低于上限，判断为 `current_rep < requiredMaxRep`；
- 字段26 `reputationReward`：属于RouteState状态转移，必须传播到后续任务可接性；
- 职业、种族、技能、法术等条件同样不能静默忽略。

但首跑前如果缺的是“按当前整图路线跑到某节点时究竟累计了多少真实声望”这一实跑量，不在玩家路线里生成“接不到就跳过/以后再查”的开放分支。先把任务按最合理地理位置固定进唯一序列，并假定该节点可接；首跑若证明确实未解锁，再把该任务整体移动到第一个真实可接的固定节点。除用户明确指定、确实会改变执行路线的阶段切换条件外，最终执行路线不保留运行时条件分叉。

物品触发任务不能只扫描NPC任务列表，必须同时检查Item DB/触发来源。

`pre_any / pre_all / parent_active`全部为空只表示当前基础数据没有记录前置，**不能直接证明该任务是独立根**。在冻结新地图scope前，所有会成为大依赖组件根节点的空前置任务必须做根节点对抗审计：优先使用用户/当前服务器实测，其次Questie Corrections和可靠公开任务链。已经确认的隐藏前置必须先物化到统一修正层，再由可达性算法递归传播到独占后代；禁止只在路线正文或生成器里手工删一串后续任务，否则自动“依赖缺口=0”可能建立在错误根节点上。

未解析的Availability事实必须明确标记为“待首跑校准”，不能伪装成已验证事实；但它不应因此把玩家执行路线变成开放分支。

## 6. 构建时闭合、局部重放与发布前薄审查

### 构建时闭合

任务结构合法性主要在**人工任务簇插入当时**完成，而不是留到发布前重新逐任务证明。每次插入前，当场确认与该任务簇有关的前置/Availability、当前接取状态、目标Spatial Instance、同区可合并任务、交付Hub、交付后直接解锁、任务日志和当时交通状态；确认无问题后才允许插入。已经这样闭合的任务簇，后续没有状态传播触及时视为已验收事实。

### 局部修改只重放受影响窗口

路线发生局部修改时，先人工列出“最早被改变的状态节点”和它直接影响的接取/交付/交通/分支/日志边，然后逐个看这些位置，直到状态重新接回原路线。没有被影响的前缀和后缀不重复验证。只有飞行点/炉石、声望/阵营、任务日志容量、跨图携带任务、等级/经验截止或其它RouteState发生可继续向后传播的变化时，才扩大窗口。

### 发布前薄审查

完整地图发布前只检查局部闭合无法单独保证的全局性质：

- 候选差集是否全部解释，正式任务池有无漏项/重复；
- 是否出现异常重复Spatial Instance、后续插入后新出现的“一次进场可合并”机会、大范围折返或反向跨图；
- 地图真实入口与上一图出口、地图真实出口与下一图入口是否仍闭合；
- 地图终点残留任务是否都有明确跨图携带/自然交付理由；
- 最终玩家可见 `point title/action/note`、`stepGroup title/summary` 是否继续服从攻略第一目标；
- 只有本轮确实修改到的HTML/构建逻辑再做对应构建/渲染检查。

薄审查发现问题时，只打开对应受影响窗口修正；不能因为发现一个局部问题默认从地图起点重新跑完整前置、交通、几何和机制链。

### 验证范围必须与本轮变更一致

- 先定义本轮变更类型：文本/展示、单任务事实、局部路线结构、整图重构、算法/规则实现。只运行能验证该变更及其直接状态传播的检查。
- 文本/展示修正默认只验证目标文本、页面构建和受影响玩家视图；不得触发整图任务集合、全图几何、估时模型或历史路线重算。
- 局部路线结构修改先人工查看受影响位置，再按需要调用最小脚本；不把“前置/覆盖/交通/几何”当固定四件套。
- 只有公共算法/解析器/状态机修改，或局部状态确实传播到跨地图公共行为时，才扩大到跨地图回归。
- 测试不是路线真值。若测试与用户当前明确指令、最新Journey/实测、CURRENT或永久规则冲突，先判断测试是否是旧快照；旧快照应更新或删除，不能反向要求当前路线恢复旧状态。
- 固定步骤数、点数、精确文案、固定步骤索引、某任务必须位于某一步等属于**快照断言**，除非该形态本身被明确声明为当前产品契约，否则不能作为长期发布门禁。
- “全测试通过”只能证明所运行测试当前通过，不能替代本轮目标对应的人工判断，也不能作为擅自扩大修改范围的理由。

## 7. 用户实跑反馈写回顺序

用户报告任务机制、地形、掉率、共享、接交异常或折返时：

1. 先判断**用户授权的影响范围**。用户只指出某条文本、某个任务或某个步骤时，只改该范围；若检查中发现其它已完成路线可能存在问题，先列出证据并询问是否修改。只有用户明确要求“同类问题全部修”“整图复审/重构”或等价授权时，才扩大修改范围。
2. 已完成/已验证路线默认视为冻结资产；发现疑点可以报告、可以验证，但未经用户授权不得擅自改变任务集合、顺序、交通或任务链结构。
3. 在授权范围内先修当前玩家执行稿，避免错误继续影响实跑；
4. 写 `data/observations/` 对应实测；
5. 单任务稳定事实回写 task-library；
6. 属于重复失败模式时写 ERROR-BOOK；
7. 跨地图、跨批次仍成立的方法才提升到 `docs/rules/`；一旦提升，立即按`docs/rules/README.md`对受影响规则邻域做永久性/唯一owner/冲突/实现同步检查，不能只把新提醒追加进去；
8. 当前等级/进度更新 CURRENT；
9. 本阶段形成完整恢复点时写NEAT。

不允许只写历史解释而保留错误正文。

已验证历史段的边界：只有用户实跑确认且仍值得复用的机制、经验和路径才进入`docs/verified-routes/segments/`；尚未实跑的建议留在当前规划或todo，已经被替代的一次性分析/候选方案/旧执行稿统一进入`docs/archive/`，不能因为静态审计通过就标成已验证实跑路线。

## 8. NEAT / CURRENT / rules 的边界

### CURRENT

只保存：当前目标、最新等级/位置/关键状态、当前唯一执行入口、下一窗口最小恢复顺序。

### NEAT (`docs/archive/neat/`)

保存某个阶段的：

- 当时状态；
- 新实跑证据；
- 本阶段判断；
- 下一恢复点；
- 形成规则的证据来源。

NEAT不是永久规则入口。后续若某结论升级为长期规则，必须写入 `docs/rules/`；NEAT只保留形成过程并归档。

日常NEAT收尾必须全文审查当前活跃知识，但不重复全文审查整个 `docs/archive/`。历史区默认只审：归档索引、本轮新增/修改/移动的历史文件，以及CURRENT或当前任务明确需要回溯的最近历史文件。

### rules

只保存跨地图/跨批次仍成立的方法和产品契约，不保存某批角色等级、某次Questie哈希、R1/R2快照、局部临时顺序、一次性异常或单次求解结果。

## 9. Git与文档持久化

- `docs/archive/` 是可版本化项目历史，必须正常纳入Git；它只是从日常活跃知识中退出，不等于忽略或删除。
- 工作区根 `/sessions/` 是浏览器/账号运行时会话，必须继续被 `.gitignore` 忽略；与项目历史档案语义完全不同。
- 项目Markdown不要依赖 `git add -f` 作为常规流程；忽略规则必须只作用于真正的运行时/敏感目录。
- 原始Questie/WTF/账号级输入不提交；只提交脱敏后的路线状态、任务知识和结构化观察。

## 10. 临时教训收件箱

`tasks/lessons.md` 只放尚未确定归宿的新发现。稳定后必须迁入：

- 永久方法 → `docs/rules/`；
- 重复错误 → `ERROR-BOOK.md`；
- 任务事实 → task-library / observations；
- 阶段状态 → NEAT。

迁移后从 `tasks/lessons.md` 删除，禁止长期重复维护两份。
