# 当前状态、完整性审计与归档规则

用途：继续当前角色、裁路线、导入Journey、做候选完整性/发布审计、写NEAT或恢复点时读取。

## 1. 当前状态证据优先级

回答“现在还要做什么”时按以下顺序：

1. 用户当前会话明确给出的现场状态、等级、经验、任务行为；
2. 最新Questie人物历程/现场可接状态；
3. 项目最近一次明确标为当前的结构化状态；
4. 较旧Journey缓存、历史CURRENT、旧路线；
5. 通用数据库和历史资料只补结构，不能覆盖当前服实况。

Questie Journey能证明接取、完成/交付、放弃、升级和时间戳；不能证明死亡、移动路线、找怪耗时、暂停原因或目标进度细节。

## 2. 当前执行路线与从零复用路线分离

永久保留：

- **从零复用主路线**：下一批正常进入地图时完整需要的任务。
- **当前执行路线**：按当前角色真实状态裁掉已完成动作、改变起点和局部顺序。

当前角色完成任务时，只从当前执行动作删除；不能从任务宇宙、任务知识和下一批路线里一起删掉。

删除节点后重新检查：

- 前置/后续；
- 当前起点；
- Hub停靠；
- 炉石/飞行点；
- 条件分支；
- 被删除节点之间的几何连接。

不能机械把旧节点前后直接连起来。

## 3. 异常顺路行为只更新结果，不自动学习成路线

学技能、买物品、测试机制、死亡跑图等造成的临时绕路：

- 产生的任务完成/接取结果进入当前状态真值；
- 绕路原因本身不自动写入下一批路线；
- 只有独立成本分析或多轮实跑证明更优才升级为长期方案。

即：**结果影响剪枝，原因不自动成为路线证据。**

## 4. 自动候选完整性审计

自动区域候选、Questie区域分类和当前日志都只负责召回。

新建/修订路线的候选集合至少取并集：

- 当前日志；
- 自动区域候选；
- 已完成任务的直接后续和完整前置闭包；
- 当前/途中/目的地任务中心NPC的全部可接可交任务；
- 野外护送、巡逻NPC；
- 物品触发、固定物体触发；
- 跨区引导/送信；
- 当前等级暂缓、后续会回访的任务。

发布前执行：

`候选并集 -（路线纳入 + 明确跳过 + 明确延后）`

每个差集项只能归为：纳入、明确延后到具体节点、日志容量原因暂不接、前置不满足、明确跳过。不能无解释消失。

每次生成/修订/审计前读 `docs/verified-routes/ERROR-BOOK.md`，执行固定复查清单。

## 5. 可接性不是只看等级和前置

Questie compact DB中的声望与其它Availability条件都是硬约束：

- `preQuestSingle`：列表中任意一个完成即可；
- `preQuestGroup`：列表全部完成；
- `requiredMinRep`：当前声望必须达到；
- `requiredMaxRep`：当前声望必须低于上限；
- 职业、种族、技能、法术等条件同样不能静默忽略。

物品触发任务不能只扫描NPC任务列表，必须同时检查Item DB/触发来源。

未解析的Availability不能进入“已验证执行路线”。

## 6. 路线发布前必须做三类验证

### 任务结构验证

- 前置闭包完整；
- 当前任务能在计划节点接到；
- 交付后后续解锁顺序正确；
- 条件任务不会留下死步骤；
- 任务日志峰值不超过25。

### 玩家可执行性验证

按 `execution-and-mechanics.md` 逐任务完成隐藏机制审计，并冷启动复走当前路线。

### 全图几何验证

整张地图路线完成后再看全图/动画，检查大范围折返、反向跨图、异常Hub回访和终点方向。不要每插一个任务就做全图审查。

## 7. 用户实跑反馈写回顺序

用户报告任务机制、地形、掉率、共享、接交异常或折返时：

1. 先修当前玩家执行稿，避免错误继续影响实跑；
2. 写 `data/observations/` 对应实测；
3. 单任务稳定事实回写 task-library；
4. 属于重复失败模式时写 ERROR-BOOK；
5. 跨地图、跨批次仍成立的方法才提升到 `docs/rules/`；
6. 当前等级/进度更新 CURRENT；
7. 本阶段形成完整恢复点时写NEAT。

不允许只写历史解释而保留错误正文。

## 8. NEAT / CURRENT / rules 的边界

### CURRENT

只保存：当前目标、最新等级/位置/关键状态、当前唯一执行入口、下一窗口最小恢复顺序。

### NEAT (`docs/verified-routes/sessions/`)

保存某个阶段的：

- 当时状态；
- 新实跑证据；
- 本阶段判断；
- 下一恢复点；
- 形成规则的证据来源。

NEAT不是永久规则入口。后续若某结论升级为长期规则，必须写入 `docs/rules/`；NEAT保留形成过程即可。

### rules

只保存跨地图/跨批次仍成立的方法和产品契约，不保存某批角色等级、某次Questie哈希、R1/R2快照、局部临时顺序、一次性异常或单次求解结果。

## 9. Git与文档持久化

- `docs/verified-routes/sessions/` 和 `docs/video-extraction/sessions/` 是项目Markdown历史，必须正常纳入Git。
- 工作区根 `/sessions/` 是浏览器/账号运行时会话，必须继续被 `.gitignore` 忽略；两者语义完全不同。
- NEAT文件不要依赖 `git add -f` 作为常规流程；忽略规则必须只作用于根运行时目录。
- 原始Questie/WTF/账号级输入不提交；只提交脱敏后的路线状态、任务知识和结构化观察。

## 10. 临时教训收件箱

`tasks/lessons.md` 只放尚未确定归宿的新发现。稳定后必须迁入：

- 永久方法 → `docs/rules/`；
- 重复错误 → `ERROR-BOOK.md`；
- 任务事实 → task-library / observations；
- 阶段状态 → NEAT。

迁移后从 `tasks/lessons.md` 删除，禁止长期重复维护两份。
