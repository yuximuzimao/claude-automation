# 练级预算与任务取舍规则

用途：做经验预算、地图轴选择、任务保留/跳过、随机掉落/护送/固定拾取价值判断时读取。玩家文案格式和特殊任务操作见 `execution-and-mechanics.md`。

## 1. 五开计算基准

- 等级、经验、补经验需求和离图判断以五个角色中**等级/经验最低的角色**为唯一保证基准。
- 每个任务块开始/结束记录最低号等级、当前经验、本级总经验、位置和关键任务；有可靠墙钟才计算经验/小时。
- 长期耗时预测不得把某一低等级任务块的经验/小时线性外推到后续全程；应按等级段比较任务奖励中位数、每级任务等价数、地图聚合度、骑术/技能节点，并优先使用“任务块经验 ÷ 任务块墙钟”比较候选。
- 用户新回报的等级/经验立即覆盖旧预测，不允许为了维持旧模型继续使用旧起点。
- 理论任务经验必须使用当前服务器已验证倍率/规则校准；具体倍率属于服务器阶段事实，从CURRENT、observations或当前版本证据读取，不在永久规则里硬编码。休息经验等额外个人加成不能写进保证预算。
- 五号交付后必须逐号确认任务从日志消失。单号经验异常先排查漏交，不先推断路线漏任务。

## 2. 经验预算必须分账

每段至少拆成：

1. **精确任务经验**：确定会完成并交付的任务。
2. **强制击杀保守经验**：任务明确要求的必要击杀，只作安全余量。
3. **零预算经验**：沿途怪、探索、竞争补杀、随机掉落额外补刷、异常刷新等保证账一律按0。

经验闭合的单位优先是**连续地图阶段**，不是强制每张地图单独闭合。离开当前地图前仍要核对最低号是否能接下一地图的核心任务、任务怪是否在可稳定击杀区间；满足这些条件时，当前图的经验缺口允许由下一张成熟地图补齐。保证账不能用“正常会顺便打怪”填缺口，但可以把下一地图确定会做的任务经验与其强制击杀保守经验纳入同一阶段预算。

### 下界账与上界账

需要同时验证：

- **下界账**：最低号一定能获得多少经验，证明任务经验够不够。
- **上界账**：最快/最高号可能提前获得多少经验，证明后续低级任务不会因等级过高而衰减。

WotLK一次性任务完整经验截止按 `last_full_xp_level = quest_level + 5`。必须按**预计实际交任务等级**检查，而不是接取等级或任务等级。若后面低级链会越线，优先调整同图交付顺序，再考虑跨图穿插。

“仍给完整经验”不等于“值得做”。最终仍比较真实剩余墙钟。

### 任务取舍统一服从打金目标，不按阶段等级划硬边界

任务是否执行不由“某等级前可删、某等级后全清”这类阶段规则直接决定。无论当前处于哪个地图或等级阶段，都必须回答同一个问题：**从当前状态开始，这个任务/任务包会怎样改变“这一整组号的任务打金周期”的总金币、总墙钟和稳定复用性？**

`现在做`是成熟连续路线中的默认动作，**不要求每条任务在首跑发布前都先做一次经济学证明**。只有准备偏离默认基线——主动删除、故意延后到满级后、发现明显独立折返/异常长耗时，或进入满级临界任务包——才启动正式取舍；一旦启动取舍，就至少比较三种动作：`现在做`、`以后做（例如满级后清）`、`永久不做`，不能只比较“做/删”两个选项。这样保留经济最优化能力，但不把尚未实跑的整张地图变成逐任务组合优化问题。

- **现在做的收益**：当前直接金币、装备/物品可出售价值、任务链后续价值，以及经验带来的后续任务可接性、等级推进和更早进入满级XP折金阶段。
- **满级后再做的收益**：当前直接金币、装备/物品出售价值、满级XP折金、后续链收益；同时扣除未来重新回图、重新定位和接交的任务路线内部成本。
- **永久不做的影响**：节省当前与未来该任务包的墙钟，但必须计入因此损失的任务金币、装备/物品价值、经验、前置链以及可能导致其它任务无法完成的损失。
- 练级经验本身不是金币，但它是这套任务打金方式内部的状态变量：决定后续任务什么时候可接、哪些任务能在满级后以XP折金兑现、整组号什么时候完成任务路线。不得把经验价值换算成“更早去团本/日常/其它打金方式”的机会收益。
- 满级XP折金、当前直接金币、装备卖店/拍卖价值都必须保留在任务卡中；它们共同构成这套任务打金方式的收益，不应因属于不同等级阶段而互相排斥。
- 任务自身时间只记录`objective/service`；真正做取舍必须重算现在做/满级后做/不做三种方案的移动、Hub接交、共享击杀、并圈、等待、失败重跑和回访成本，禁止把单任务卡分钟数直接冒充边际墙钟。
- 脑力负担和可重复性纳入经济判断：频繁切号、容易漏、需要临场搜索、路线记忆复杂、失败后难恢复的任务，即使纸面金币/分钟略高，也可能因实际执行方差和认知成本而劣于更稳定方案。

### P1—P4只保留为成本筛选器，不再拥有阶段性删除权

P1—P4/A—C仍可用于快速指出“多件个人掉落、低收益、长链”等潜在高成本任务，但只是一层**候选成本标签**，不能直接决定任何等级段的正式删除。

- 第一层先锁定任务事实：可装备奖励、当前直接金币、满级XP折金、多物品掉落/拾取、后续链、五开共享机制、可信服务时间。
- 多个不同任务物各取1件、单个任务物、单次互动，以及仅多次摧毁/使用世界物体而不取得多个任务物的任务，不进入“重复同物品”的P级先验。
- 历史P标签可以保留用于回溯，但每次真正删/留必须重新做经济边际比较；不得因为“以前P2”或“某阶段曾采用全清策略”沿用旧结论。
- 任务是否有后续链必须按当前已确认地图轴判断；路线范围改变时显式迁移链价值，不得静默改写。
- 反向审查必须同时检查：经验/等级门槛、后续一次性任务可达性、装备/出售价值、满级XP折金时点、交通、任务日志、五开机制、失败风险，以及改动后这一整组号任务周期的总金币/总墙钟/金币小时是否改善。

### 单任务事实不得升级成全局例外

某个具体任务因为面包屑互斥、免费交通、特殊奖励、异常共享机制或极低边际成本而形成特殊处理时，结论只进入对应任务卡/observations/路线决策层。永久规则只保留可泛化的方法：先确认真实机制与可达性，再比较该任务在当前路线中的边际金币、经验状态价值、交通价值、任务日志占用和后续链影响。不能因为一两个任务的特殊处理，反推出“某地图只有这一条可跳过”“某类送信永远保留”之类新的权限体系。

### 路线优化仍必须先压真实墙钟

无论最终做多少任务，都优先：同区域并行、减少折返、利用**当时已经开启**的飞行点/炉石、把个人拾取分散到自然经过路线、把低掉率任务和其它击杀目标重叠、把护送/脚本插入顺路位置。未开启飞行点一律不可假设可飞，且不得拿后续才会开启的节点倒推前半段交通。

### 基础任务属性与优化决策必须分层锁定

奖励、收集形态、范围化后续链、预计时间属于**基础任务属性**；完成核对后写入任务卡属性锁。任务卡只保存事实、关系、数值和来源，不得写“跳过/保留/剔除”等行为结论，也不得把P级优先级混进基础任务卡。

P1—P4及A/B/C属于基于任务操作成本与奖励结构推导出的**候选成本标签**，单独写入决策锁。它们不再代表“升级路线自动删除优先级”，也不属于任务本身固有属性。真正的正式取舍必须回到项目唯一目标，比较现在做/以后做/永久不做对长期可重复净金币/真实墙钟的影响。无论基础属性锁还是决策锁，出现重算漂移都必须先查明原因；只有确认原事实/规则确实有误并获得用户明确确认，才允许修正对应锁值。

以上规则**只生成候选和优先级标签**，不得因为标签本身直接修改正式 Route Atlas 路线或 HTML。每批候选必须先做反向审查（前置/后续与互斥、装备及出售价值、经验与等级门槛、交通/动线、五开机制、任务日志占用、脚本/失败成本），再按当前用户已授权的修改范围落地并重算路线/时间；只有超出既有授权、触碰明确锁定项或需要改变项目目标时才额外请求确认，不能把“逐批重复确认”本身固化成流程负担。

### 任务打标 → 删除试验 → 正式路线的固定顺序

1. **先区分任务知识全集与当前可用任务池。** effective foundation可以保留联盟、未来等级、副本、职业/专业、已移除等任务事实，作为知识层；但优化打标前必须单独生成“当前方案实际可能被选择”的可用池。阵营不符、无经验/重复/节日、职业/专业不符、副本（当前户外主线）、当前入口互斥、已被正式删前置导致不可达等任务不得进入P级池。条件性但仍真实可选的任务可以留在池中，即使当前路线暂未采用。
2. **只对当前可用池冻结基础事实。** 至少包括奖励（装备/当前直接金币）、收集来源（drop/pickup/其它）、收集形态、五开共享/个人机制、范围化前后置关系、任务自身服务时间及来源置信度。此层严禁出现“保留/跳过/P级”等行为判断；foundation知识层不因为未进优化池而删除。
3. **基础事实锁定后再派生优化标签。** P1—P4和A/B/C只对当前可用池生成；基础属性锁与决策标签分开存储、分开锁。可用池范围变化也属于显式scope迁移，必须写清加入/退出原因，不能把foundation总数直接当P级任务数。
4. **初筛阶段正式路线冻结。** P级只代表“先尝试删除谁”，不是已经决定删除；HTML、正式点位和整图时间在反向审查前不得跟着候选变化。
5. **删除必须按依赖闭包做包级试验。** 从候选根任务向后追`pre_all`、唯一`pre_any`、父任务激活关系及已确认跨图前置；被根任务切断的后续一起进入删除包。若仍有其它有效`pre_any`路径则不得误删。B类恰好1个有价值后续也按整包删除试验，不因“还有1个好奖励”自动保护。
6. **区分“临时保留”与“结构性非剔除”。** 因实跑很快、共享机制、连续经验链等理由暂保时，写retention override但默认保留原P标签；如果用户明确确认某任务是当前路线主轴/结构保护项，已经不属于“尝试剔除谁”的候选，则在override中标记`priority_behavior=exclude_from_priority_candidates`，让它退出P1—P4排名，但仍保留在当前可用任务池、基础任务卡和正式路线中。两种override都属于formal removal硬门禁，除非用户明确要求重审/删除。
7. **锁漂移先查事实，再迁移。** 若用户实测证明`drop→pickup`、共享机制、掉率/耗时等旧事实错误，先修基础事实，再让P级按规则自然重算；若正式路线变化导致某任务由“可用”变成结构性不可达，先更新可用池再重算其余任务链价值。只有用户明确确认事实/规则/范围错误时才执行批准锁迁移。
8. **正式删除不等于自动删除历史标签，但会重新判断当前可用性。** 被直接删除的任务若以后仍可独立补回，可继续保留在当前可用池及标签中；若它的删除切断某后续的唯一可达路径，该后续必须退出当前可用池并记录原因。历史P级仍留在analysis/NEAT用于追溯，但不能继续冒充当前筛选池成员。
9. **落路线后必须重新算四笔账。** 一是任务经验与下一地图/后续任务等级门槛，以及达到80级XP折金阶段的时点；二是依赖闭包/跨图任务是否仍可达并据此刷新当前可用池；三是新的移动、Hub接交和任务服务墙钟；四是这一整组号的任务打金周期内，当前直接金币、装备/物品变现、80级XP折金和未来回访成本如何变化，最终比较整套任务路线的总金币、总墙钟与金币/小时。不得引入团本、日常或其它打金方式的机会收益。删减理由留在analysis/NEAT，玩家HTML只展示删完以后“现在要做什么”，不展示“这里跳过了什么/为什么删除”。

## 3. 五开任务成本不能二元化

每个任务至少评估：

- 实际交付等级下的任务经验；
- 后续任务链价值；
- 强制怪数量与目标等级；
- 跑路、回头、交通切换；
- 是否共享击杀；
- 每号物品数量与掉率方差；
- 同尸体是否可多人分别拾取；
- 固定物体是否共享/个人；
- 刷新密度、命名怪搜索、洞穴、护送、载具、断跟随和失败重跑风险。

主号本来承担普通战斗和路线移动，不能把“主号要操作”统一当五开惩罚。真正需要加权的是逐号切换、逐号定位、断跟随、等待和失败重跑。

## 4. 固定物体、护送与随机掉落必须分开评价

### 固定拾取/固定交互

地面采集、固定容器、固定场景物没有怪物掉率长尾。只按逐号操作量、刷新周期、竞争、点位密度和路线偏移评估，不能因为“个人采集”就整类降权。

### 护送

护送不得按类型自动排除。与主路线重合、沿途本来要清怪、一次可让五号完成时可保留；真正的负担是启动等待、断跟随、失败重跑和明显绕路。

### 随机怪物掉落

从零设计时随机掉落默认低于共享高密度击杀和固定交互，但不是自动删除。

准备纳入主线时必须：

- 检查 Questie/数据库参考概率；
- 对高风险任务查公开 Classic/WotLK 社区实跑反馈；
- 优先使用当前服务器实测；
- 先确认是否存在高密度刷点，再评价掉率；不能用散点慢刷的学习成本直接证明任务本身低效。

明显低掉率且无高价值后续链的任务优先进入经济审查候选，但仍不能仅凭“低掉率”直接删除；只有`现在做 / 以后做 / 永久不做`的边际比较证明跳过更优时才正式移出路线。与主体击杀高度重叠、低数量、高掉率或后续链价值高的任务同样按真实剩余边际成本判断。

普通自由拾取不能套一条统一机制。是否“五号总需求累计”“同尸五号分别可取”“Party Loot”“个人独立掉落”以逐任务实测为准。误转团队会阻断普通任务物掉落，任务块开始前确认仍为普通五人小队。

## 5. 路线优化先地图轴、再地图内任务

### 地图轴

1. 优先连续完成当前地图/任务中心，减少飞艇、跨大陆、长飞行和回城。
2. 只有下一张地图整块墙钟明显更高效，或当前地图出现明确等级/任务断层，才提前转图。
3. 老手口述“某地图到X级”先视为连续阶段检查点，必须用本图可执行经验核验；任务自然清空仍不到口述等级时，进入下一任务中心，不在空地图无任务刷怪。
4. 后续批次优先复用已经验证的稳定地图骨架/正式路线，不复制早期探索阶段因逐任务拼接造成的地图振荡；具体当前权威路线入口由CURRENT/verified route决定。

### 地图内默认优先级

1. 共享刷怪 / 高密度击杀；
2. 固定拾取 / 固定场景物 / 可预测交互；
3. 与主路重合的护送；
4. 需要额外补刷的随机掉落。

随后再比较预计交付等级、真实路线、链价值和风险。类型只是先验，不是最终结论。

## 6. 任务中心与同目标区聚合

- 第一次到任务中心先扫描当前可接的一次性任务；交任务后再次扫描刚解锁的后续。
- 去刷怪区、洞穴、据点或固定物区域前，把当前可接且目标落在同一区域的任务尽量聚齐，避免同一地点二次返工。
- 日志容量不足时，优先当前目标区重叠、低等级截止链和结构性前置；远期引导、PvP、可重复或明显不在本轮目标区的任务延后。
- 户外Route Atlas与副本/团队副本保持独立scope：`is_dungeon`或raid任务默认不进入户外执行池，仅保留在任务知识层；只有当前目标明确开启副本专项路线时才单独纳入，不得因为一次性经验高、视频里做过或任务链已解锁而静默混入户外路线。
- 阶段终点必须复算下一地图进入条件、逐项归类当前日志任务、给所有延后任务明确回访点。

## 7. 已接任务使用剩余边际成本，不重算沉没成本

已接、已解锁、已拿到稀有触发物的任务，其前置/接取/触发物获取成本已经发生。后续只比较从当前状态开始的剩余成本。

同图多个已接任务按“任务包”计算，共享骑行、公共回城、重叠击杀不能给每个任务重复计费。

准备放弃已接任务前必须做**反向替代测试**：把保留与放弃推到同一后续里程碑比较完整收益和墙钟。未满级且删除会造成经验缺口时，明确后面要新增哪些具体任务并比较替代墙钟；满级或里程碑不依赖经验时直接比较金币、后续链、回访和节省时间，不能强行套“补经验任务”。

未满级阶段前段多获得高效经验、形成真实余量时，应从尚未开始的后半程任务中优先审查边际成本最高的任务包，而不是只把经验余量越堆越大；满级清图不适用这条经验裁剪逻辑。

## 8. 阶段实验不进入永久规则

诸如“某一批新号减少哪类任务”“实验到几级停止”“当前批次经济权重”等，只保留在 `CURRENT.md`、`tasks/todo.md`、对应VETERAN/NEAT文档中。永久规则只保存实验验证后仍能跨批次成立的方法；不得把阶段实验本身写成长期硬规则。
