# 测试分层与选择

本目录的测试不是一套必须在每次修改后全部跑绿的总门禁。验证范围必须服从本轮目标和用户授权范围；先确定要保护的契约，再选择最小相关测试。

## 三类测试

### 1. 永久不变量测试

保护跨地图、跨批次仍成立的产品/数据契约。只有这类断言适合长期保留为稳定门禁，例如：

- 规则入口能路由到所有永久子规则；
- 解析器、坐标投影、任务日志容量等公共逻辑的输入输出契约；
- 正式HTML唯一性、玩家可见文本不泄漏内部token等跨地图产品契约；
- `docs/archive/scripts/`中的历史脚本不能重新成为现役builder、audit或test入口。

公共实现变化时，运行与受影响不变量直接对应的测试；仍不要求无差别运行全目录。

### 2. 当前地图 / 当前功能开发验证

保护正在开发或明确授权修改的地图、模块或功能。典型文件包括地图foundation/route、交通、objective anchor、特殊机制、估时和对应Route Atlas生成结果。

只在对应地图或公共算法真的发生变化时运行。其它已完成地图默认冻结，不能因为本地图开发验证失败而顺手重写。

### 3. 路线快照 / 历史回归参考

固定步骤数、点数、任务数、精确标题、固定步骤索引、某任务必须出现在某一步、某段精确玩家文案等，都属于快照断言。它们可以用于当前形态的短期回归和定位差异，但不是永久路线真值。

`test_route_atlas_workbench.py`目前是混合文件：既有跨地图UI不变量，也有大量地图快照断言。运行其中快照测试前必须确认本轮确实要保护对应地图的当前形态。若用户授权的新路线/新文案使旧快照失效，应更新或删除快照，禁止为了跑绿恢复旧路线。

## 按目标选择验证

- 纯玩家文案 / HTML展示：验证目标文本、工作台可构建、受影响玩家视图和必要JS语法；不自动跑任务集合、交通、几何或估时全套。
- 单任务事实：验证该任务及直接依赖；不自动重算整图。
- 局部路线结构：验证受影响地图的前置、覆盖、交通、几何和估时。
- 整图重构：运行该地图完整结构验证与玩家冷启动复审。
- 公共解析器 / 公共算法：运行对应永久不变量，并按真实影响范围补跨地图回归。

默认不要使用`pytest tests`或“全测试通过”作为收尾条件。某个与本轮目标无关的旧测试失败时，先判断它是否属于过时快照；不允许让测试反向覆盖用户实测、CURRENT、现役规则或已授权的新实现。
