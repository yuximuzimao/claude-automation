# KK平台限时活动扫雷助手

项目类型：一次性工具  
生命周期：已完成  
维护级别：不维护

用于 KK 平台（魔兽 RPG 游戏官方对战平台）限时活动中的 K宝扫雷玩法。项目已完成实机验证，保留完整源码供以后需要时直接使用或参考；默认不继续维护。

## 你只需要这样用

1. 把整个 `kk-event-minesweeper` 文件夹放到 Windows。
2. 双击 `START.bat`。
   - 如果电脑已经有 Python，会自动准备环境并启动。
   - 如果没有 Python，会自动打开 Windows Python 下载页；安装后再双击一次 `START.bat`。
   - 以后如果已经生成 `dist\KBaoHelper.exe`，`START.bat` 会直接启动 EXE。
3. 游戏保持现在的固定大小，点助手里的“框选棋盘”。大致框住 18×18 棋盘即可，不需要像素级精准；助手会按已确认的 522×522 棋盘自动吸附。
4. 想自己操作时点“刷新分析”，助手仍会显示绿色/蓝色/红叉标记。
5. 想自动玩时点“自动执行确定格”：
   - 100% 炸弹：自动右键标 `!`。
   - 100% 非炸弹：自动左键；不要求先分清它最终是 K宝还是普通安全格。
   - 同一轮所有确定格按至少 200ms 的间隔依次点击。
   - Windows 点击改用 `SendInput`，并在每批执行前激活棋盘所在窗口；如果目标程序以管理员身份运行，助手也需要同级权限。
   - 一轮全部点完后固定等待 3 秒，再截图、更新已救 K宝和已标炸弹数量并重新计算。
   - 自动模式不显示棋盘标记层，助手主窗口全程保持显示，也不会自行移动位置。
   - 一旦没有任何 100% 确定格，立即停止，不猜。

第一次框选成功后会记住位置。只要游戏窗口位置不变，以后直接“刷新分析”即可；如果窗口移动了，再点一次“框选棋盘”。

## 当前安全边界

- 自动模式只执行求解器判定为 100% 确定的格子；没有确定解立即停止。
- 不读游戏内存、不注入进程，只截图、计算、显示覆盖标记并模拟普通鼠标左/右键。
- 识别存在低置信度格子时，不显示任何可操作标记。
- 约束互相矛盾时停止，不强行给答案。
- `?` 当作普通未确定格；窄 `!` 当作已经标记的炸弹。
- 用户保持助手主窗口不覆盖棋盘；刷新时只清除棋盘上的标记覆盖层，不隐藏主窗口。

## 已确认规则

- 红色数字：周围 8 格中的炸弹数量，并且这一圈没有 K宝。
- 蓝色数字：周围 8 格中的 K宝数量，并且这一圈没有炸弹；因此周围所有未开格都可以安全左键。
- 黄色数字：周围 8 格中的 `K宝 + 炸弹` 总数量，并且这一圈同时至少有 1 个 K宝和 1 个炸弹；如果只有 K宝会显示蓝色，如果只有炸弹会显示红色。
- 一个格子不能同时既是 K宝又是炸弹。
- 当前二阶段棋盘固定按 38 个 K宝、26 个炸弹计算。

## 识别与求解

- 棋盘固定 18×18，已从用户 Windows 实际截图确认约 522×522px，即单格约 29px。
- 已用进行中截图验证：未开格、空白格、红/蓝/黄数字、K宝、`!` 均可区分；用户提供的 `?` 会保持为普通未知格。
- 已用实际截图复核数字模板；当前支持红/蓝/黄 `1~6`。这次实测发现左侧黄色 `6` 曾被误识别为 `4`，已补入真实 `6` 模板。
- 求解器使用 Z3，只输出在所有合法解中结论一致的格子。
- 早中期主要检查已揭示数字附近的前沿格子；当剩余未开格不超过 48 个时，会自动把全部未开格纳入确定性检查，利用“剩余 K宝数量 / 剩余炸弹数量”做残局推理。
- 界面会直接显示“剩余K宝 / 剩余炸弹”，方便人工核对识别是否合理。

如果未来出现当前截图里还没有见过的 `7/8` 数字，识别器应优先停下来而不是强行给结论；把诊断文件给我后再补真实模板。

## 诊断

界面里有“打开诊断目录”按钮。目录是：

`%LOCALAPPDATA%\KBaoHelper\`

其中：

- `last_board.png`：助手实际截到的棋盘。
- `last_recognition.txt`：18×18 每格的识别结果，以及安全格 / 炸弹 / K宝坐标。
- `settings.json`：保存的棋盘位置。

如果标记不对或分析失败，直接把 `last_board.png` 和 `last_recognition.txt` 发给我，不需要再手工裁格子。

## 文件

- `START.bat`：用户唯一需要双击的启动入口。
- `app.py`：浮窗、框选、截图、覆盖标记、自动左/右键执行。
- `vision.py`：棋盘视觉识别。
- `solver.py`：确定性约束求解。
- `diagnostics.py`：诊断文件输出。
- `requirements.txt`：运行依赖。
- `build_windows.bat`：确认实测通过后，在 Windows 本机生成单文件 `dist\KBaoHelper.exe`。
- `test_solver.py`：求解器自测。

## 当前验证结果

- Python 全文件语法编译通过。
- 精简后的运行依赖可安装并正常导入。
- Qt 主窗口可在离屏模式实例化。
- 求解器单元测试通过，包括：红色线索、蓝色安全圈、黄色同时含 K宝与炸弹、残局全局数量约束、歧义保持未知、非前沿不误标。
- 18×18 全未知盘的求解基准约 0.3 秒量级；实际有数字前沿时通常只检查局部。
- Windows 实机已完成自动识别与自动点击验证；`START.bat` 运行方式可用。单文件 EXE 构建入口保留，但未作为本次收尾的必要交付重新实测。
