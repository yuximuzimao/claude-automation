## 新确认的稳定质量问题

### 1. 具体事实被泛化方法论吞掉

典型表现是原文有明确装备名、数值、价格、门槛和失败样本，Silver 却只留下：

- “要综合判断”；
- “根据预算选择”；
- “看职业需求”；
- “不要机械套用”；
- “供需决定价格”。

本轮统一改成：先写清原始具体事实，再保留必要的适用边界。

### 2. 上层卡片无用，不代表原文无用

用户明确确认：点击“没用”只是在裁决当前聚合主题，不应向下继承到 canonical 原文。

例如 `#059` 的大框架无用，但原文仍可拆出：

- 泰坦余烬法系饰品 + 美酒节怀表的低成本组合；
- 美酒节一年一次的活动周期。

因此现役规则新增：discard 上层主题前必须检查同一讨论里是否存在能独立回答另一问题的具体事实。

### 3. 窄事实不要强行扩成大框架

如果真正可复用的信息只有一句，例如：

> 想刷大型美酒节科多兽时，多角色可以增加每天的奖励容器次数。

就直接保留这条窄事实。不能为了“跨日整合”再加一套RNG常识、职业门槛、概率框架，使一条本来有用的信息变得冗长。

### 4. Topic Card / Atomic Claim 不是原文无损替代

`coverage=full` 只能表示“已抽出来的卡片语义被 Silver 吸收”，不能证明 canonical 原文没有其它独立事实。

本轮因此把 canonical 原文重新纳入二次核对，而不是只看 Topic Card / Atomic Claim。

### 5. 连续原文窗口允许夹杂相邻无关聊天

“查看原文”本质上是一个连续时间/行范围窗口。窗口里自然出现相邻话题不是数据错误，也不需要把窗口切得极窄。

但这同时建立一个硬边界：**连续窗口不是新的全量采矿区。**

只有与当前 evidence discussion 明显属于同一讨论、但被上层抽取漏掉的事实，才允许补回或拆出新 Silver；仅仅因为相邻聊天看起来有用，不得顺手新增知识。无法确定时宁可不救。

### 6. 已存资料库的知识也允许重构

用户进一步确认：已经点过“存资料库”的知识仍允许：

- 补回具体事实；
- 删掉泛化废话；
- 拆分或重组表达；
- 调整结构化展示。

但“这是用户已经确认有用的知识”这一裁决本身不能被模型覆盖。

同理，已点“没用”的条目也允许重构内容，但其 discard 裁决不能被模型改成 knowledge。

用户裁决继续以 `knowledge_id` 为稳定绑定点；重写后重建 semantic fingerprint 即可。

## 全量二次处理方式

本轮不是机械改写全部 346 条，而是“全量审计 + 有风险才重写”：

1. 每条都检查当前 `canonical_facts`、证据卡与可定位 canonical 原文；
2. 已经是具体、窄、可检索事实的条目直接 keep；
3. 只有出现泛化、事实漏失、不同话题混入、冲突被抹平、结构类型不合法等问题时才重写；
4. 对连续原文窗口明确禁止挖相邻无关聊天；
5. 对模型输出再做结构契约校验，非法 `kind` 或空 comparison/mechanism 不进入正式 Silver；
6. 人工校准结果优先于模型重写。

审计中曾尝试用独立 Codex CLI 批量复核；前若干校准批次证明方法可行，但随后触发 Codex usage limit。因此剩余条目由当前会话按同一规则完成全量浏览与高风险回原文审计，没有把“额度不足”当成跳过剩余数据的理由。
