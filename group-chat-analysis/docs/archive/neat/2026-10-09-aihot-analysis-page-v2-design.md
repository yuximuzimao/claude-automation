# 2026-10-09 — AIHOT 参考与分析页面 v2 设计归档

## 阶段范围

本归档记录页面 v1 首轮评审之后，对 AIHOT 开源仓库的机制研究，以及据此形成的群聊分析页面 v2 方向。

AIHOT 只作为信息组织参考。本项目不复制多信源新闻站的来源等级、热度榜、精选门槛或日报体系；现役分析规则只以 `../../rules/analysis.md` 为准。

## 从 AIHOT 吸收的机制

1. 不把每条原始材料直接当成一个发现，先把相关材料归入同一话题，再识别事实、进展、冲突和新增信息。
2. 结论必须绑定来源证据，页面先给结论，再允许读者查看原始材料和条件。
3. 同一信息只保存一份，通过多个视图读取，避免“精选、全部、项目相关”各自生成一份互相漂移的摘要。
4. 分类、标签、提示词和评估规则应集中维护，不散落在页面文案里。
5. 日/周/月等派生结果只能建立在已处理的稳定信息上，不应每次重新解释所有原始材料。

## 明确不照搬的机制

1. 不使用 T1/T2 等新闻信源等级。不同群友不等于独立来源，多人重复也不等于事实更可信。
2. 不使用 AIHOT 的新闻精选门槛。群聊中的一条孤立短消息也可能对用户很有价值。
3. 不建立以讨论热度为核心的排行榜。热度可以描述群聊现象，但不决定个人价值。
4. 暂不建设日报、周报、月报和新闻式首页；先把话题整理、长期跟踪、攻略知识和项目候选做稳。

## v2 核心目标

页面 v2 的目标不是只展示少数“精选”，而是同时满足两件事：

- 完整告诉用户本批群聊涉及了哪些有意义的话题；
- 按对用户的实际价值标出必看、应该看、可以看和留档内容。

完整不等于逐条复述闲聊。所有有语义的信息先进入话题归组，纯寒暄、刷屏和广告只进入覆盖状态；短消息、孤立消息和低讨论量消息不得因此被静默删除。

## 项目边界

群聊分析项目和 `wow-quest-route` 分开保存资料：

- 本项目保存群聊原文、证据、话题、AI 分析、长期跟踪和待核验候选；
- 不共享运行时数据库，不自动读取或改写魔兽项目；
- 可以定期整理“建议转入魔兽项目”的候选；
- 只有用户确认后，候选才进入目标项目自己的核验流程；
- 目标项目核验通过后，才保存为正式事实、路线或规则。

正式路径：

`群聊原文与分析 → 候选信息 → 用户确认 → 目标项目独立核验 → 目标项目保存`

## 统一分类维度

一级分类只使用“信息讨论的游戏对象或机制”：

| 一级分类 | 二级示例 |
| --- | --- |
| 版本与服务器 | 开服、维护、热修、服务器生态 |
| 职业与战斗 | DK、天赋、技能、装备、输出、单刷 |
| 任务与练级 | 任务机制、共享、BUG、声望、路线 |
| 副本与活动 | 副本机制、Boss、掉落、组队、活动 |
| 经济与交易 | 金价、材料价、供需、拍卖、交易风险 |
| 专业技能 | 采集、制造、分解、转化、专业收益 |
| 工具与操作 | 插件、宏、界面、效率工具 |
| 其他游戏信息 | 暂时无法稳定归类的有效内容 |

“打金”“当前项目相关”“适合练级”等是用途标签，不与主分类并列。下一级继续按具体对象细分，例如“职业与战斗 → DK → 天赋”。

## 事实优先的信息卡

每条实质信息按固定顺序展示：

### 1. 事实信息

先准确说明群聊里实际出现了什么内容。群友说法只能写成“有人提到、声称或分享”，不能因为 AI 做了整理就变成外部已证实事实。

### 2. 群聊原文

默认保留支撑事实的完整相关原文和必要上下文。原文特别长时可以节选，但必须标明是节选，并保持连续原句。不得把不同位置的句子拼成一段看似来自群友的原话。

### 3. AI 扩展分析

事实和原文之后，才允许增加明确标注的 AI 判断，例如：

- 攻略提炼；
- 经验提炼；
- 趋势判断；
- 打金或其它机会线索；
- 对当前 DK、五开、任务路线或魔兽项目的影响；
- 不确定点和建议核验方式。

例如“即将开放新服”可以是来源事实；“这可能导致时光服金价下跌”只能作为趋势判断，并同时显示依据、条件和不确定性。

## 黑话的特殊处理

纯黑话消息不生成普通话题卡，只更新独立黑话库。黑话库保存：

- 词语；
- 当前解释；
- 适用副本、物品、服务器或聊天语境；
- 最小必要原文；
- 首次与最近出现时间；
- 是否待核验。

如果一条实质信息同时包含黑话，事实卡仍正常展示；黑话含义另外进入词典，但不复制整张事实卡。

## 价值、可信度与热度

三者分别表达不同问题：

- **个人价值**：值不值得用户现在看；
- **可信度**：目前能信到什么程度；
- **讨论情况**：有多少人、多少次谈到，只作为背景。

个人价值分为：

| 等级 | 含义 |
| --- | --- |
| 必看 | 直接影响当前项目、角色、打金方式或近期决策 |
| 应该看 | 有明确操作价值、收益机会、避坑价值或重要跟踪变化 |
| 可以看 | 当前用不上，但可能形成未来攻略、知识或机会 |
| 留档 | 当前用途不明显，但属于真实、有意义的信息 |

可信度单独标为多人独立支持、单人具体经验、传闻、存在争议或待核验。证据较弱不能抹掉高价值线索；讨论热度高也不能自动提高价值等级。

## 页面 v2 信息架构

页面使用六个视图读取同一份分析结果：

1. **本期总览**：必看、应该看、重要跟踪更新和处理状态；
2. **话题总览**：按统一分类完整列出本批所有有意义话题；
3. **长期追踪**：价格、版本、服务器生态和其它持续变化的信息；
4. **攻略知识**：职业、任务、副本、专业技能、交易与打金方法；
5. **项目相关**：可能影响当前魔兽项目的候选和核验状态；
6. **黑话**：独立、语境化、持续更新的玩家用语词典。

“话题总览”不恢复页面 v1 已删除的“全部信息”页。旧“全部信息”只是重复生成一份浅摘要；新“话题总览”是覆盖导航，确保低优先级有效内容仍可被找到。

同一条信息只保存一份，可以因为标签和状态同时出现在总览、长期追踪、攻略知识或项目相关视图。

## 建议的数据单元

页面实现前，分析结果至少要能表达：

- 所属主分类与二级对象；
- 事实标题与事实说明；
- 原文证据和上下文引用；
- AI 扩展分析及其类型；
- 个人价值等级与理由；
- 可信度与争议状态；
- 首次出现、最近更新和时间范围；
- 是否长期追踪、可沉淀攻略或项目候选；
- 是否包含需要更新到黑话库的词语。

## 完整性门禁

页面只展示重点不代表分析可以先过滤。正式分析需要记录本批：

- 已归入话题的消息；
- 只进入黑话库的消息；
- 无语义闲聊、广告和刷屏；
- 无法分类或待判断的线索；
- 由于非文字媒体无法分析的占位消息。

分块时每块先宽松提取，再跨块归组和排序。不能用关键词预筛，也不能用“只有一人说过”作为排除条件。
