## 信息价值模型的关键修正

### 1. 第一轮 topic card 只是索引，不是最终成品

第一轮切卡的目标是避免漏掉语义，因此允许较碎。最终页面可以：

- 合并多个原卡；
- 隐藏单独没有决策意义的节点；
- 从 canonical 原文补回第一轮漏掉的硬信息；
- 把一张混合卡拆成两条真正独立的信息；
- 在发现第一轮串人、错链或错误总结时，把原卡退出默认审阅流而保留可追溯记录。

因此后续不能把“整理 3124 张卡”误解成“逐张润色后全部展示”。

### 2. 主信息必须能转化成可复用知识

“真实发生过”“有人实测”“有数字”“多人反复说”“描述很具体”都不是进入主信息的充分条件。

当前主信息优先保留：

- 明确机制；
- 可复用路线/玩法；
- 明确排雷：触发条件 / 原因 / 正确动作中至少能形成可迁移关系；
- 有完整比较基线的时间、成本、装备、收益或阶段样本；
- 能改变操作、选择或判断的具体信息。

默认退出主信息的典型内容：

- 玩家审美、情绪、叙事体验和生活安排；
- 只说明“有人这么玩/这么想/这么倒霉”的经历；
- 缺职业/装备/阶段/场景等关键基线的单个数字；
- 只有方向性原则但没有具体输入的信息；
- 项目已经明确掌握、且没有新增边界/例外的基础事实；
- 纯萌新基础错误、可由游戏最基础 UI 直接解决的问题；
- 黑话/术语本身。

用户显式判断继续高于 GPT 初排；“无用”可以退出默认流，但原卡/canonical 不被删除。

### 3. 案例只有能提炼出机制/排雷才有主信息价值

案例分为：

- 排雷案例：错误/触发条件 → 原因 → 正确动作；
- 机制实测：单次操作足以证明明确机制关系；
- 数值样本：只有比较基线足够时才有独立价值；
- 经历记录：无可迁移结论，隐藏。

例如“同时点了双手路线和萨萨里安的威胁”只有在能解释为“双手与双持路线混搭、浪费天赋点”的 DK 排雷时才值得保留；“某人点错了”本身没有价值。

## 纵向连续实测：从节点卡转为过程卡

本阶段用同一玩家的 DK 升级记录验证了新的聚合边界。

原先独立出现的 78 / 79 / 80 等等级节点，单独展示没有意义。确认同一发言人、同一角色、同一连续过程后，改成一张：

`同一玩家双持冰DK：67→80连续实测`

首屏只保留：起止等级、路线、主要升级方式、日历跨度及“不是净在线练级时间”的边界。每日等级节点只留在跨日证据原文中，不再占首屏。

重要约束：

- 不能只因“DK + 等级”相似就串成同一过程；
- 必须至少确认同一发言人、同一角色/对象、同一连续过程；
- 已发现第一轮把另一个发言人的 61 级 DK 节点错误串入后续升级链，该卡已退出默认流；
- 第一轮 topic cards 漏掉的 74 / 75 等节点可以直接从完整 canonical 补入聚合证据，因此聚合不能只依赖已有卡。

## 职业页与黑话页

职业页用于“这个职业本身的玩法/机制/路线/排雷”，不是“正文里提到过这个职业”。

本阶段在 DK 上经过多轮人工收敛，验证出：

- `BDK=血系DPS`、`DKT=DK坦克`、`红脸=鲜血灵气` 属于群内黑话/术语，移出 DK 主信息；
- 职业/专精/阵营概念混淆、不能用某类基础装备等纯新手问题不占主信息；
- “先确定最终武器路线”若没有任何具体装备/门槛/操作，只是抽象原则，也不占主信息；
- 具体路线、机制、排雷和已确认的低成本过渡方案才继续留在职业主信息。

相同标准已经推广到其它职业与非职业信息；后续仍需用户逐页继续人工复核并进一步收敛。

黑话页不依赖合集是否定型，因此已提前落成；词义继续按 `rules/analysis.md` 的语境化词典规则维护。

## 原文可靠性修正

### 1. 旧的关键词式高置信回链已废弃

早期页面曾使用全日关键词/数字搜索为 topic card 自动寻找原文，出现过 DK 78 级卡链接到无关装备聊天的问题。

现行原型只把卡片自身保存的 `time_range` 作为用户可见原文主锚点；时间窗口命中后仍需语义线索才能称“可直接查看”。宁可标待补，也不展示猜测原文。

### 2. 相邻截图重叠造成的重复已定位并修复

2026-10-12 00:51 的 ZAM / 鸟德 / 树皮讨论在 canonical 中出现两份近似消息。根因不是页面简单重复，而是：

- 相邻 raw 页 `page-000305` / `page-000306` 有重叠；
- 一页顶部只识别到 headerless `top fragment`；
- 下一页把同一文字合并进完整回复消息；
- 旧 overlap 算法要求连续消息结构一一对应，被这个残片阻断，于是整个前序重叠没有消除；
- 同一文字还存在轻微 OCR 差异，如 `乌德 / 鸟德`。

现已在 normalizer 中保留 fragment kind 作为**瞬态重建元数据**，不进入 message-record schema；只有当旧页顶残片的规范化长文本明确被新页附近完整消息包含时，才允许该残片不阻断已经确认的连续多消息 overlap。未被覆盖的残片继续保留。

回归测试新增“covered top fragment 不阻断强重叠”和“uncovered top fragment 必须保留”，相关 `normalize overlap + assemble` 共 **26 项测试通过**。

为避免修改旧 canonical 导致大量历史 `source_ranges` 行号整体偏移，本阶段不直接删除旧历史行；页面详情层对已确认的重叠消息做保守去重。

### 3. QQ 回复引用与重复消息分开显示

QQ 回复气泡可能 OCR 成：`被回复者 + 被回复正文 + 新 @回复` 三段，并被误看成上一句话再次重复。

页面详情现在会在确认引用正文已紧邻出现时折叠引用，只显示 `↳ 回复某人` 和真正的新回复正文。canonical 仍保留可见 OCR 内容。

## 合集展示尚未定型

本阶段形成的新判断是：当主信息已经收敛到每天很少、用户可以日常快速审阅时，独立“合集”标签页的必要性会下降。

一个更自然的候选方向是：

`连续/强相关事实组 → 各条明细与原文 → 组内最终综合结论`

即把原“合集”的价值变成相关信息组内部的阶段总结，而不是再做一套平行的信息页面。

但当前仍未定型。应等其它职业和非职业主信息继续人工审阅、进一步收敛后再决定；现在不把此方向写成正式 UI 契约。
