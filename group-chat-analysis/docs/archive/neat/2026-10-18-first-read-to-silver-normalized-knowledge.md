# 2026-10-18 — 首次阅读模型转向 Silver 规范化知识单元归档

## 阶段范围

本阶段承接 `2026-10-16-analysis-v2-value-convergence-and-source-fidelity.md`。用户在真实页面审阅中确认：旧版把大量信息压到“待核验”后漏掉了值得第一次看一眼的内容；恢复宽召回后又暴露出另一个根问题——**第一轮 Topic Card 只是语义切片，不能直接作为最终阅读单元、资料库条目或动态专题内容**。

因此本阶段不再继续围绕“主信息 / 待核验”做价值压缩，而是正式引入 **Silver 语义清洗层**：在原始候选与页面之间完成跨日去重、实体对齐、结构化和证据挂接，再把结果投影到低摩擦页面。

## 已稳定的用户使用模型

- 页面优先保证“值得第一次看一眼的信息尽量不漏”，最终价值判断留给用户。
- 用户终审只有两种：`没用` / `存资料库`。两者都视为已阅；只有后者进入长期知识。
- 单纯可信度升降、更多人重复同一结论只在后台更新证据状态，不重新占阅读队列。
- 用户日常需要的是最低操作摩擦，不需要 AIHOT 式复杂仪表盘。
- 页面顶层继续只保留：`新信息 / 资料库 / 无限服 / 黑话`。
- 职业与副本、任务、装备、插件、防骗等都是同级专题入口，不做职业 × 专题的组合筛选。
- 资料库主要用于以后只记得部分关键词时找回知识，不要求日常浏览。
- 无限服目前是唯一动态专题，因为封测阶段的零散观察组合后可能形成服务器发展、经济与打金机会的完整认知。

## 根问题：缺少真正的数据清洗层

此前链路近似是：

`canonical聊天 → Topic Card → 页面`

这导致：

- 同一结论的概括、解释和实例各占一张卡；
- 同一话题跨多天讨论时被日期切碎；
- 路线/升级链只是“把几句话写成一段更顺的中文”，用户实际使用时仍需自己重新拆步骤；
- 比较类信息会变成“A一条 + B一条 + 再来一条总结”；
- 无限服动态档案只是长段自然语言总结，难以持续更新单个状态字段。

现行目标链路改为：

`canonical聊天 → Topic Card候选索引 → Silver规范化知识单元 → 新信息 / 资料库 / 无限服动态专题 / 黑话`

Topic Card 保留用于追溯、重建和漏项检查，但不再视作页面最终信息。

## Silver 规范化知识单元

稳定字段至少包括：

- `subject`：明确对象；
- `question`：这组信息回答什么问题；
- `kind`：知识形状；
- `scope`：版本、服务器、阶段、职业、等级、时间等适用边界；
- `canonical_facts`：去重后的核心事实；
- `structured`：按知识形状保存的固定结构；
- `evidence_refs`：来源卡及其证据角色；
- `search_terms`：正式名、俗称、缩写、ID 等检索词；
- `evidence_state`：后台证据状态；
- `freshness`：静态、阶段性或动态信息。

当前验证的结构类型：

- `ordered_route`：阶段/步骤链，使用 `条件 → 做什么 → 获得/练什么 → 用途 → 备注`；
- `comparison`：同一比较对象下保存多个 `variant`；
- `mechanism`：条件 / 机制 / 动作 / 结果 / 失败后果；
- `strategy`：准备 / 步骤 / 切换条件 / 失败点；
- `sample`：场景 / 观测值 / 比较边界；
- `dynamic_signal`：观察维度 / 当前状态 / 指标 / 变化时间 / 未解决问题。

类型不是封闭枚举。后续遇到不适合这些模板的知识，应先分析其稳定形状，必要时新增类型；不能为了“标准化”把内容强塞进错误表格。

## 4 个 pilot 样例

私密 runtime 中已建立 `normalized-knowledge-pilot-v1.json`，用 4 个规范化单元吸收 20 张来源卡，验证数据形状；**这不是全量清洗完成**。

### NAXX 装备追赶

原先“199鸟德可进NAXX”“一车199→228”“NAXX适合作为P4/P5追赶”不再各占一条。

Silver 单元保存一个核心结论：NAXX 在当前阶段可作为低装等满级角色向后续阶段追装的节点；`199→228` 只是 `concrete_sample` 证据。

### 区服组团方式比较

“二区常把NAXX与双龙捆绑”“四区联盟更常分开”“组团方式是区服变量”合成一个 `comparison`。

标准结构直接回答：不同区服行为有什么差异、这种差异在估算集合石团型/清CD时间时有什么影响，并补齐当前语境下“双龙”的对象身份。

### 坦克学习路线

原先普通5人本、旧团本、NAXX、P5、TOC分别占卡，现改为一条有序学习阶梯：

1. 普通5人本：拉怪、技能、基础仇恨；
2. ZG/双龙/MC/SSC/TK 等旧团本：团本节奏、站位、朝向；
3. NAXX：僵尸、多目标、减伤，作为中期考试节点；
4. P5：更高惩罚环境；
5. TOC尤其虫阶段：换坦、位置、多目标和高压机制。

“先DPS观察成熟坦”“公会/新手团更适合练习”等放在同一知识单元的辅助规则里，不再散成多张卡。

### 双持冰DK 70→80武器链

原来的长段自然语言资料改成 `ordered_route`：70级AH占位 → 74/75祖达克任务武器 → 80级美酒节窗口武器；每阶段独立保存条件、动作、物品/收益、用途和时效备注。

这是用户已经确认有价值的资料库条目，因此不重新进入新信息队列。

## 对象身份补齐

展示前基础身份补齐是分析职责，不是额外“可补全研究”。当前已经用弗约恩案例验证：

- 地图：风暴峭壁；
- 任务：《弥补关系》；
- 任务 ID：12915；
- 简要任务目标；
- 群聊真正新增的控制栏/操作排雷。

后续优先扩展到：

- 任务：地图 / 正式名称 / ID / 简要目标；
- Boss：副本 / 阶段或等级 / Boss名称 / 顺序 / 相关难度；
- 职业阈值：职业专精 / 版本 / 具体数值 / 适用条件；
- 装备：正式名称 / ID / 部位 / 来源 / 限制。

只有需要额外联网研究、比对多个来源才能补足关键结论的内容，才标为“可补全候选”。

## 无限服动态专题 v2

`runtime/analysis-work/infinite-dossier-v1.json` 已升级为结构化 schema v2。六个现有维度不再保存长段 `current_view`，而保存一组动态信号：

`观察字段 / 当前状态 / 适用范围 / 依据 / 证据ID`

当前维度：练级与玩家发展、经济与打金、专业与资源、规则与风险、职业与玩法变化、服务器生态。

后续重复观察只增强后台证据；只有状态或边界变化才产生新的可见更新。AI 对经济阶段、供需或玩家发展阶段的综合判断只能建立在这些来源信号之上，不能覆盖来源事实。

## 分析窗口与阅读批次分离

历史补课需要跨半个月甚至更长范围统一清洗，否则相同话题会继续按日期碎裂。但用户不需要一次处理整段历史。

现行原则：

`完整分析窗口统一聚类/清洗 → 得到规范化知识单元 → 页面再分页给用户处理`

当前原型每批最多 40 个阅读单元。分页只控制阅读负载，不参与语义切分。未来正常日常增量通常天然只有一天左右，历史回看才特别依赖这一层分离。
