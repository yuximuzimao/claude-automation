## 已验证事实

1. 当前 macOS/黑苹果环境中，QQ 官方客户端可由系统正常激活。
2. QQ 的 macOS Accessibility 树对聊天正文暴露不足，不能作为正文主读取通道。
3. 屏幕像素捕获 + Apple Vision 本地 OCR 已实测可识别当前 QQ 群的群名、昵称、时间和聊天正文。
4. 键盘 Page Up 受焦点影响，不适合作为正式翻页控制。
5. 系统滚轮事件在已确认的消息区域可稳定向历史方向滚动，不需要点击输入框或发送按键文字。
6. QQ“聊天记录”是独立的 QQ 窗口，窗口标题直接等于当前群名，可作为 OCR 前的目标群校验。
7. 聊天记录窗口可由 ScreenCaptureKit 独立捕获；Apple Vision 能稳定识别日期、昵称/正文和多条消息时间。
8. 动态滚轮锚点由当前页 OCR 中的真实正文块选择，不依赖固定屏幕坐标。
9. 历史方向在当前环境中使用负向 pixel wheel。
10. 滚动距离按当前聊天记录窗口高度约 61% 动态计算，不使用固定像素。
11. `1033px` 高窗口时约为 `630px`；`720px` 高窗口时约为 `439px`；`982px` 高窗口时约为 `599px`。
12. 小窗口约 `660×720` 的正式 3 屏测试中，相邻正文重叠约 `37.5% / 27.3%`，连续相同块均为 2。
13. 放大窗口约 `1442×982` 的正式 3 屏测试中，相邻正文重叠约 `45.5% / 18.2%`，连续相同块为 5 / 2。
14. QQ 每次重新打开聊天记录可能把窗口恢复为较小尺寸。正式入口已支持启动时自动拖动右下角边框放大窗口，不要求用户手动调整。
15. 自动放大回归已通过：窗口从约 `662×722` 自动拉到 `1452×978`，随后成功捕获 27 个 OCR block。
16. v1 抓取期间聊天记录窗口必须保持前台；程序只在开始时激活 QQ，进入抓取循环后用户若切走则停止，不应自动抢回。
17. 正式单页入口：`src/app/capture-once.swift`。
18. 正式最小多页入口：`src/app/capture-pages.swift`。
19. raw page 契约：`schemas/capture-page.schema.json`；真实单页输出已通过结构/类型/范围校验。
20. 错误群标题会拒绝捕获；已有 raw page 会拒绝覆盖；`runtime/` 与 `build/` 均确认被 Git ignore。
21. 时间不能单独作为消息唯一 ID：同一分钟可以连续出现多条消息；后续去重必须依赖连续消息序列。
