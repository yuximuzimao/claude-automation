# 采集规则

## 目标

从官方 QQ 当前可见/可滚动的指定群聊中取得尽可能完整的文字视觉信息，同时把对 QQ 的操作限制在最低必要范围。

## 允许的控制动作

默认只允许：

- 激活 QQ；
- 读取窗口几何/标题等系统可见元信息；
- 在正式采集开始时，必要时拖动聊天记录窗口右下角边框把窗口放大；
- 移动鼠标到已确认的聊天正文安全区域；
- 发送滚轮事件；
- 屏幕/窗口像素捕获；
- Apple Vision 本地 OCR。

不得：

- 点击输入框；
- 键入或粘贴聊天内容；
- 发送消息；
- 修改群设置；
- 加/退群；
- 自动操作成员列表；
- 依赖非官方 QQ 插件或注入。

如果后续确实需要“点击群列表切换目标群”，必须单独设计可验证的安全点击路径，且点击前确认目标控件不可能是发送/确认类动作。

## 正文读取优先级

1. **QQ 聊天记录独立窗口 + 窗口级像素捕获**：正式主路径。该窗口可由系统枚举为独立 QQ 窗口，标题直接提供当前群名，可在进入 OCR 前做目标群校验；历史滚动不依赖主聊天输入区。
2. **QQ 主聊天窗口 + 窗口级像素捕获**：fallback。已验证全屏和普通窗口下可动态定位消息区并安全滚动，但活跃群新消息可能扰动历史滚动位置，因此不作为首次全量/每日历史采集的首选。
3. **屏幕捕获 + 系统窗口几何裁剪**：窗口级捕获不可用时的 fallback；QQ/macOS 环境变化后重新验证。
4. Accessibility 正文只作为可选辅助，不作为正文主路径。

不得因前述路径不完美升级到进程注入、数据库解密或协议抓取。

## 聊天记录窗口

QQ 每次重新打开聊天记录时可能恢复为较小默认尺寸，因此正式采集不能依赖上一次窗口尺寸。

v1 启动流程：

1. 激活 QQ 一次。
2. 找到 owner=QQ 且标题精确匹配目标群的聊天记录窗口。
3. 若窗口明显偏小，则只拖动右下角窗口边框，把它扩大到当前显示器可用范围附近。
4. 放大完成后重新读取窗口实际尺寸，再进入捕获。
5. 若窗口尺寸已足够大，则不重复调整。

已实测默认约 `662×722` 的窗口可自动放大到约 `1452×978`；单屏 OCR block 从约 `19~21` 提高到约 `27`。

窗口调整只发生在采集开始阶段；连续采集过程中不反复拉伸。

## 聊天区域

不得长期写死绝对屏幕坐标。

正式实现应把聊天区域表示为：

- 当前 QQ 窗口实时几何；
- 相对于窗口的聊天区；
- 必要时结合群标题等视觉/系统信号校验。

聊天记录主路径优先利用其独立窗口标题校验目标群：窗口 owner 必须是 QQ，窗口标题必须匹配当前目标群配置。标题不匹配时本轮立即停止，不把 OCR 结果写入 messages。

主聊天 fallback 仍不得写死绝对屏幕坐标；当前已验证可通过像素长边界重新定位正文安全矩形。

## 前台规则

v1 抓取期间聊天记录窗口必须保持前台。

正式程序只允许在采集开始时激活 QQ；进入连续抓取循环后不得在用户切走时再次抢回 QQ 前台。

每页本来就需要读取当前窗口，因此只顺手检查：

- QQ 仍是前台；
- 当前聊天记录窗口仍可见且尺寸大于最低门槛；
- 窗口标题仍匹配目标群；
- 连续采集时窗口 ID 未意外变化。

任一检查失败立即停止本轮。后续 state 层必须把这种中断记录为 incomplete。

## OCR前变化检测

滚动后先对聊天区域生成低成本图像指纹。

- 画面显著变化 → 进入 Vision OCR。
- 几乎未变化 → 等待有限时间后再检测。
- 连续有限次数无变化 → 交由状态机判断“未滚动成功 / 正在加载 / 已到边界”，不得无限重试。

变化检测是性能与可靠性门禁，不代替消息级去重。

## Vision OCR

- 使用 macOS Apple Vision。
- 优先内存中的图像对象直接 OCR。
- 保留每个识别块的 text、bbox、confidence 和当前 page_index。
- 识别语言至少覆盖简体中文和英文。
- OCR低置信文本仍可保留到 raw 层，但不得擅自“纠正”为模型猜测文本。

## 滚动

正式滚动以聊天记录窗口消息列表中的真实 OCR 正文块作为安全鼠标锚点，不依赖 Page Up 键盘焦点，也不使用固定绝对坐标。

历史方向在当前 QQ/macOS 环境中使用负向 pixel wheel。

滚动距离不是固定像素，而是按**当前聊天记录窗口高度约 61%**计算。该比例来自真实重叠测试：在 `1033px` 高窗口下约等于 `630px`；在 `720px` 高窗口下自动换算为约 `439px`；在 `982px` 高窗口下约 `599px`。

目标是降低重复 OCR 页数，同时保留连续跨页锚点。真实 3 屏测试中：

- 小窗口约 `660×720`：相邻正文重叠约 `37.5% / 27.3%`，连续相同块均为 2；
- 放大窗口约 `1442×982`：相邻正文重叠约 `45.5% / 18.2%`，连续相同块为 5 / 2。

因此当前 61% 是 v1 实测参数，不是永久协议常量；未来正式模糊序列匹配成熟后可再重新标定。

聊天记录中的可见时间是强锚点，但不是唯一 ID：同一分钟可能有多条消息。跨屏匹配必须组合时间、昵称/正文和前后连续序列，禁止只按时间去重。

## 停止条件

### 首次全量

达到用户给定历史边界、QQ实际可取边界，或经过明确验证的顶部/无变化边界。

### 每日增量

可靠命中上次 completed batch 保存的消息连续序列锚点。

“今天/昨天”文本只能辅助，不得作为唯一停止依据。

## 用户可见完成信号

连续采集开始和结束/中断都应给用户明确提示，避免用户因为看不到某一瞬间的滚动而误以为已经结束。

v1 可以使用系统通知 + 提示音；提示只是用户体验信号，不参与 capture 完整性判断。

## 失败原则

- 捕获到错误应用/错误群：本页作废，停止本轮，不写入 messages。
- 用户中途切走：立即停止，不自动抢回 QQ。
- OCR失败：允许有限重试；原画面仍在时不先滚走。
- 滚动状态不确定：宁可停止为 incomplete，也不假装完整。
- 任何可能导致发送消息或业务写操作的异常路径：立即停止。
