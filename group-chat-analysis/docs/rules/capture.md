# 采集规则

## 目标

从官方 QQ 当前可见/可滚动的指定群聊中取得尽可能完整的文字视觉信息，同时把对 QQ 的操作限制在最低必要范围。

## 允许的控制动作

默认只允许：

- 激活 QQ；
- 读取窗口几何/标题等系统可见元信息；
- 通过 macOS Accessibility 仅调整已确认聊天记录窗口的位置与大小；
- 移动鼠标到已确认的聊天正文安全区域；
- 发送滚轮事件；
- 屏幕/窗口像素捕获；
- Apple Vision 本地 OCR。

不得：

- 点击输入框；
- 键入或粘贴聊天内容；
- 发送消息；
- 修改群设置；
- 加/退群；
- 自动操作成员列表；
- 依赖非官方 QQ 插件或注入。

目标群切换只允许走已验证的安全路径：先在主 QQ 窗口用 Vision OCR 找到会话列表中的唯一目标行，并确认其 bbox 中心位于左侧会话安全区；点击后重新 OCR 主聊天头部确认目标；随后仅 hover 已校准的历史记录图标位置，局部 OCR 必须精确得到 `聊天记录` 才允许点击；最后等待唯一历史窗口的标题与配置中的 `history_title` 精确一致。任何一步不满足都停止，不允许退化成盲点坐标。

## 正文读取优先级

1. 窗口级像素捕获：全屏实验验证稳定后优先。
2. 屏幕捕获 + 系统窗口几何裁剪：窗口级捕获不可用时的 fallback；QQ/macOS 环境变化后重新验证。
3. Accessibility 正文只作为可选辅助，不作为正文主路径。

不得因 1/2 不完美升级到进程注入、数据库解密或协议抓取。

## 聊天区域

不得长期写死绝对屏幕坐标。

正式实现应把聊天区域表示为：
- 当前 QQ 窗口实时几何；
- 相对于窗口的聊天区；
- 必要时结合群标题等视觉/系统信号校验。

每轮正式采集前都要重新确认当前窗口仍是 QQ 且当前会话是目标群，避免 OCR 到其它应用或其它群。

历史窗口正文上边界只能由同一水平带内至少两个过滤控件共同确认；正文里偶然出现“表情 / 文件 / 链接”等词不能单独定义工具栏位置。

## 窗口准备

QQ“聊天记录”窗口重新打开后可能恢复默认几何。正式采集前按以下顺序准备：

1. 只在官方 QQ 进程中查找标题与目标群配置一致的 `AXWindow`；不得用“最大窗口”之类的模糊规则代替目标确认。
2. 确认 `AXPosition` 与 `AXSize` 可写后，通过 macOS Accessibility 设置本机配置中的目标位置和大小；窗口几何属于本机配置，不写死进正文定位算法。
3. 设置后立即读回位置和大小并做小范围容差校验；失败则停止本轮，不改用鼠标拖窗口继续碰运气。
4. AX 读回成功不代表 QQ/SCK 已完成窗口布局。必须再在有限检查点内由 ScreenCaptureKit 重新取得**唯一同标题窗口**，等待其 frame 落入目标几何的小范围容差；未稳定则停止。不得直接用刚设置完 AX 后的瞬时 SCK frame 做滚轮坐标映射。
5. SCK 几何稳定后重新动态定位正文区域；只有这些检查都成功才进入正式捕获。

窗口准备只改变窗口框架，不点击聊天内容、输入框或任何发送/确认控件。常规流程不使用鼠标拖标题栏或缩放角作为 fallback。

## OCR前变化检测

正式指标使用正文区域的稀疏 RGB mean absolute difference（MAD）：按固定步长抽样像素，计算两帧 RGB 三通道绝对差的平均值。该门禁只判断“画面有没有变化、是否已稳定”，不做消息级去重。

当前环境经真实聊天记录窗口校准后，默认阈值为：
- `MAD <= 0.10`：视为静止/噪声范围；
- `MAD >= 0.50`：视为发生了明确内容变化；
- `0.10 < MAD < 0.50`：视为不确定，继续等待后复测，不直接进入 OCR。

检测时序：
1. 第一次把鼠标移动到正文安全落点后，先等待约 `300ms`，避开 QQ 自身 hover/滚动条变化，再保存滚动前 baseline。
2. 发送滚轮事件后约 `100ms` 取第一帧；随后在约 `250ms / 500ms / 1000ms` 检查后续帧。
3. 只有**当前最终帧**相对 baseline 仍 `>= 0.50`，且相邻两次采样 `<= 0.10`，才判定为“已变化且稳定”并进入 Vision OCR。若中途曾明显变化但随后又回到 baseline，不得当作新页。
4. 若采样间仍 `> 0.10`，说明画面仍在变化/加载，继续到下一个有限检查点。
5. 若至少检查到 `500ms` 仍始终相对 baseline `<= 0.10`，输出“无变化”给状态机判断“未滚动成功 / 已到边界”；变化检测层自身不猜边界原因。
6. 到 `1000ms` 仍处于不确定或持续变化状态，则停止本次 OCR 门禁并上报状态机；不得无限等待或无限重试。

这些数值属于当前 QQ/macOS/显示缩放环境的校准值。若窗口渲染、显示缩放或 QQ UI 明显变化，应重新做静态噪声与正常滚动两组校准，而不是沿用旧阈值。

## Vision OCR

- 使用 macOS Apple Vision。
- 优先内存中的图像对象直接 OCR。
- 识别语言至少覆盖简体中文和英文。
- OCR低置信文本仍可保留到 raw 层，但不得擅自“纠正”为模型猜测文本。

### capture 输出契约

单页 raw 输出必须符合 `schemas/capture-page.schema.json`；字段、类型、必填项与坐标约定只以该 Schema 为准，本规则不维护第二份字段定义。

稳定行为语义：
- batch/group/page/window 等公共上下文只存页级 envelope，不在每个 OCR block 重复；
- `page_index` 表示采集顺序，不表示聊天时间顺序；
- 同一 incomplete batch 恢复时沿用原 `batch_id`；
- capture 只保存 Apple Vision 看到的原始 OCR 结果，不判断“昵称/时间/正文”等消息语义；
- capture-page v2 额外保存私密 `dhash512` 视口指纹。它只用于验证当前窗口仍停在上一份 durable raw 对应视口，不得用于昵称/成员/消息身份判断。

## 滚动

正式滚动以聊天正文区域上的系统滚轮事件为主，不依赖 Page Up 键盘焦点。

每次滚动应保留一定屏幕重叠，不追求整屏跳跃；重叠是后续可靠去重的重要证据。

发滚轮前必须重新截取当前窗口并与上一份 durable raw 的 `dhash512` 比较。当前环境校准：同一未滚动视口连续样本 Hamming distance 最大 `18`，不同真实页最低 `31`，因此正式门槛取 `<=20`。超过门槛时必须在滚动前停止；不得把该阈值用于消息去重。

MAD 比较允许 SCK 捕获尺寸出现 `<=3px` 的小漂移，并把两帧渲染到共同尺寸后比较；任一方向漂移超过 3px 仍视为异常并停止。

## 停止条件

### 首次全量
达到用户给定历史边界、QQ实际可取边界，或经过明确验证的顶部/无变化边界。

### 每日增量
可靠命中上次 completed batch 保存的消息连续序列锚点。

“今天/昨天”文本只能辅助，不得作为唯一停止依据。

## 失败原则

- 捕获到错误应用/错误群：本页作废，停止本轮，不写入 messages。
- OCR失败：允许有限重试；原画面仍在时不先滚走。
- 滚动状态不确定：宁可停止为 incomplete，也不假装完整。
- 任何可能导致发送消息或业务写操作的异常路径：立即停止。
