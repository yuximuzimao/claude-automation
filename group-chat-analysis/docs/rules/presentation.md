# 页面展示投影规则

本文件只负责 **Silver → 用户可读 QA** 的展示与审核契约。事实清洗、证据归并、Silver 语义边界仍以 `analysis.md` 为准；本文件不得反向修改 Silver 事实层。

## 目标

页面默认只回答“我现在需要知道什么”。默认阅读层应尽量短，复杂证据、来源、判档理由和核验建议只在用户主动展开时出现。

标准结构：

`问题 + 结论 + 单字置信度 + 可选时间节点 + 折叠依据`

## Silver 与 QA 的边界

- Silver 继续作为同一知识主题与证据的稳定容器，不因展示需要拆写正式 Silver。
- 一个 Silver 可以投影成多个独立 QA。
- 是否拆 QA 不看事实数量，只看两个结论是否可以被**分别搜索**，并且会**分别改变判断或操作**。
- 只是同一结论的原因、样本、例子、反例或证据时，不拆 QA，放入折叠依据。
- QA 的增删、合并、重写不改变原 Silver 的 canonical facts、evidence refs 或用户既有 Silver 裁决。

## 默认可见内容

每个 QA 默认只显示：

1. 问题；
2. 一句或极短一段直接结论；
3. `高 / 中 / 低` 单字置信度标志；
4. 只有在省略会导致误用时才显示的适用条件；
5. 时效性 QA 必须显示的时间节点。

以下内容默认收起：

- 依据与原文；
- 证据类型、发言人、样本数量；
- 判档原因；
- 建议核验的具体内容；
- 冲突证据的详细展开。

## 标签最小化

除置信度外，默认**零标签**。

职业、副本、地图、对象名、来源类型等如果已经由一级/二级分类、当前搜索词、QA 问题或结论提供，就不得再次作为标签重复展示。

只有“不显示就可能让用户错误使用结论”的条件才允许进入默认层，而且优先写进问题或答案本身，而不是制造新的标签。

## 置信度

置信度描述的是“这条 QA 目前能否拿来用”，不是统计意义上的真实性概率，不显示百分比。

- **高**：结论与关键适用条件明确，没有会改变实际操作的重大缺口；可以直接使用。
- **中**：核心结论可用，但仍有可能影响边界、效果或外推的未确认项；可以使用，重要场景建议进一步核验。
- **低**：关键条件、来源或结论本身仍有明显不确定性；仅供参考，实际使用前应核验。

判档至少考虑：结论是否明确、适用范围是否明确、证据是否互相支持、是否存在会改变实际操作的关键缺口。

不得把“玩家实测 / 群友建议 / 多人重复”等来源类型机械映射为固定置信度。

## 核验提示

- “缺口”不是必填字段。
- 只有缺失信息可能改变结论、适用条件或实际操作时，才需要内部记录核验内容。
- 默认正文不展开“建议核验”的具体说明；中/低置信度标志已经承担第一层提醒。
- 具体核验原因放进折叠详情，用户需要时再查看或单独让模型进一步查询。

## 时效性与生命周期

展示 QA 至少区分：

- `durable`：预期跨当前阶段仍有复用价值；
- `time_bound`：价格、工资、首周/首CD、版本开放前预测、临时活动窗口等只在特定时间段有意义。

`time_bound` 必须带清楚的时间节点或阶段描述。它可以保留为历史阶段信号，但不得自动进入长期总资料库，也不得把当时预测改写成长期通用规律。

如果后续出现实际结果，可建立“已验证 / 被推翻 / 部分验证”的关系；没有后续证据时，保持当时阶段记录，不补写结果。

## 审核粒度

最终用户审核对象是 QA，而不是强迫用户对整个 Silver 一刀切。

- 如果一个 QA 的唯一价值只是把群聊里的缩写、称呼、压缩口令或玩家说法翻译成可理解的词义，它不进入普通 QA 审核/资料库队列，直接进入独立黑话词典；若同一 Silver 还包含可独立使用的打法、机制、数值或决策信息，只移出纯词义 QA，其余 QA 保留。包含黑话不等于整条信息属于黑话。

- 一个 Silver 内某个 QA 可以单独“没用”，其余 QA 不受影响。
- 既有 Silver 级用户裁决必须保留；展示层迁移时不得静默改写用户历史决定。
- `time_bound` QA 不应通过普通“存资料库”路径进入长期资料库；阶段记录的独立去向可在展示层稳定后继续完善。

## 分类与搜索

现有正式页面一级分类保持：

`职业 / 副本攻略 / 任务与练级 / 装备机制 / 专业技能 / 经济 / 打金 / 插件 / 故障排查 / 防诈骗经验 / PVP / 野外生态 / 其他`

职业和副本继续提供现有二级筛选。QA 继承父 Silver 的分类与搜索上下文，不因为拆 QA 新造一级分类。

搜索应能命中 QA 自己的问题与结论；如果父 Silver 含多个不同决策问题，搜索结果应直接落到对应 QA，而不是要求用户先打开大主题自行寻找。

## 当前阶段边界

- 先完成展示投影与历史 348 Silver 的 QA 化，不重做数据清洗。
- 旧私密 FAQ/知识候选页面只是测试中间产物，不再作为现役页面或规则来源。
- “高价值、边界清楚的信息默认自动归入资料库，用户只挑异常/不要”属于后续优化方向；在误判率未验证前不自动启用。
