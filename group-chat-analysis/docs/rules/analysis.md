# GPT 分析规则

## 输入

默认且唯一的日常入口：

`runtime/inbox/current.md`

除非排查采集错误，不让 GPT 日常读取 raw OCR、截图或状态文件。

## v1目标

从高流量群聊中筛出用户值得看的文字信息，而不是普通聊天摘要。

优先关注：

- 新服、版本、开放时间、维护、重要改动；
- 时光服/无限服具体机制；
- DK/其它职业的配置、技能、天赋、雕文、手法；
- 五开技巧；
- 任务机制、共享性、BUG、地图/路线坑点；
- 打金、金币、拍卖行、收益效率；
- 多人反复确认的经验；
- 明显争议、需要验证的说法；
- 对现有用户项目可能有影响的新线索。

普通闲聊、刷屏、广告在不影响上下文时尽量忽略。

## 输出与排序

报告不是按“群聊讨论最多的主题”平均分配篇幅，而是按**对用户当前魔兽项目的实际价值**排序。排序机制目前只作为试行，不冻结数值权重；先由以下因素综合决定从上到下的顺序：

1. 与当前执行组/路线是否直接相关：当前重点是兽人双手深鲜血 DK ×5 的户外练级、五开任务执行、特殊任务机制与路线坑点；
2. 是否能改变当前操作：五开共享/不共享、任务特殊机制、地图/路线、职业天赋/技能/雕文、户外清怪与生存、收益效率；
3. 是否是新增且可行动的信息，而不是已经掌握的常识；
4. 证据强度：多人独立确认 > 单人具体经验 > 传闻；
5. 时效性与可核验性。

用户当前没有稳定时间参加团本，因此普通团本打法/木桩配装默认降权；只有在它直接影响打金判断、职业配置、版本机制或未来项目决策时才前置。降权不等于删除：**所有有意义的信息仍应进入“全部有效信息”，排名只影响阅读顺序，不允许先关键词筛掉低优先级内容。**

页面/报告的一级结构优先采用：

- **重点发现**：所有有效发现按当前试行排序从上到下展示；
- **当前项目相关**：五开、练级、任务、路线、DK/职业配置等能直接映射到 `wow-quest-route` 的线索；
- **新增黑话**：本批新出现或本批首次解释的玩家简称/圈内表达；
- **全部有效信息**：保留其它版本、打金、装备、副本、团规等信息，确保不因当前优先级低而丢失。

每条发现仍需标记证据类型：**多人共识 / 单人经验或传闻 / 存在争议 / 待核验 / 可能影响现有项目**。没有内容的标签不为版式强行制造空项。

新增黑话必须尽量保留一条最小必要群聊原文，帮助用户从真实语境理解；若含义不确定或具有版本/服务器语境差异，必须明确标“待核验”，必要时查公开资料，不能按字面硬猜。

## 参与者价值

活跃人员明细由当前批次的分析阶段顺手生成，不建立长期昵称注册表，也不把发言数当作主要指标。GPT 可以结合以下因素判断参与价值：

- 是否提供具体事实、经验、数据或可核验线索；
- 是否有效回答问题、补充背景或纠正错误；
- 信息是否具有独立性、时效性和后续行动价值；
- 观点是否有足够上下文，还是重复、刷屏、广告或低信息量闲聊；
- 结论的证据强度，以及是否需要后续核验。

结果保留当前批次的显示昵称和消息引用；相似昵称的当前批次归并不应被解释为跨批次真实身份识别。

## 证据

重要结论应尽量保留最小必要证据：
- 群；
- 大致时间；
- 显示昵称或本地成员标识；
- 原话的简短摘录/准确转述；
- 关联上下文。

不得为了摘要流畅把多人观点合成一个并不存在的“群结论”。

## 对魔兽项目的边界

群友说法不等于已验证任务事实。

GPT分析完成后：
- 可以指出“这可能影响 DK 配置/某任务路线/新服判断”；
- 可以建议核验；
- 不能直接改 `wow-quest-route`。

只有用户明确要求进一步核验/写回后，才进入目标项目自己的规则流程。

## 模型职责

GPT负责：
- 语义筛选；
- 主题聚类；
- 争议/共识识别；
- 摘要；
- 指出需要核验的线索。

GPT不负责：
- 判断采集是否完整；
- OCR去重状态机；
- 决定滚动/重试；
- 修改原始消息；
- 自动执行跨项目写入。
