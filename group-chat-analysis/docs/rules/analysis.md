# GPT 分析规则

用途：这是 `ANALYSIS_BATCH`、`ANALYSIS_DESIGN` 和 `PROMOTION` 的唯一分析 owner。项目级任务先由 `../OPERATING-SOP.md` 分类；采集、规范化和存储问题不在这里处理。

## 输入

默认且唯一的日常入口：

`runtime/inbox/current.md`

除非排查采集错误，不让 GPT 日常读取 raw OCR、截图或状态文件。

## 分析目标

这个项目不是普通聊天摘要器，也不是热点榜。目标是从高流量、低信息密度的群聊中，完整整理有意义的话题，再按**对用户是否有用**排序，逐步形成独立的本地魔兽情报库。

优先关注：

- 对当前魔兽项目、DK、五开、练级、任务路线或打金决策有直接影响的信息；
- 版本、服务器、价格、供需等值得长期追踪的变化；
- 职业、任务、副本、专业技能、交易等可复用攻略和经验；
- 当前未使用、但以后可能产生收益或节省时间的机会线索；
- 明显争议、矛盾或需要进一步核验的说法；
- 新出现或出现新语境的玩家黑话。

普通闲聊、刷屏、广告在不影响上下文时可以不进入展示层，但不能用关键词预筛代替完整阅读。

## 批次分析 SOP

前提：对应 capture batch 已 completed，`runtime/inbox/current.md` 已由正式 builder 生成。当前没有正式分析 CLI，现阶段由 Codex/模型人工触发执行。

每个批次按以下顺序处理：

1. 读取并确认 batch id、群、消息数和时间范围，只使用 `current.md` 中的规范化消息；
2. 第一遍完整提取本批涉及的话题、具体说法、事实线索、攻略、经验、趋势推断、机会线索和黑话，不先按重要性删除；
3. 第二遍按话题合并重复内容，识别补充、更新、支持、冲突和修正关系；
4. 为每条实质信息建立“事实信息 → 群聊原文 → AI 扩展分析”，纯黑话只更新词典；
5. 分别判断个人价值、可信度、长期用途和页面去向；
6. 核对覆盖情况，区分已归组消息、纯黑话、无语义闲聊、无法分类和待判断线索；
7. 把报告和页面结果保存到 `runtime/reports/`，不得提交 Git；跨项目内容只标为候选。

一条消息只出现一次、篇幅很短或没有引起讨论，都不能成为降权或删除理由。它可以是“高价值、低可信、待核验”的线索。讨论次数和参与人数只描述聊天现象，不代表真实性，也不作为核心排序值。

分块分析时必须保持群、时间与讨论连续性。各块先宽松提取，再做跨块全局归组和排序；不得在分块前用关键词筛掉消息。

## 统一分类

话题只按“信息讨论的游戏对象或机制”使用一套主分类：

- 版本与服务器：开服、维护、热修、版本变化、服务器生态；
- 职业与战斗：职业、天赋、技能、装备、手法、单刷与生存；
- 任务与练级：任务机制、共享性、BUG、声望、地图与路线；
- 副本与活动：副本机制、Boss、掉落、组队和限时活动；
- 经济与交易：金币、金价、材料价格、供需、拍卖和交易风险；
- 专业技能：采集、制造、分解、转化和专业收益；
- 工具与操作：插件、宏、界面设置和效率工具；
- 其他游戏信息：暂时无法稳定归入以上类别的有效内容。

“打金”“当前项目相关”“适合练级”等是用途标签，不与主分类并列。下一级按具体对象继续细分，例如“职业与战斗 → DK → 天赋”。

## 事实优先的展示契约

每条实质信息必须先展示可追溯材料，再展示 AI 的扩展判断，顺序固定为：

1. **事实信息**：准确说明群聊里实际出现了什么说法、经验、变化或问题。群友说法只能写成“群内有人提到/声称/分享”，不能直接提升成外部已证实事实；
2. **群聊原文**：默认保留支撑该事实的完整相关原文和必要上下文。原文过长时可以节选，但必须标明是节选，保持连续原句，不得为摘要流畅拼造一句不存在的原话；
3. **AI 扩展分析**：放在事实和原文之后，明确标注为攻略提炼、经验提炼、趋势判断、机会线索、项目影响或核验建议；不得与来源事实混写。

AI 可以从事实中进一步整理：

- 可执行的攻略步骤或经验规律；
- 对价格、供需、服务器生态等的趋势判断；
- 潜在打金、专业技能或副本收益机会；
- 对当前 DK、五开、任务路线或其它现行决策的影响；
- 尚缺什么证据，以及建议怎样核验。

推断必须同时列出事实依据、适用条件和不确定点。例如“即将开新服”是来源事实，“时光服金价可能下跌”是趋势判断，两者不能合并成一个已确认结论。

只有黑话、没有其它实质信息的消息，不生成普通话题卡，只进入黑话库。若一条实质信息同时包含黑话，事实卡照常保留，黑话含义另在词典中按语境更新，不复制整张事实卡。

## 价值排序与可信度

页面按个人价值分级，不按热度排序：

- **必看**：直接影响当前魔兽项目、当前角色、现行打金方式或近期决策；
- **应该看**：有明确操作价值，可能带来收益、避坑或效率提升，或是重要长期追踪变化；
- **可以看**：目前用不上，但可能成为未来攻略、知识或机会；
- **留档**：当前没有明显用途，但属于真实、有意义的讨论内容，保留供以后检索。

价值等级回答“值不值得用户看”；可信度回答“现在能信到什么程度”。两者必须分开。证据可标为多人独立支持、单人具体经验、传闻、存在争议或待核验，但证据较弱不能自动抹掉高价值线索。

当前重点是兽人双手深鲜血 DK ×5 的户外练级、五开任务执行、特殊任务机制、路线坑点和打金收益。普通团本打法或木桩配装默认不前置，但仍应进入对应话题；若能影响打金、职业配置、版本机制或未来决策，可以提高价值等级。

## 页面与报告视图

页面 v2 使用不同视图读取同一份分析结果，不重复保存信息：

- **本期总览**：必看、应该看、重要跟踪更新和本批状态；
- **话题总览**：按统一主分类完整列出本批所有有意义话题。它是覆盖导航，不是重复生成一份“全部信息”摘要；
- **长期追踪**：价格、版本、服务器生态和其它会持续变化的信息；
- **攻略知识**：可复用的职业、任务、副本、专业技能、交易与打金方法；
- **项目相关**：可能影响当前魔兽项目的候选信息和核验状态；
- **黑话**：语境化、可持续更新的玩家用语词典。

“本批没有发现……”“本批不触发项目修改”等只属于状态总结，不能占据发现排序。低优先级有效内容应在话题总览中保留，不能因为首页只展示重点就消失。

## 黑话词典

黑话必须语境化、可演化。同一个词在不同副本、物品、服务器或聊天上下文里可以代表不同含义，不能永久绑定单一释义。

每次新增或语义变化都应保存：词语、当前解释、适用语境、最小必要原文和首次/最近出现时间。含义不确定或具有版本/服务器差异时必须标“待核验”，必要时查公开资料，不能按字面硬猜。

## 参与者价值

活跃人员明细由当前批次分析顺手生成，不建立长期昵称注册表，也不把发言数当作主要指标。GPT 可以结合是否提供具体事实、经验、数据、纠错或可核验线索判断参与价值。

结果只保留当前批次所需的显示昵称和消息引用；相似昵称的当前批次归并不应被解释为跨批次真实身份识别。

## 对魔兽项目的边界

群聊分析项目和 `wow-quest-route` 必须分别保存资料，不共享运行时数据库，也不自动互相写入。群友说法不等于已验证任务事实。

本项目可以把信息标成“建议转入魔兽项目”，但流程必须是：

`群聊原文与分析 → 候选信息 → 用户确认 → 目标项目独立核验 → 目标项目保存`

只有用户明确要求进一步核验或写回后，才进入目标项目自己的规则流程。

## 模型职责

GPT负责语义提取、主题聚类、事实与原文对应、争议识别、摘要、扩展分析和核验建议。

GPT不负责判断采集是否完整、控制 OCR 去重/滚动/重试、修改原始消息，也不得自动执行跨项目写入。
