# GPT 分析规则

## 输入

默认且唯一的日常入口：

`runtime/inbox/current.md`

除非排查采集错误，不让 GPT 日常读取 raw OCR、截图或状态文件。

## v1目标

从高流量群聊中筛出用户值得看的文字信息，而不是普通聊天摘要。

优先关注：

- 新服、版本、开放时间、维护、重要改动；
- 时光服/无限服具体机制；
- DK/其它职业的配置、技能、天赋、雕文、手法；
- 五开技巧；
- 任务机制、共享性、BUG、地图/路线坑点；
- 打金、金币、拍卖行、收益效率；
- 多人反复确认的经验；
- 明显争议、需要验证的说法；
- 对现有用户项目可能有影响的新线索。

普通闲聊、刷屏、广告在不影响上下文时尽量忽略。

## 输出分类

分析报告至少能区分：

- **值得关注**：与用户当前目标明显相关。
- **多人共识**：多个独立成员对同一事实/经验给出一致信息。
- **单人经验/传闻**：有价值但证据弱。
- **存在争议**：群内明显有不同说法。
- **待核验**：如果要进入正式项目，需要联网、数据源或用户实测确认。
- **可能影响现有项目**：指出可能影响哪个项目/哪类规则，但不直接修改。

不要求每天所有分类都出现；没有内容就不制造内容。

## 证据

重要结论应尽量保留最小必要证据：
- 群；
- 大致时间；
- 显示昵称或本地成员标识；
- 原话的简短摘录/准确转述；
- 关联上下文。

不得为了摘要流畅把多人观点合成一个并不存在的“群结论”。

## 对魔兽项目的边界

群友说法不等于已验证任务事实。

GPT分析完成后：
- 可以指出“这可能影响 DK 配置/某任务路线/新服判断”；
- 可以建议核验；
- 不能直接改 `wow-quest-route`。

只有用户明确要求进一步核验/写回后，才进入目标项目自己的规则流程。

## 模型职责

GPT负责：
- 语义筛选；
- 主题聚类；
- 争议/共识识别；
- 摘要；
- 指出需要核验的线索。

GPT不负责：
- 判断采集是否完整；
- OCR去重状态机；
- 决定滚动/重试；
- 修改原始消息；
- 自动执行跨项目写入。
