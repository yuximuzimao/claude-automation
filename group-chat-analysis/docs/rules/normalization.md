# 消息重建与去重规则

## 原则

OCR block 不是消息。Normalize 层必须先根据几何位置、相邻关系和 UI 结构重建消息，再做跨屏去重。

缺失字段必须保持未知，不得猜测。

## 输入

Normalize 的正式输入是符合 `schemas/capture-page.schema.json` 的 page records；输入字段与类型只以该 Schema 为准。

Normalize 读取 block 时继承所属 page 的 batch/group/page 上下文。`page_index` 只表示采集顺序，不能直接当作聊天时间顺序；窗口 frame 只用于来源审计/诊断，不作为消息身份或跨页去重依据。

## 输出

输出必须符合 `schemas/message-record.schema.json`。

v1 至少区分：
- 普通文字；
- 系统文字；
- 图片占位；
- 语音占位；
- 文件占位；
- 表情/其它占位；
- unknown。

只有普通/系统文字是当前分析重点，其它类型用于说明消息流中存在非文字内容。

## 几何重建

正式算法应基于相对位置而非绝对屏幕像素。当前已用真实 QQ“聊天记录”窗口连续多页验证普通文字消息，规则如下：

1. 先应用 capture 给出的正文区域，只在消息列内参与重建；正文区域外的工具栏、日期侧栏和右侧控件即使被 OCR 成文字/符号，也不得并入消息。
2. block 按视觉从上到下排序；同一视觉行再按从左到右排序。
3. 日期分隔文本只作为后续消息的日期上下文，不单独生成消息。
4. 普通消息头必须同时具备“文本末尾可解析为 `HH:MM`”和“小于正文主字体”两类证据。当前环境以该页普通正文 block 高度中位数为基准，头部高度上限取约 `0.95 × 正文中位高度`；QQ UI/缩放变化后必须重新校准，不能改成固定像素阈值。
5. 时间前可见文本作为 `sender_display`；如果 OCR 只识别出时间，`sender_display=null`。禁止因为相邻消息昵称相同就把上一条昵称自动继承下来。
6. 一个已确认头部之后、下一个头部或日期分隔之前的正文 block 属于同一消息候选，并按视觉顺序保留。多行正文的最终拼接方式仍需真实多行样本验证，不能只凭这一规则宣称已经完成。
7. 页面顶端在第一个有效头部之前出现的正文、只有头部但正文未出现的候选、以及正文贴到页面底边的候选，都视为**页边缘残片**，不得在单页阶段直接产出最终消息。真实相邻页已验证这类残片会在下一页重新出现为完整候选，应留给相邻页拼接处理。
8. OCR 无法可靠识别昵称或时间时保持未知；不得模型猜测。只有日期上下文和时间文本都可靠时才考虑生成绝对 `timestamp`，否则保留 `timestamp_text` 并令 `timestamp=null`。

系统消息、媒体占位以及真实多行正文的几何形态尚未完成实测；遇到未覆盖布局时先输出 unknown/不完整候选，不套用普通文字规则硬猜。

## 顺序

同一页：按聊天视觉从旧到新排序。

跨页：利用相邻页重叠区拼接为全局顺序。

最终 messages 与 current.md 均按实际聊天时间方向由旧到新输出。

## 去重：禁止全局字符串去重

以下情况不能判重复：
- 同一个人隔一段时间再次发“好的”；
- 多个人都发同一句话；
- 广告重复；
- 相同系统提示再次出现。

所以禁止用 `sender + text` 的全历史唯一键直接删除消息。

## 跨屏去重

只在相邻/近邻屏之间做重叠消除。

优先证据：
1. 连续多条消息序列同时重合；
2. sender/text/相对顺序一致；
3. 可用时结合 timestamp_text；
4. bbox只用于页面内几何，不作为跨页身份。

推荐以“最长连续重叠序列”方式找 page N 的尾部与 page N+1 的头/中部重合。

单条短文本原则上不足以独立确认重复。

## OCR差异容忍

同一条消息在两屏中可能发生轻微 OCR 差异。

允许在相邻页锚点匹配中使用受控模糊匹配，但：
- 只能用于判断是否是同一视觉消息；
- canonical text 优先选择置信度更高/信息更完整的一次；
- 不允许让模型自由改写原文。

## 增量锚点

每日增量停止锚点必须是一个**连续消息序列**，而不是单条句子。

锚点建议包含若干条近期已完成消息的：
- sender_display（若有）；
- content_text；
- timestamp_text（若有）；
- 相对顺序。

命中阈值需通过真实数据实测后固化，不在架构阶段拍脑袋设数字。
