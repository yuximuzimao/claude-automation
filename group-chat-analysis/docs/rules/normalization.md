# 消息重建与去重规则

## 原则

OCR block 不是消息。Normalize 层必须先根据几何位置、相邻关系和 UI 结构重建消息，再做跨屏去重。

缺失字段必须保持未知，不得猜测。

## 输入

每个 OCR block 至少有：
- text；
- bbox；
- confidence；
- page_index；
- batch_id。

## 输出

输出必须符合 `schemas/message-record.schema.json`。

v1 至少区分：
- 普通文字；
- 系统文字；
- 图片占位；
- 语音占位；
- 文件占位；
- 表情/其它占位；
- unknown。

只有普通/系统文字是当前分析重点，其它类型用于说明消息流中存在非文字内容。

## 几何重建

正式算法应基于相对位置而非绝对像素：

- 先过滤窗口侧栏、工具栏等非聊天区域；
- 同一昵称附近、纵向连续的正文块组成同一消息候选；
- 多行正文必须按视觉顺序拼接；
- 时间标识可绑定到后续消息区段，但不能把一个时间强行复制成每条消息的精确时间；
- OCR无法识别昵称时允许 sender=null；
- OCR无法识别时间时允许 timestamp=null / timestamp_text=null。

## 顺序

同一页：按聊天视觉从旧到新排序。

跨页：利用相邻页重叠区拼接为全局顺序。

最终 messages 与 current.md 均按实际聊天时间方向由旧到新输出。

## 去重：禁止全局字符串去重

以下情况不能判重复：
- 同一个人隔一段时间再次发“好的”；
- 多个人都发同一句话；
- 广告重复；
- 相同系统提示再次出现。

所以禁止用 `sender + text` 的全历史唯一键直接删除消息。

## 跨屏去重

只在相邻/近邻屏之间做重叠消除。

优先证据：
1. 连续多条消息序列同时重合；
2. sender/text/相对顺序一致；
3. 可用时结合 timestamp_text；
4. bbox只用于页面内几何，不作为跨页身份。

推荐以“最长连续重叠序列”方式找 page N 的尾部与 page N+1 的头/中部重合。

单条短文本原则上不足以独立确认重复。

## OCR差异容忍

同一条消息在两屏中可能发生轻微 OCR 差异。

允许在相邻页锚点匹配中使用受控模糊匹配，但：
- 只能用于判断是否是同一视觉消息；
- canonical text 优先选择置信度更高/信息更完整的一次；
- 不允许让模型自由改写原文。

## 增量锚点

每日增量停止锚点必须是一个**连续消息序列**，而不是单条句子。

锚点建议包含若干条近期已完成消息的：
- sender_display（若有）；
- content_text；
- timestamp_text（若有）；
- 相对顺序。

命中阈值需通过真实数据实测后固化，不在架构阶段拍脑袋设数字。
