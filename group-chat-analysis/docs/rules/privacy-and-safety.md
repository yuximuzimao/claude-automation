# 隐私与安全规则

## 最小权限原则

实现目标所需的权限仅限：
- macOS Accessibility：用于安全窗口控制/定位；
- Screen Recording / ScreenCaptureKit 等系统屏幕捕获权限；
- 本地文件读写：仅本项目 runtime；
- Apple Vision 本地 OCR。

如果某技术路线要求额外高风险权限，应先说明必要性，不能自动扩大。

## 禁止路径

当前项目禁止使用：
- QQ进程注入；
- Debugger/LLDB Attach 获取聊天数据；
- 修改 QQ 签名；
- Hook；
- QQ数据库解密；
- SQLCipher key 获取；
- 协议逆向/模拟 QQ 客户端；
- NapCat、LiteLoader 等 QQ 非官方运行时扩展；
- 通过第三方服务器中转截图/OCR。

这些不是“暂时没实现”，而是当前安全边界的一部分。

## 操作安全

采集不得产生聊天写操作。

任何代码路径如果无法证明一个 UI 动作不会发送/确认/修改账号或群状态，就不得自动执行。

目标群切换若以后必须点击：
- 必须先定位并验证群列表安全区域；
- 禁止通用坐标盲点；
- 失败时停止，不连续乱点。

## 隐私

默认收集范围只包括完成分析所需内容：
- 群名/本地群标识；
- 可见昵称；
- 可见时间；
- 可见消息文字；
- 文字类型占位。

不主动采集：
- QQ号；
- 成员资料页；
- 手机号；
- 群成员完整名单；
- 非目标群聊天；
- 其它应用内容。

首次实现必须尽快从“全屏测试”收敛到“只捕获目标 QQ 聊天区域”。

## 模型边界

本地采集与 OCR 不代表数据永不离开本机。

当用户要求 GPT 分析时，`runtime/inbox/current.md` 中的文字会进入当前模型处理链。因此：
- 默认不把原始截图发给模型；
- 默认不包含 QQ号等不必要标识；
- 只把完成当前分析所需的群聊文字放入 current.md。

## Git边界

任何真实群聊原文、昵称、截图、分析包和报告都不得 commit/push。

如果需要测试数据：
- 优先人工合成；
- 或使用彻底脱敏、无法还原成员身份和真实聊天内容的 fixture。
