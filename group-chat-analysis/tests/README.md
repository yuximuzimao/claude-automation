# 测试策略

项目测试分三层，不能混成“一个全量测试脚本”。

## 1. 纯确定性单元测试

可用合成/脱敏 fixture，覆盖：

- capture raw page schema 校验；
- bbox 行/消息重建；
- 时间文本解析；
- 相邻屏最长连续重叠；
- OCR轻微差异下的受控锚点匹配；
- 不同真实重复消息不能被误删；
- current.md 构建顺序；
- message schema 校验。

这类测试应该可重复、无需启动 QQ。

## 2. 本地采集适配器测试

只在用户当前 Mac/QQ 环境运行，正式主路径验证：

- QQ 聊天记录窗口能被独立识别；
- 窗口 owner 是 QQ，窗口标题与目标群配置匹配；
- 窗口偏小时只通过拖动窗口边框自动放大，不点击正文控件；
- ScreenCaptureKit 可直接捕获聊天记录窗口；
- 通过实时 OCR 选择消息列表内的安全滚轮锚点，不依赖绝对屏幕坐标；
- 滚动距离按当前窗口高度比例计算；
- 系统滚轮只影响消息列表；
- Vision OCR 输出 text/bbox/confidence；
- raw page 符合 `schemas/capture-page.schema.json`；
- 用户切走前台后不得自动抢回 QQ；
- 不发生任何聊天写操作。

当前已经真实验证：

- 默认小窗口约 `660×720` 可连续抓 3 屏；
- 自动放大后约 `1442×982` 可连续抓 3 屏；
- 自动放大回归 `662×722 → 1452×978` 后仍可正常捕获。

主聊天窗口的全屏/普通窗口动态定位保留为 fallback 适配器测试，不作为主路径成功的必要条件。

这不是 CI 真值；QQ UI 更新后要按实时环境重新验证。

## 3. 首个端到端 dry-run

用一个目标群的一小段聊天记录历史：

`capture → normalize → store → current.md`

成功标准至少包括：

- 全程 QQ 聊天记录窗口保持前台；
- 窗口标题始终匹配目标群，若中途不匹配则批次必须失败为 incomplete；
- 至少跨 3 个相邻页面，验证真实滚动与页面重叠；
- 每页 raw JSON 均通过 capture-page schema；
- 没有其它应用/其它群内容；
- 消息方向正确；
- 相邻屏重复消除；
- 同文真实重复不被错误吞掉；
- 中断时标记 incomplete；
- completed 才生成 current.md；
- runtime 文件确实不被 Git 跟踪。

GPT分析属于后续独立验收，不用“摘要看起来不错”代替采集完整性验证。
