# 日记回顾索引

这里存放个人日记的周回顾和月回顾，内容来源主要是 Apple Notes 日记条目，并结合必要的项目记录、周回顾和提交历史做交叉校验。

## 目录

- `weekly/`：周回顾，文件名格式 `YYYY-Www.md`，按 ISO 周编号。
- `monthly/`：月回顾，文件名格式 `YYYY-MM.md`。
- `insights/`：只存关于本人、跨周跨月仍有意义且会持续修正的长期画像，例如“我是个什么样的人”“长期语言习惯”“稳定的决策/思考模式”。按主题持续更新，不把某次对话或某一周刚出现的判断单独存成洞察；这类内容先留在对应 `weekly/`。

## 写作约定

### 数据源分层（月回顾三源，不是二源）

月回顾有三条独立、部分不重叠的数据流，缺一条就会系统性丢东西：

1. **周回顾** = 定弧线 + "别再挖哪"。给整月叙事、以及本月已经说过的模式（避免重复贴旧标签），也告诉你哪些材料被当周跳过了。
2. **日记原文** = 纹理 + 被跳过的材料。跨周纹理、单周分析当噪音删掉的细节、任何一周没看上的东西——只在原文里。**日记原文不是"补充"，是必读。** 做法：带着"月尺度想问什么"定点读枢纽日记，不必通读全部。
3. **项目 git log** = "实际造了什么"。前两者都不含。工程改动和情绪变化叠在一起，常出单看任一源都看不见的洞察。

- 周回顾优先基于该周日记原文，必要时补充项目提交和任务记录。
- 月回顾**不是"综合周回顾为主"**——三源分层：周回顾定方向，日记原文定点勘探，git log 给实际产出。三者交叉才是月回顾的独有价值（跨周、跨天的模式，恰恰死在单周压缩里）。

### 动手前：数据可及性自检（缺源必须出声）

写回顾前先确认三源是否都在手：日记原文能读到几篇、周回顾覆盖是否连续、git 时间窗对不对。**有缺口先报告，不许拿不全的数据默默产出一份"看起来完整"的回顾。** 对应工作区铁律「失败出声：完成=没有东西被静默跳过」。一份静默残缺的回顾比没有更坏，因为她会信它。
（历史教训：GPT 曾"没权限抓到日记原文，就根据项目进展凑一份"，那版最空。源丢了，分析再好也补不回来。）

### 反标签硬约束

**要"有用"不要"看起来有道理"。标签式的模式归纳 = 无用**（她已住在自己里面，准确的模式归纳对她零增量）。破局靠**换看她的角度**，不靠更准的同类分析。每条自检："这是复述她知道的，还是给了她一个新视角/新可能/能用的判断工具？"后者才留。收尾摘要尤其危险，bullet 化最容易退化成标签复述。详见 memory `feedback_review_format.md`。

### 其他

- 不写流水账，重点抽取反复出现的模式、转折、风险和可延续观察点。
- 不把单次回顾结论写进根 `CLAUDE.md` / `AGENTS.md`；这些文件只放会影响后续 AI 工作的规则。
