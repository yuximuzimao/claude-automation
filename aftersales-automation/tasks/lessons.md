# 可复用工程教训

本文件只保留跨会话仍有价值的开发习惯，不再保存 session 流水账。精确业务规则以 `docs/INDEX.md` 和对应 `docs/flow-*.md` 为准；当前生产入口、文件地图和已知失败模式以 `SKILL.md` 为准。历史过程可从 git 追溯。

> 2026-07-29 按 neat-freak 清理：原 481 行历史记录已合并为下列长期习惯；已经稳定的具体规则不在这里重复维护。

## 开始修改前

1. **先确认数据生产者、消费者和真实入口。** 不从字段名、旧 simulation/case 或历史脚本猜数据语义；先沿当前生产链路读到实际调用方。
2. **事实判断必须回到实时源头。** 页面状态用当前 DOM/CLI 重新读取；历史 JSON 只用于追溯，不作为真值。
3. **优先复用现有工具链。** 已有 CLI、op-queue 或安全编排时，不另写一次性 CDP 脚本绕过它们。
4. **调用新函数前先读返回契约。** 禁止凭习惯猜 `.ok`、`.success`、`.data` 等字段。
5. **怀疑代码或规则发生变化时先看 git 历史。** 先确认事实，再构造解释。

## 业务规则修改

1. **业务选项按“工单类型 × 状态分支”确认。** 平台下拉原因、按钮和可见字段不一定跨工单类型一致，禁止为了抽象方便强行统一。
2. **用户对业务语义的纠正优先于既有实现假设。** 收到纠正后应检查推理、执行、文档和测试的完整影响面，但只改受影响分支，保留其他已确认行为。
3. **解释字段与写入字段分层。** `decision.reason` 用于说明证据和判断过程；平台原因、详情、按钮等写入载荷必须使用独立字段。
4. **安全关键字段只有一个真值来源。** 已确认分支的执行值由 decision 产生，执行层不得被前端或路由参数覆盖；字段缺失时 fail-closed，不能回退到解释文本。
5. **不要把“有共同文案”误当成“同一业务枚举”。** 详细说明可以复用，平台下拉原因仍需按分支分别选择。

## 浏览器自动化

1. **能检测状态就不依赖固定延时。** 页面加载、弹窗关闭、搜索完成和账号切换都应验证真实状态。
2. **DOM 查询同时满足可见性、容器作用域和业务特征。** 多弹窗按标题锁定；表格按表头定位列；禁止依赖 DOM 顺序或数据格式猜测。
3. **鲸灵行为操作失败即停。** 不因“可能是瞬时错误”自动重试；风险信号先熔断。
4. **新链路逐步骤验证。** 先测 DOM/单函数，再测编排，最后跑全链路，避免多个独立缺陷叠加后反复返工。
5. **审查必须追踪完整执行流。** 看到某个安全函数被调用不代表整个入口已经安全，要继续检查后续导航、点击、状态写回和失败路径。

## 交付与归档

1. **测试覆盖语义分支，不只覆盖主路径。** 规则映射至少验证各独立分支、混合状态、外部覆盖尝试和缺失字段的 fail-closed 行为。
2. **修改 `lib/` 后完整测试并安全重启。** 重启只加载新代码，不自动重采或重写已有工单。
3. **只提交本次相关文件。** 工作区存在其他项目脏文件时，不顺手清理、暂存或覆盖。
4. **合并前检查删除项。** 运行时 `data/`、状态文件和用户资产即使已被 `.gitignore`，只要曾被追踪仍可能在 merge 时被删除；必须先检查并备份。
5. **规则文档保持单一真值。** 稳定业务规则进 `docs/INDEX.md`/flow；AI 必须遵守的硬边界进 `CLAUDE.md`；本文件只保留方法论，避免重复和过期。
