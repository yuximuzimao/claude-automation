# 换货处理流程（5.4）

> 前置：已读 `docs/INDEX.md`，工单类型确认为「换货」
> 核验重点：**退回商品规格编码是否与原订单一致**
> 操作边界：**换货永不进入扫描中的无人自动执行；人工核对后可以使用系统单笔或批量执行**

---

## 完整流程

### Step 1：读鲸灵工单详情

```bash
node cli.js read-ticket <工单号>
```

记录：
- `subBizOrderDetailDTO[0].spuBarcode` — 货号
- `subBizOrderDetailDTO[0].attribute1` — attr1
- 售后说明 + 是否有售后图片
- 客户退货快递单号（buyerLogisticsNo）

### Step 2：查商品明细（必查，不靠记忆）

```bash
# 货号 → 规格商家编码
node cli.js product-match <货号> "<attr1>" <ERP店铺名>

# 规格商家编码 → 单品信息（subItemNum、名称）
node cli.js product-archive <规格商家编码>
```

记录**原订单规格商家编码**（用于 Step 4 对比）。

### Step 3：ERP 售后工单新版搜退回快递单号

```bash
node cli.js erp-aftersale <退货快递单号>
```

展开所有已收货行，读取：
- shortTitle（商品简称）
- 规格商家编码
- 数量
- 良品/次品（qtyBad）

### Step 4：验收判断

```
ERP 收货规格商家编码 = 原订单规格商家编码
  + 数量吻合
  + 全良品（qtyBad = 0）
→ ✅ 推荐人工同意换货

ERP 收货规格商家编码 ≠ 原订单规格商家编码
→ 进入 5.4a（退回物品不符）
```

> ⚠️ **禁止用商品名字判断是否一致**，必须用规格商家编码对比。
>
> “推荐同意”不等于无人自动执行。换货同意后会生成新的发货单，系统必须先明确提醒人工核对；人工确认无误后，可以使用单笔“执行操作”或主动发起批量执行。
>
> ⚠️ 同意前必须确认正确商品是否已经提前人工补发/换出。若已经发出，应拒绝换货并手动归档，避免再次生成发货单；只有未提前发出时，才执行同意换货。

### Step 4a：退回物品不符

执行以下步骤（不点任何同意/拒绝按钮）：

```bash
# 1. 添加内部备注（写 shortTitle，不写编码）
node cli.js add-note <工单号> "退回商品为[ERP shortTitle][数量]个，与订单商品[原商品shortTitle]不符，需拒绝换货+[后续动作]"

# 2. 通过「创建提醒」快捷指令创建待办（5分钟后触发）
node cli.js remind <工单号> <账号名> "⚠️ 换货退回商品不符：{退回商品} vs {换货商品} → {动作}"

# 3. 停止对该工单一切后续操作，等待人工处理
```

> 备注示例：`退回商品为KGOS保温壶1个，与订单商品灵芝金花黑茶不符，需拒绝换货+人工补发杯子`

### Step 5：人工确认后同意换货

系统保留换货“执行操作”按钮，但不会在扫描时自动触发。人工核对后点击单笔执行或批量执行，系统按工单类型精确点击“同意换货”；找不到换货专属按钮时立即失败，不会改点“同意退款”。

仅限人工已再次确认以下信息后执行：

- 提醒标题明确显示“换货”或“商责换货”，不能只看右上角小标签；
- 退货单号、实际退回商品、规格编码、数量和良次品全部无误；
- 已知同意后会生成新的发货单。
- 正确商品没有被提前人工补发/换出；若已经发出，改为拒绝换货并手动归档。

### Step 6：商责换货

商责原因（如“卖家发错货”）不再提前结束采集：

- 有退货单号：照常完成 Step 2～4 的退回商品核验；
- 核对一致：输出“商责换货｜推荐人工同意换货”，同时提醒商责风险和新发货单；
- 核对异常或证据不足：输出“商责换货｜人工确认”，列出仓库实际退回商品；
- 无论结果如何都禁止扫描中的无人自动执行；
- 核对一致且人工确认正确商品未提前发出时，可通过单笔或人工发起的批量执行同意换货；
- 核对异常、证据不足，或正确商品已经提前发出时，不得直接同意；已提前发出的场景应拒绝换货并手动归档。

## 决策快速参考

```
鲸灵读详情 → 货号 + attr1 + 退货快递单号
  ↓
商品对应表+档案V2 → 原订单规格商家编码（必查）
  ↓
ERP售后工单新版搜退货快递单号 → 展开已收货行
  ↓
对比规格商家编码：
  ├─ 一致 + 数量吻合 + 全良品 → 推荐人工同意换货
  └─ 不一致 → 备注+提醒+停止，等待人工

操作约束：
  ├─ 所有换货 → 禁止扫描无人自动执行
  ├─ 核验一致 + 未提前补发 → 人工确认后可单笔/批量执行“同意换货”
  ├─ 已提前补发 → “拒绝换货”后手动归档
  └─ 商责换货 → 同时显示“商责+换货”提醒，执行边界不变
```

## 已知坑位（换货流程）

- `[∞/永久保留]` **#23 换货必须查商品对应表**：换货工单同样必须查 ERP 商品对应表取规格商家编码，不能只看 ERP 收货名称来判断商品是否一致
- `[∞/永久保留]` **#24 换货同意前检查提前补发**：退回明细完全匹配只能证明客户退回正确，不能证明新货尚未发出；若正确商品已提前人工发出，再同意换货会重复生成发货单。必须醒目提醒并由人工确认。
