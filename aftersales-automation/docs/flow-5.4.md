# 换货处理流程（5.4）

> 前置：已读 `docs/INDEX.md`，工单类型确认为「换货」
> 核验重点：**退回商品规格编码是否与原订单一致**
> 操作边界：**换货永不由系统执行；系统只采集事实并给出人工建议**

---

## 完整流程

### Step 1：读鲸灵工单详情

```bash
node cli.js read-ticket <工单号>
```

记录：
- `subBizOrderDetailDTO[0].spuBarcode` — 货号
- `subBizOrderDetailDTO[0].attribute1` — attr1
- 售后说明 + 是否有售后图片
- 客户退货快递单号（buyerLogisticsNo）

### Step 2：查商品明细（必查，不靠记忆）

```bash
# 货号 → 规格商家编码
node cli.js product-match <货号> "<attr1>" <ERP店铺名>

# 规格商家编码 → 单品信息（subItemNum、名称）
node cli.js product-archive <规格商家编码>
```

记录**原订单规格商家编码**（用于 Step 4 对比）。

### Step 3：ERP 售后工单新版搜退回快递单号

```bash
node cli.js erp-aftersale <退货快递单号>
```

展开所有已收货行，读取：
- shortTitle（商品简称）
- 规格商家编码
- 数量
- 良品/次品（qtyBad）

### Step 4：验收判断

```
ERP 收货规格商家编码 = 原订单规格商家编码
  + 数量吻合
  + 全良品（qtyBad = 0）
→ ✅ 推荐人工同意换货

ERP 收货规格商家编码 ≠ 原订单规格商家编码
→ 进入 5.4a（退回物品不符）
```

> ⚠️ **禁止用商品名字判断是否一致**，必须用规格商家编码对比。
>
> “推荐同意”不等于系统执行。换货同意后会生成新的发货单，必须打开工单，在平台页面逐单人工确认；定时自动、批量和系统单张执行都必须排除。

### Step 4a：退回物品不符

执行以下步骤（不点任何同意/拒绝按钮）：

```bash
# 1. 添加内部备注（写 shortTitle，不写编码）
node cli.js add-note <工单号> "退回商品为[ERP shortTitle][数量]个，与订单商品[原商品shortTitle]不符，需拒绝换货+[后续动作]"

# 2. 通过「创建提醒」快捷指令创建待办（5分钟后触发）
node cli.js remind <工单号> <账号名> "⚠️ 换货退回商品不符：{退回商品} vs {换货商品} → {动作}"

# 3. 停止对该工单一切后续操作，等待人工处理
```

> 备注示例：`退回商品为KGOS保温壶1个，与订单商品灵芝金花黑茶不符，需拒绝换货+人工补发杯子`

### Step 5：人工确认后同意换货

系统不提供换货执行按钮，也禁止调用退款专用的 `approve` 自动化。人工点击“查看工单”后，在平台页面自行确认并处理。

仅限人工已再次确认以下信息后执行：

- 提醒标题明确显示“换货”或“商责换货”，不能只看右上角小标签；
- 退货单号、实际退回商品、规格编码、数量和良次品全部无误；
- 已知同意后会生成新的发货单。

### Step 6：商责换货

商责原因（如“卖家发错货”）不再提前结束采集：

- 有退货单号：照常完成 Step 2～4 的退回商品核验；
- 核对一致：输出“商责换货｜推荐人工同意换货”，同时提醒商责风险和新发货单；
- 核对异常或证据不足：输出“商责换货｜人工确认”，列出仓库实际退回商品；
- 无论结果如何都设置人工专属约束，禁止定时自动、批量和系统单张执行。

## 决策快速参考

```
鲸灵读详情 → 货号 + attr1 + 退货快递单号
  ↓
商品对应表+档案V2 → 原订单规格商家编码（必查）
  ↓
ERP售后工单新版搜退货快递单号 → 展开已收货行
  ↓
对比规格商家编码：
  ├─ 一致 + 数量吻合 + 全良品 → 推荐人工同意换货
  └─ 不一致 → 备注+提醒+停止，等待人工

操作约束：
  ├─ 普通换货 → 仅允许平台页面逐单人工处理
  └─ 商责换货 → 同时显示“商责+换货”，仅允许平台页面逐单人工处理
```
