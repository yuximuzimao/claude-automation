# 自动处理授权与统计口径

本文只描述当前生产口径。历史设计、实施计划和阶段记录见 `docs/superpowers/archive/`。

## 核心原则

- 系统不根据次数、好评或历史成功自动学习、自动开权。
- 自动授权粒度是“售后原因＋工单类型＋最小最终分支”的独立 `caseId`，不能由相邻分支继承。
- 每次执行前都用本次采集重新证明关键事实；只匹配历史文案或分支名称不能放行。
- 人工 hint、关键采集错误、事实缺失或冲突一律阻断自动执行。
- 当前只允许自动同意；换货、商责、拒绝、等待、上报及未登记分支均不进入无人自动执行。
- 不同子订单共用同一退货单号属于独立关联组分支；即使逐规格汇总核对通过，也显式标记 `requiresHumanReview:true`、`autoExecutionBlocked:true`，当前不继承普通“精确退回”的无人自动授权。严格证明通过后保留 `humanTriggeredExecutionAllowed:true`，允许用户人工确认后单笔或批量执行。
- 普通退货退款的无人自动动作延迟到当前固定批次全部详情采集完成后；等待期间写入不可执行占位结果，批次失败或中止也不能继续使用旧 approve。
- 所有人工执行在 HTTP 入队前和操作队列真正触碰平台前都必须确认目标 simulation 是该 queue item 的最新记录；旧页面、历史链接或已排队的旧结论不得绕过后来写入的安全占位结果。
- 商责退货申请阶段无退货单号属于正常流程前置状态。商责主张未经人工证实时，只推荐拒绝退货；人工需要按客户填写原因寻找合理拒绝理由。只有确认确属商责且无法合理拒绝时才同意退货。该推荐拒绝分支禁止无人自动、人工批量和直接系统执行。

## 当前已授权分支

| 售后原因 | 工单类型 | 最小分支 | 执行前独立证明 |
|---|---|---|---|
| 七天无理由退货（不喜欢/不合适） | 退货退款 | 已入库、主品赠品严格精确退回、无次品或未匹配项 | 退货单号存在；全部主品赠品按各自 `afterSaleNum` 和 `specCode` 精确核对；实退数量相等、`qtyBad=0`、无未知规格和关键采集错误 |
| 多拍/拍错/不想要 | 仅退款 | 主品赠品全部无单号未发货 | 每个主品赠品子订单有唯一 ERP 搜索结果；每行平台交易号匹配；状态仅限待审核、待打印快递单、待发货；ERP 与鲸灵均无运单 |
| 多拍/拍错/不想要 | 仅退款 | 全部 ERP 行无单号未发货，或对应运单均明确未揽收/已退回 | 复用逐子订单完整性门禁；无单号行只能是未发货状态；至少存在一个 ERP 行内运单；鲸灵和 ERP 不得出现行外额外运单；每个运单复用推理引擎的同一物流语义，任何在途、签收、未知或缺失结论均阻断 |

生产门禁位于 `lib/server/after-sales-auto-gate.js`；物流判定与 `lib/infer.js` 共用 `evaluateRefundOnlyTrackings()`，避免扫描推理和执行门禁出现两套语义。分支登记及状态位于 `lib/server/after-sales-branch-history.js`。

## 统计口径

统计页按最近 30 天不同工单的最新 simulation 汇总，只展示采集、归类完整的固定分支，顺序为“已授权自动 → 可评估自动化 → 仅人工”。历史数据只用于复盘，不会改变权限。

| 指标 | 来源 |
|---|---|
| 真实自动成功 | `auto-execution-journal` 中页面动作成功，且能映射回同一 `caseId` |
| 执行操作 | `cases.jsonl` 的 `groundTruth.source` 为 `executed` 或 `batch_executed`；仅对缺少归档来源的旧记录兼容读取非自动 `executedAt` |
| 手动归档 | `groundTruth.source = manual_handled` |
| 确认无需处理 | `groundTruth.source = confirmed_no_action` |

自动处理来源不计入“执行操作”或“手动归档”。后端暂时保留 `manualHandledCount` 作为兼容合计，但界面不再使用这个合并数字。

## 变更规则

新增、停用或扩大自动分支必须同时满足：

1. 用户明确授权具体 `caseId`，不能仅凭出现次数自动开启；
2. 更新 `ENABLED_AUTOMATION_CASES` 和 `AUTO_EXECUTABLE_BRANCHES`；
3. 为该分支增加执行前独立事实证明及正反边界测试；
4. 更新本文、对应 flow 文档和 `tasks/todo.md`；
5. 运行 `npm test`，确认操作队列空闲后按 `/aftersales-restart` 重启；不得自动重跑已有工单。
