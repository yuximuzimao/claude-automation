# 2026-10 鲸灵切号“新用户”过渡态误判修复

## 问题

最近自动切换鲸灵账号时开始间歇出现：

`注入后店铺名不匹配目标账号：页面="新用户" ...`

人工单独打开对应店铺始终正常。现场观察确认：自动切号过程中页面会短暂显示“新用户”，随后才恢复真实店铺工商名称。

## 根因

`lib/jl/login-state.js` 原逻辑只要 `p.readonly` 读到任意非空文本，就直接判定为 `logged-in`。因此切号瞬间的“新用户”也会被当成真实店铺名，随后进入目标店铺关键字匹配并误报错号。

这不是普通的固定等待时间不足：问题在于中间态被当作合法终态。

## 最小修复

- `lib/jl/login-state.js`
  - 将店铺名精确等于“新用户”识别为 `state='transitional'`。
  - 该状态不视为已登录，也不进入错号匹配。
- `scripts/jl-steps/04-inject.js`
  - 原有注入后固定等待和目标账号校验保留。
  - 若读取到 `transitional`，每 1 秒只读重查一次，最多额外 8 秒。
  - 一旦出现真实店铺名，立即继续原有关键字匹配。
  - 若持续停留“新用户”达到上限，明确报“注入后页面长时间停留在切号过渡态”，不再误报店铺名不匹配。

未改动 Cookie 清理、显式 `targetId`、session 注入、目标店铺匹配和错号保护。

## 验证

- `node --test test/jl/login-state.test.js`：14/14 通过。
- `node --test test/jl/direct-after-sale-navigation.test.js`：12/12 通过。
- 修改后按 launchd 规则重启 `com.heizong.aftersale-server`。
- 重启后 `http://127.0.0.1:3457/api/queue` 返回 HTTP 200，队列原有 `simulated` / `waiting` 状态保持不变，没有自动重跑工单。

## 长期规则

账号注入后的“新用户”是鲸灵切号过程中的已确认过渡态，不是合法店铺名。后续登录态判断若命中该值，只允许等待真实店铺名出现后再校验；不得把它直接解释为错号，也不得仅靠延长固定 sleep 掩盖状态判断问题。
