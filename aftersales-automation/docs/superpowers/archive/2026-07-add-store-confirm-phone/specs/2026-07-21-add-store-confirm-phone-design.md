# 新增店铺确认保存与首次手机号初始化设计

日期：2026-07-21

## 目标

修复“新增店铺”登录完成后，店铺管理页不显示“确认保存”的问题；首次确认保存后，从本次 Session 文件中提取手机号写入账号索引，保证下一次重新登录可以自动填写。

## 范围

只做以下两项：

1. 新增店铺启动登录窗口后，复用现有重新登录的待确认流程，向前端返回新账号编号并显示现有“确认保存/取消”控件。
2. 仅新增店铺的首次保存，从 `accountN.json` 的 `supplierInfo.supplierMobileList[0]` 提取手机号，写入 `accounts.json.phone`。

明确不做：保存前店铺身份校验、刷新后恢复确认态、确认写盘竞态改造、状态语义调整或其他额外风险控制。

## 数据流

1. 前端提交店铺备注。
2. 后端创建账号记录，用“首次初始化手机号”标记启动现有 `jl.js add <num> --auto-save` 登录流程，等待临时确认端口准备完成，并返回 `num`。
3. 前端将 `num` 放入现有 `reloginConfirm` 集合，渲染现有确认/取消按钮。
4. 用户确认后，`jl.js` 保存 `accountN.json`。
5. 仅当本次带首次初始化标记且账号尚无 `phone` 时，从保存态的 `supplierInfo.supplierMobileList[0]` 提取、规范化为字符串并写入账号配置。
6. 普通重新登录不带该标记，继续保留现有 `phone`，不从 Session 覆盖。

## 失败边界

- Session 中没有可用手机号时，不阻断 Session 保存，只保持 `phone` 缺失。
- 已有手机号时绝不覆盖。
- 登录窗口启动失败沿用现有重新登录错误处理。

## 验证

- 新增接口返回新账号编号，前端进入确认保存状态。
- 首次新增能从合法 `supplierMobileList[0]` 写入手机号。
- 普通重新登录和已有手机号场景不覆盖手机号。
- 缺失或格式异常的 `supplierInfo` 不影响 Session 保存。
- 账号 15 从已保存的 `account15.json` 一次性补齐手机号，并读回核对账号映射。
