# 售后分支统计页清晰化设计

> 归档状态（2026-07-19）：已实现。当前生效口径见 `../../../../automation-policy.md`；本文件只保留当时的页面设计依据。

## 1. 页面目的

这个页面用于判断哪些固定业务分支已经具备自动处理资格，哪些分支值得继续观察。

它不是异常监控页，也不负责展示采集失败、资料缺失或无法归类的数据。自动处理权限仍由人工配置，不根据历史次数自动学习或自动开启。

本次只调整前端展示，不改变固定分支门禁、历史统计口径或自动处理权限。

## 2. 展示数据边界

页面只展示同时符合以下条件的历史分支：

- 已经匹配到现有固定业务分支；
- 售后原因、工单类型、最终决定和规则结果完整；
- 没有采集缺失或规则归类异常。

现有数据中，`registered === false` 或 `missingFacts` 非空都代表不满足以上条件，应在进入页面分组和统计前排除。

这类异常数据本来就绝不允许自动处理，没有必要放在自动化评估页面，也不在卡片中展示“资料是否缺失”。异常仍保留在原始历史记录中，不删除、不修改；只是本页不显示。

差评不等于采集异常。正常固定分支中的好评、差评和人工处理记录仍作为自动化效果证据展示，但不使用红色作为页面主视觉。

## 3. 页面层级

页面按自动化价值分成三层，不再先按异常程度排序。

### 第一层：已授权自动

- 放在最前面，默认完整展开；
- 使用最明确的绿色强调；
- 展示当前已经人工授权自动处理的固定分支及其历史表现。

### 第二层：可评估自动化

- 放在已授权分支之后，默认完整展开；
- 使用蓝色强调；
- 展示规则上具备候选资格、但尚未人工授权的固定分支。

同层排序只用于帮助查看，不会自动改变权限：

1. 真实自动成功次数从多到少；
2. 好评次数从多到少；
3. 差评次数从少到多；
4. 出现次数从多到少；
5. 分支名称作为稳定排序。

### 第三层：仅人工

- 放在页面最底部；
- 默认整体折叠；
- 使用低对比度灰色；
- 展开后仍可查看具体分支，但不与可自动化分支争夺注意力。

## 4. 分支卡片

已授权和候选分支不再压缩成“一行结果 + 隐藏详情”，改为接近待处理工单信息密度的分支卡片。

每张卡片直接展示：

- 售后原因；
- 售后类型；
- 固定触发条件；
- 系统处理结果；
- 最近 30 天出现次数；
- 真实自动成功次数；
- 好评次数；
- 差评次数；
- 执行操作次数；
- 手动归档次数；
- 历史备注及各备注出现次数。

条件路径直接从现有固定分支定义拆开显示，不增加新的推理逻辑。例如：

> 七天无理由退货（不喜欢/不合适）｜退货退款 → 已入库 → 精确退回 → 同意退款

其中售后类型单独标注，中间节点作为必须满足的条件，最后一个节点作为处理结果。这样用户能直接比较不同最小分支到底差在哪个条件和结果上。

仅人工分支展开后使用相同字段，保证信息口径一致，但视觉权重更低。

## 5. 顶部概览与视觉规则

顶部不再用四张卡片凑数，也不显示“需要关注的异常分支”。只突出：

- 已授权自动分支数；
- 可评估自动化分支数。

最近 30 天工单数和正常固定分支总数作为辅助文字保留，不与自动化状态争夺视觉焦点。

颜色规则：

- 绿色：已授权自动；
- 蓝色：可评估自动化；
- 灰色：仅人工；
- 不为差评、未登记或资料缺失设置红色重点样式。

不增加搜索、筛选器、图表、评分、进度条或新操作按钮。

## 6. AI 洞察与反馈明细

AI 洞察的“待洞察反馈”和页面下方“反馈记录”都只展示填写了具体评论内容的记录。

- 单纯点击“好评”但没有填写评论：不显示在明细中；
- 好评并填写了具体评论：显示；
- 差评并填写了具体评论：显示；
- 原有总体好评、差评统计数字不受影响。

这里的过滤只影响前端明细展示，不删除历史反馈，也不改变后端洞察数据。

## 7. 自动更新

历史记录不需要人工定期更新：

- 每次打开统计页时，从现有接口读取最新记录并重新汇总；
- 页面停留在统计页时，工单推理、案例归档或反馈发生变化，会通过现有实时事件重新加载；
- 切走再返回统计页时也会重新读取；
- 统计范围继续保持最近 30 天，因此旧记录会自然退出窗口。

本次不增加定时器、缓存或后台任务。

## 8. 验证

- 验证未登记分支和 `missingFacts` 非空分支不会出现在页面分组、卡片或顶部数量中；
- 验证已授权、候选、仅人工三个区域的顺序和默认展开状态；
- 验证候选分支按自动化证据排序，但不会改变实际权限；
- 验证卡片直接显示原因、类型、条件、结果和完整历史统计；
- 验证仅人工区域默认折叠且视觉弱化；
- 验证页面不再使用异常优先和红色重点样式；
- 验证没有评论内容的好评不会出现在洞察与反馈明细；
- 验证带评论的好评和差评仍然显示；
- 验证窄屏下卡片内容不横向溢出；
- 运行完整测试，重启服务，但不手动触发工单扫描。
