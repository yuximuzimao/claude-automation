# 2026-10-19 鲸灵账号边界与紧急停止安全收口

## 本轮目标

针对 2026-10-17～19 自动多账号扫描中出现的 `about:blank`、空店铺名和“新用户”过渡态连续异常，继续收紧账号边界；同时把紧急停止统一为“当前现场立即停住”的语义，避免停止后为了收尾继续导航、读取或关闭标签页。

本轮只强化现役 A1 / op-queue 安全链路，不重构 legacy `scan-all.js / collect.js / pipeline.js`，也不把普通工单错误扩大成账号异常。

## 最终规则

### 1. 真实页面是账号身份唯一权威

- `data/current-session.json` 只记录最近一次已由真实页面确认成功的账号，是辅助缓存，不是当前登录态证明。
- 现役 A1 的打开店铺、扫描、重新采集、执行、查看工单都必须经过 `openAccountFlow/readShopName` 读取真实页面。
- 禁止因为缓存命中跳过店铺身份校验；页面确认成功后再同步缓存。
- legacy 路径过去依赖缓存跳过注入的问题只作为历史教训保留，不重新接回现役链路。

### 2. 自动多账号扫描的账号边界

- 正常账号完成工单处理、详情页正常收尾和首页提醒读取后，只读确认主页面仍是当前店铺，再允许进入下一账号。
- 明确掉登录继续按 expired 处理，只作废 current-session，不触发异常账号隔离。
- 工单未找到、详情 tab 未找到/关闭失败、ERP/推理等普通业务错误不因为本规则自动升级为“前账号污染后账号”。
- 只有主 tab 缺失、离开可信鲸灵页面、店铺态长期未知或店铺名不匹配等真正的“当前账号身份不可信”才执行异常隔离并停止整轮扫描。
- 隔离关闭已知 target 后先等待 300ms，必须同时证明该具体 `targetId` 已消失且没有其他鲸灵 tab；随后再要求 5 秒内无鲸灵 tab 或原 target 重现。`about:blank` 不能仅因 URL 还不是鲸灵域就被误判为已经关闭。

### 3. 紧急停止语义

- 收到停止后，普通读取、等待、导航、排序、翻页、打开工单、首页提醒、详情页关闭、主 tab 关闭和账号异常隔离都不得再发起新的浏览器动作；当前页面可以原样留着。
- 新开登录页后的被动等待、店铺稳定读取和多 tab 清理都支持停止；多个 tab 清理过程中收到停止后不再继续关闭后续 tab。
- 鼠标 `mousePressed` 已经发出时，只补配对的 `mouseReleased`，随后立即停止，避免把浏览器输入状态留在“按住未松开”。
- Cookie/storage 清理和已经启动的单次账号注入属于认证态原子动作，不在半途中强杀；本次原子动作返回后立即停止后续步骤。
- 唯一更高优先级例外：退款同意/拒绝等不可逆平台写操作已经实际发出时，必须完成该次结果确认和 execution journal 本地记账，然后立即停止，不进入下一业务动作。

## 明确不做的扩展

- 不为普通“未找到工单标签页”等工单错误自动增加“关闭全部鲸灵 → 等 5 秒 → 自然打开页面 → 等 8 秒确认店铺”的恢复流程；当前没有足够证据证明普通工单错误会伴随账号污染。
- 不把手动单店铺操作纳入自动扫描专用的异常隔离规则；真实使用中手动打开店铺未复现自动连续扫描的异常。
- 不修改全局队列“普通错误后继续后续独立操作”的成熟语义。
- 不修 legacy `scan-all.js / collect.js / pipeline.js` 的历史缓存类型或继续账号逻辑；它们不是当前 A1 正式入口。
