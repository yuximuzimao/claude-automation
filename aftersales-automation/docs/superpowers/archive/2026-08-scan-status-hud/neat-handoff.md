# 2026-08 定时扫描状态窗阶段交接

状态：已完成并加载到当前生产服务。本文只保存阶段边界和验证证据；当前运行口径以 `SKILL.md` 和 `docs/ops-queue.md` 为准。

## 1. 目标

定时自动扫描原本会直接开始浏览器操作，用户在 Mac 上工作时缺少明确的开始预告和整轮进度反馈。本阶段增加一个仅用于观察的 macOS 浮动状态窗，不改动售后判断、自动执行授权、ERP/JL 重试规则或队列串行语义。

## 2. 最终行为

- 仅 `label=定时扫描工单` 的自动扫描触发状态窗；人工扫描、单笔处理、重新采集和执行操作保持原有立即执行行为。
- 真正开始本轮 Chrome/CDP 操作前固定倒计时 10 秒。
- 运行中持续显示当前店铺、店铺总数、剩余店铺、当前工单、本店工单总数、工单号、累计已处理工单和异常店铺数。
- 单店异常继续沿用原扫描逻辑：记录异常后处理下一个店铺，状态窗只展示，不触发重试。
- 整轮正常完成、带店铺异常完成、整轮异常或紧急停止时显示对应终态，约 5 秒后自动关闭。
- 状态窗本身不激活前台应用，不额外抢键盘焦点；真正需要前台焦点的仍是原 Chrome 自动化。

## 3. 实现边界

- 队列生命周期和真实进度接入：`lib/server/op-queue.js`。
- 状态文件、进程生命周期和终态收口：`lib/server/scan-hud.js`。
- macOS JXA 原生浮动窗口：`scripts/scan-status-hud.js`。
- 回归测试：`test/server/scan-hud.test.js`。
- 状态通信使用 `/tmp/aftersales-scan-hud/` 下的临时 JSON，不写入业务数据目录。
- 紧急停止在店铺级异常捕获层显式重新抛出 `AbortError`，避免最后一家店停止时被误吞并显示“完成”。
