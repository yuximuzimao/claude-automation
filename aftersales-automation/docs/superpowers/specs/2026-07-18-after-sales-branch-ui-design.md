# 售后分支统计页清晰化设计

## 1. 目标

让用户进入统计页后，先一眼看到总体情况，再按“售后原因 → 最小结果”逐层查看，避免 35 个结果和所有统计数字同时铺开。

本次只调整展示，不改变固定分支门禁、历史统计口径或自动处理权限。

## 2. 页面层级

### 第一层：总体概览

售后分支区域顶部只显示四项：

- 最近 30 天工单数；
- 最小结果分支数；
- 已授权自动分支数；
- 需要关注的分支数。

“需要关注”指存在差评、未登记或缺少必要信息的分支。它只是查看提示，不改变业务判断。

### 第二层：售后原因

所有结果先按售后原因分组。每个原因只显示：

- 原因名称；
- 工单总数；
- 结果数量；
- 该原因下是否包含已授权、需关注或仅人工结果。

默认只展开包含已授权自动、差评、未登记或缺少必要信息的原因；其他原因保持折叠。用户仍可手动展开全部原因。

原因按优先级排序：需要关注 → 包含已授权 → 其他；同一优先级按工单数从多到少排列。

### 第三层：最小结果

每个结果的主行只显示：

- 最终结果名称；
- 自动状态：已授权自动、仍需人工、永不自动；
- 出现次数；
- 好评和差评。

结果按优先级排序：有差评或缺少信息 → 已授权自动 → 其他；同一优先级按出现次数从多到少排列。

以下次要信息收进“查看详情”：

- 真实自动成功次数；
- 人工处理次数；
- 历史处理结果；
- 缺少的必要信息；
- 备注内容及分布。

## 3. 视觉规则

- 延续现有页面的蓝、绿、橙、红和灰色体系，不重做整站风格。
- 绿色只表示“已授权自动”，红色只表示“需要关注”，橙色表示“仍需人工”，灰色表示“永不自动”。
- 不再用大量行内样式堆叠信息，新增少量专用 CSS 类控制间距、层级和移动端换行。
- 不增加搜索、筛选器、图表或新的操作按钮。

## 4. AI 洞察与反馈明细

AI 洞察的“待洞察反馈”和页面下方“反馈记录”都只展示填写了具体评论内容的记录。

- 单纯点击“好评”但没有填写评论：不显示在明细中；
- 好评并填写了具体评论：显示；
- 差评并填写了具体评论：显示；
- 原有总体好评、差评统计数字不受影响。

这里的过滤只影响前端明细展示，不删除历史反馈，也不改变后端洞察数据。

## 5. 自动更新

历史记录不需要人工定期更新：

- 每次打开统计页时，从现有接口读取最新记录并重新汇总；
- 页面停留在统计页时，工单推理、案例归档或反馈发生变化，会通过现有实时事件重新加载；
- 切走再返回统计页时也会重新读取；
- 统计范围继续保持最近 30 天，因此旧记录会自然退出窗口。

本次不增加定时器、缓存或后台任务。

## 6. 验证

- 测试默认展开规则和原因、结果排序；
- 测试关键数字与详情字段没有丢失；
- 测试没有评论内容的好评不会出现在洞察与反馈明细；
- 测试带评论的好评和差评仍然显示；
- 运行完整测试，重启服务，但不手动触发工单扫描。
