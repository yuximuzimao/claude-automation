# 仅退款 ERP 逐行与退回物流规则交接

状态：2026-07-17 已完成、已测试、已重启服务加载。本文件只记录最终边界；实施过程以 Git 历史为准。

## 最终业务规则

1. 仅退款必须读取主品和赠品的全部子订单、全部 ERP 行，不能只看第一行。
2. ERP 按子订单号搜索后，每一行“平台交易号”都必须包含搜索号。合并订单可显示为 `756292468；756311711`，中文或英文分号都支持。
3. 搜索结果错误时，只重新执行一次搜索，总共最多 2 次。第二次仍失败立即报错，不继续物流采集、推理或整张工单流程。
4. 每一行无单号且状态为待审核、待打印快递单或待发货时，视为未发货；任意状态只要有快递单号，就必须按实际物流判断。
5. `收件人要求退回，等待发件人确认！` 只是请求，不是确认退回。必须另有独立退回节点；双源重复文案或单独“退回件”标签不算第二个节点。
6. 创建过拦截记录不代表拦截成功，仍以实际物流节点为准。

## 实现位置

- `lib/erp/search.js`：平台交易号读取、逐行核验、搜索最多两次。
- `lib/infer.js`、`lib/constants.js`：全部退回判断统一使用确认退回规则。
- `lib/jl/target-aware-collector.js`：主品和赠品全部子订单顺序采集。
- `docs/flow-5.2.md`、`docs/flow-5.3.md`：正式业务流程。
