# 五本教材逐章原文处理与独立复核协议

版本：2.1  
更新时间：2026-11-11

## 1. 目标与边界

五本教材的全部正式编号章节都要建立可定位、可复核的原文缓存，但这不等于全部章节都要正式学习。预处理只负责忠实原文、OCR、章节边界、页码映射、图表和独立复核；不做总结、归纳、翻译、润色或教学。

## 2. 固定职责

- **Workbuddy / DeepSeekPro：唯一流水线主控。** 维护章节总目录和唯一进度台账；逐章提取原文；生成单文件 PDF 复核资料包；接收复核报告；回到原始 PDF 核实差异、修订并保存最终稿。
- **独立复核模型：默认千问办公；可替换为 Kimi K2.8 或 Kimi 3.1 Pro。** 每次只复核用户提交的一个 PDF 资料包，不维护总进度、不寻找下一章、不修改原文。替换模型时沿用同一份复核提示词和完全相同的输出文件名规则。
- **用户：文件交接者。** 将 DeepSeek 指定的单一 PDF 资料包交给复核模型，再把复核报告文件附加给 DeepSeek。无需向复核模型解释章节，也无需告诉 DeepSeek 报告属于哪一章。
- **ChatGPT：教师与分析者。** 负责正式学习、概念解释、推论标注、项目映射和理解检查，不参与日常 OCR。

复核模型只输出差异报告；DeepSeek 是唯一可以修改章节原文的执行者。任何模型都不得把教材内容总结、归纳或扩写进原文缓存。

## 3. 处理顺序与范围

按以下顺序处理五本书全部正式编号章节：

| Book ID | 教材 | 目录预期章节数 |
|---|---|---:|
| B01 | 《实例化需求：团队如何交付正确的软件》 | 18 |
| B02 | 《软件需求（第3版）》 | 32 |
| B03 | 《软件设计的哲学（第2版）》 | 22 |
| B04 | Effective Software Testing: A Developer's Guide | 11 |
| B05 | 《可观测性工程》 | 22 |

预期合计 105 个正式编号章节。数量仅作目录核对提示，实际 PDF 目录和正文才是最终依据；如数量不同，记录差异，不得为了凑数增删章节。

正式章节完成后，再将有实质内容的附录、练习答案和技术补充材料列为独立处理单元。封面、版权页、目录、空白页、广告、纯参考文献和索引不作为正文 OCR 单元，但要保留定位信息。前言、译者序等非编号内容先登记为补充材料，不插入正式章节队列。

处理顺序严格按 Book ID 和章节编号升序。每次只处理一个章节的一个阶段。已完成章节自动跳过，不允许越过阻塞章节继续处理后续章节。

### 已完成章节

B01-C02《实例化需求》第2章“关键过程模式”已完成原文提取、独立复核、DeepSeek 修订和 Chat 最终验收。该最终版已预置在流水线文件夹的 最终章节/B01/。初始化时必须登记为已完成，不得重做；同时检查最终 Markdown 的图2-1相对链接，若图片缺失，从 B01 原始 PDF 的 PDF 第31页裁剪原图，保存到 图表资源/B01-C02/ 并修正相对链接。

B01-C01 尚未完成，因此初始化后的第一项待提取章节是 B01-C01；完成后跳过已完成的 B01-C02，继续 B01-C03。

## 4. 流水线文件夹生命周期与位置

用户已将整个 教材流水线 文件夹剪切到 Workbuddy 自己的“杂事”工作区，并删除主学习项目中空的 workbuddy-handoff/ 父目录。当前运行期间，DeepSeek 必须以 Workbuddy“杂事”中的 教材流水线/ 文件夹为唯一工作根目录。不要假设固定绝对路径；所有内部引用使用相对路径。

文件夹应包含：
- 00-使用说明.md
- 01-DeepSeekPro固定主提示词.md
- 02-千问办公固定复核提示词.md
- 03-流水线规则.md
- 原始教材PDF/（五本教材的工作副本）
- 待千问复核/
- 最终章节/
- 复核报告/
- 图表资源/
- 处理记录/
- 01-章节总目录.md
- 02-处理进度.md

原始 PDF 工作副本保持只读，不修改、不重命名、不覆盖。主学习项目的 resources/books/ 中原始主副本保持不变。工作副本复制时已核对 SHA-256 与主副本一致。

### 完成后的回迁要求

当全部正式章节，以及已登记的附录/补充处理单元均完成复核闭环后，用户应将整个 教材流水线/ 文件夹剪切回：

software-engineering-study/resources/processed-books/教材流水线/

如果用户届时忘记回迁，Codex 应主动在 Workbuddy 的“杂事”工作区中按文件夹名 教材流水线 定位，并核对其中的规则文件、固定提示词、五本 PDF、进度台账、最终章节和复核报告；确认是本项目完整资料后，将整个文件夹迁回上述目标目录。不得只移动部分子目录，也不得误搬同名的其他文件夹。若 Codex 当时无法访问 Workbuddy“杂事”工作区或本地路径权限不足，应明确告知用户并请求打开/提供该工作区，不得猜测路径。

主项目根 .gitignore 已明确忽略：
- software-engineering-study/workbuddy-handoff/
- software-engineering-study/resources/processed-books/

教材 PDF、逐章原文、复核资料包、图表和报告只用于个人学习，不提交 Git、不公开分发。

## 5. 唯一进度台账与状态机

Workbuddy 文件夹中的 02-处理进度.md 是唯一进度真值，只由 DeepSeek 维护。复核模型不维护第二份总进度。

每个章节只能处于以下状态：
- 待提取：尚未提取。
- 待复核：原文稿和单一 PDF 复核资料包已生成，等待用户交给复核模型。
- 待修订：DeepSeek 已收到匹配的复核报告，等待核实和修订。
- 已完成：独立复核闭环完成，最终文件已保存。
- 待人工确认：存在无法可靠解决的章节边界、正文或关键图表问题，必须暂停。

合法状态流转：

~~~text
待提取 → 待复核 → 待修订 → 已完成
                         ↘ 待人工确认
~~~

每条台账至少记录：章节 ID、教材/章节标题、PDF 起止页、印刷页码及证据类型、状态、原文提取稿路径、复核资料包路径、复核报告路径、最终文件路径、图表路径、未解决问题和更新时间。

每次 DeepSeek 会话只处理一个章节的一个阶段：
1. 无台账时初始化全书章节清单和进度台账，登记预置 B01-C02 已完成；初始化会话不处理新章节。
2. 收到文件名以 -复核报告.md 结尾的附件时，根据章节 ID 匹配唯一的待复核章节，执行修订。
3. 有待复核章节但本轮没有报告时，停止并告诉用户把指定 PDF 交给复核模型。
4. 有待修订或待人工确认阻塞项时，停止并报告，不得处理下一章。
5. 没有阻塞时，选择队列中第一项待提取章节。
6. 修订完成后停止；下一章必须在新会话处理。

## 6. 固定文件名与交接方式

DeepSeek 提取阶段必须生成：
- 原文稿：待千问复核/{ID}-{章节标题}-原文提取.md
- 唯一交给复核模型的文件：待千问复核/{ID}-{章节标题}-复核资料包.pdf

用户只需把这个 PDF 交给千问办公或替代复核模型，不需要另外寻找 Markdown、图表或原始 PDF。

复核模型必须从输入 PDF 文件名读取章节 ID 和章节标题，并严格输出：
- {ID}-{章节标题}-复核报告.md

文件名不得增加日期、版本号、模型名称或其他前后缀。报告必须是可下载的 Markdown 文件；若界面无法生成文件，则完整输出 Markdown 内容并在首行标注规定文件名。

用户将该报告文件直接附加到 DeepSeek 下一次会话。DeepSeek 只根据报告文件名中的章节 ID 与唯一待复核状态匹配；必须校验章节 ID、标题和状态，不匹配时停止，不得猜测。用户无需另行说明报告属于哪一章。

DeepSeek 修订后固定保存：
- 最终章节：最终章节/{BookID}/{ID}-{章节标题}-最终版.md
- 复核报告副本：复核报告/{BookID}/{ID}-{章节标题}-复核报告.md
- 原始提取稿归档：处理记录/原始提取稿/{BookID}/
- 复核资料包归档：处理记录/复核资料包/{BookID}/
- 修订记录：处理记录/修订记录/{BookID}/{ID}-{章节标题}-修订记录.md
- 图表资源：图表资源/{ID}/

最终 Markdown 的图片引用必须使用相对路径，确保整个文件夹移动后仍然有效。

## 7. 单文件 PDF 复核资料包

每章生成一个完整 PDF，内含：
1. 封面和章节定位信息；
2. 本章所有原始 PDF 页面的完整、清晰页面图像；
3. 每张原始页面图像之后紧跟该页的原文转录；
4. PDF 页码和印刷页码，并区分直接读取与推定；
5. 图表原图、OCR 质量说明；
6. 必要的目录页、前一章末页、后一章标题页作为边界证据，并标明这些是边界证据而非本章正文。

建议页面渲染 250–300 DPI；若压缩必须保证文字仍可辨。不得只把 Markdown 打印成 PDF，必须包含原始页面图像和对应转录。

用户此前已使用千问办公复核过原始教材 PDF，确认其具备阅读 PDF 的能力。当前默认认为 DeepSeek 能稳定生成组合 PDF 资料包，不再安排额外专项验证；如果实际处理时发生生成异常，用户会单独告知，再针对异常调整规则。若 DeepSeek 实际无法生成完整资料包，必须暂停并报告，不得交付缺少页面证据的文件。

## 8. 原文提取与独立复核质量要求

- 目录、正文标题页、下一章标题页共同确认章节边界，不得只依赖书签或固定页码偏移。
- 原生文本 PDF 优先直接提取；扫描版或 OCR 质量不足时使用本地 OCR，并逐页对照原页面。
- 保留原文顺序、标题层级、段落、列表、脚注、表格、代码、公式、英文术语、数字和 URL。
- 无法确认的文字标记疑点，不得根据上下文猜测补全。
- 图表从原始 PDF 直接裁剪，不重绘、不使用生成模型重画。
- 每章质量报告区分初次 OCR 错误、已修正错误、转录手误、未解决正文疑点、图表疑点、页码推定和未核对页面。
- 章节 Markdown 超过 1.5 MB 时按连续 PDF 页拆分，不得静默截断；同一章节仍只生成一个完整 PDF 复核资料包。

复核模型必须逐页对照资料包中的原始页面图像和对应转录，不得抽查。检查漏字、错字、漏句、重复、段落顺序、数字、标点、术语、URL、表格、脚注、图题图注、页码映射和章节边界。无法判断的图形拓扑或小字必须标记疑点，不得猜测。

DeepSeek 收到报告后逐条回到原始 PDF 核实。只有页面证据支持的差异才修正；不采纳的建议记录原因；无法确认的问题继续保留疑点。修订后保存最终稿、复核报告副本、原始提取稿、复核资料包和修订记录。影响正文完整性的关键问题未解决时，状态标记为待人工确认。

## 9. 暂停条件

遇到以下情况必须暂停当前章节，不得继续下一章：
- 原始 PDF 不存在或文件身份不匹配；
- 章节边界无法可靠确认；
- 页码映射无法区分直接读取和推定；
- 正文存在可能影响语义的未解决疑点；
- 复核报告与章节 ID/标题/状态不匹配；
- 复核意见与原始页面证据冲突且无法判定；
- 关键图表丢失或无法定位；
- 复核资料包不完整或无法实际逐页核对；
- 当前章节没有完成规定的提取、复核和修订闭环。

不设每日完成量，不要求连续运行。每个会话只推进一个章节阶段，以准确性和可恢复性优先。
