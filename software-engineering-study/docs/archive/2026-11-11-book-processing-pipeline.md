# NEAT 归档：五本教材逐章原文处理流水线定稿

日期：2026-11-11

## 背景

《软件工程与 AI 系统设计学习》首批五本教材已完成 PDF 版本、目录和可读性核验。第一章的原文提取试验《实例化需求》第2章已完成 OCR、逐页独立复核、DeepSeek 修订和 Chat 最终验收，证明章节级原文缓存可以用于后续学习。

本次将一次性试验固化为可跨会话恢复的全书预处理流程，范围从原先只处理学习计划重点章节调整为五本教材全部正式编号章节。

## 已确认决策

### 处理范围与顺序

按既定教材顺序处理全部正式编号章节，目录预期合计约105章；实际章节数量以每本 PDF 的目录和正文为准。正式章节完成后，再处理有实质内容的附录、练习答案和补充材料。全部预处理不等于全部正式学习，学习仍按 docs/learning-plan.md 的知识单元推进。

### 角色与职责

- Workbuddy / DeepSeekPro 是唯一流水线主控：维护章节总目录和唯一进度台账，自动选取下一章，提取原文、OCR、定位页码、生成复核资料包，接收报告后回到原始 PDF 核实差异并修订。
- 独立复核模型默认使用千问办公。若千问额度不足，用户可替换为 Kimi K2.8 或 Kimi 3.1 Pro。
- 替代复核模型沿用同一份复核提示词、同一份单文件 PDF 复核资料包和相同的报告文件名规则，不因模型更换而改变 DeepSeek 工作流。
- 复核模型只输出差异报告，不修改原文、不总结、不润色、不维护项目进度。
- ChatGPT 负责后续教学、解释、推论、项目映射和理解检查，不参与日常 OCR。

### 文件交接方式

- DeepSeek 每次只处理一个章节的一个阶段。
- 提取后只向用户指定一个 PDF 文件：{ID}-{章节标题}-复核资料包.pdf。PDF 内同时包含原始页面图像、对应逐页转录、页码证据、必要的边界页面和质量说明。
- 用户将该 PDF 交给千问或替代复核模型。
- 复核模型必须输出 {ID}-{章节标题}-复核报告.md，不得添加日期、模型名或版本前后缀。
- 用户将报告文件直接附加给 DeepSeek 下一次会话。DeepSeek 根据报告文件名中的章节 ID 自动匹配唯一待复核章节，不要求用户解释。
- DeepSeek 核实并修订后更新唯一进度台账，完成后停止；下一章在新会话继续。

### 文件夹生命周期

- 用户已将整个“教材流水线”文件夹剪切到 Workbuddy 自己的“杂事”工作区，并删除主学习项目中空的 workbuddy-handoff/ 父目录。
- 文件夹内包含五本教材 PDF 工作副本、DeepSeek 固定主提示词、独立复核提示词、完整规则、B01-C02 最终版，以及所有后续输出目录。
- 五本 PDF 工作副本的 SHA-256 与主学习项目中的原始 PDF 一致；主副本保持不变。
- 全部正式章节和已登记补充处理单元完成后，整个文件夹必须迁回 software-engineering-study/resources/processed-books/教材流水线/。
- 若用户忘记回迁，Codex 应根据 Todo 在 Workbuddy“杂事”工作区定位文件夹，核对其规则、提示词、原始教材、进度台账和最终章节后整体迁回。若无权限则请求用户打开/提供工作区，不猜测绝对路径。
- workbuddy-handoff/ 与 resources/processed-books/ 均由根 .gitignore 排除，教材原文、PDF 和复核资料不进入 Git。

### PDF 复核资料包假设

用户此前已用千问办公复核过原始教材 PDF，确认其具备 PDF 阅读能力。当前默认 DeepSeek 可以稳定生成包含原始页面图像与逐页转录的组合 PDF，不再安排额外专项验证。若实际处理时出现生成异常，再按用户反馈单独调整，不为此增加预防性复杂流程。
